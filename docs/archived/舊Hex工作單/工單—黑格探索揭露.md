# 工單：黑格探索揭露

> 優先級：P1  
> 前置：格內平滑移動（v0.14.5 已完成）  
> 目標：玩家可從彩格邊緣觸發黑格偵查，不可走地形秒開，可走地形需踏入精探  
> 驗收環境：手機 PWA（390×844 基準），桌面次之  
> 依據文件：`docs/reference/Hex探索揭露與漸進生成—規格草案.md`

---

## 一、範圍

### 做

1. 字圓走向黑格方向時，在**彩格-黑格邊界線**自動停止
2. 邊界停止後，前端發送偵查請求，後端計算該黑格地形
3. 不可走地形（Mountain / Water / WaterDeep / Wall）→ **秒開**：黑格立即轉彩，字圓不動
4. 可走地形 → 格子轉彩但**覆灰霧**（已知地形，尚未精探）
5. 玩家點擊灰霧格 → 字圓以**高阻力**速度進入
6. 字圓抵達灰霧格**中心區域** + **完全靜止** → 開始讀秒
7. 讀秒完成 → 灰霧散去 → 探索完成（精煉層解鎖）
8. 讀秒中斷（移動/離開）→ 本次計算不列入，格子維持灰霧狀態

### 不做

- 多人同步揭露 / 接軌
- IOU 配額系統 / 全域多樣性驗證
- 聚落生成（村/鎮/市觸發）
- 精煉層內容（資源點、NPC、設施）——本工單只開格，精煉層另案
- 遺落之地機制

## 二、格的三種視覺狀態

| 狀態 | 視覺 | 含義 |
|------|------|------|
| **黑格** | 純黑 / 迷霧，無地形資訊 | 完全未知 |
| **灰霧格** | 地形底色 + 地形字可見，但覆半透明灰霧層 | 已偵查（知道地形），未精探 |
| **彩格** | 正常渲染，無遮罩 | 探索完成，精煉層已解鎖 |

不可走地形（山/水/牆）沒有灰霧階段——偵查即完成，直接變彩格。

## 三、流程細節

### 3.1 邊界停止

字圓朝黑格方向移動時，canvas render loop 須檢測：

- 計算 `(playerOffsetX, playerOffsetY)` 對應的地圖絕對座標
- 若下一步 `(nextX, nextY)` 落入**不在 hexView.cells 中的格**（即黑格），停止移動
- 停止位置：彩格邊緣（距格中心約 `HEX_R` 處），不越線

**判定方式**：將 `nextX, nextY` 轉為 hex 座標，若該座標不存在於 `state.hexView.cells`，視為黑格邊界。

### 3.2 偵查請求

字圓因黑格邊界停止後，前端自動發送：

```
POST /api/hex/scout
Body: { "player_id": "xxx", "target_q": 3, "target_r": -1 }
```

後端行為：
1. 驗證 target 座標與玩家座標相鄰（距離 = 1）
2. 驗證 target 為黑格（grid 中不存在）
3. 呼叫 `generate_wild_cell(grid, coord)` 生成地形（決定性，依 world_seed + 座標）
4. **寫入 grid**（契約釘死）
5. 回傳結果：

```json
{
  "ok": true,
  "cell": {
    "q": 3, "r": -1,
    "terrain": "forest",
    "name": "密林",
    "display_char": "木",
    "color": "#2d5a27",
    "text_color": "#1a3d18",
    "text_font": "FZJiaGuWen",
    "move_cost": 1.5,
    "walkable": true
  },
  "scouted": true
}
```

### 3.3 前端收到偵查結果

- **不可走**（`walkable: false`）：  
  將該格加入 `hexView.cells`，正常渲染（彩格）。秒開完成，無需進一步動作。

- **可走**（`walkable: true`）：  
  將該格加入 `hexView.cells`，但標記 `fogged: true`。  
  渲染時在地形底色上覆蓋半透明灰層（建議 `rgba(40, 40, 40, 0.45)`）。  
  字圓仍停在邊界，等待玩家主動點擊進入。

### 3.4 踏入灰霧格

玩家點擊灰霧格 → 字圓進入，移動速度：

```
探索速度 = 30 px/s（固定，不分單擊雙擊，不受地形 move_cost 影響）
```

理由：未精探的地方一律小心翼翼，不管是草原還是沼澤。

### 3.5 中心讀秒

**中心區域判定**：距格中心 ≤ `30px`（HEX_R = 202，約 15% 半徑）

**靜止判定**：字圓無 pending 移動指令（`isIntraMoving === false`）且在中心區域內

**讀秒**：
- 時長：`3 秒`（MVP 固定值，日後可依地形/天氣/技能調整）
- 前端顯示：中心出現環形進度條或圓弧填充動畫
- 讀秒期間玩家點擊其他地方 → 中斷，字圓開始移動，進度歸零
- 讀秒完成 → 前端發送：

```
POST /api/hex/explore
Body: { "player_id": "xxx", "target_q": 3, "target_r": -1 }
```

後端行為：
1. 驗證玩家確實在該格（hex_q, hex_r 一致）
2. 標記該格為已探索（精煉層解鎖，本工單暫不填充內容）
3. 回傳確認

前端收到後移除該格 `fogged` 標記，灰霧散去。

### 3.6 跨格座標同步

字圓從彩格進入灰霧格時，需同步後端玩家座標：

```
POST /api/hex/move
Body: { "player_id": "xxx", "to_q": 3, "to_r": -1 }
```

後端更新 entity 的 `hex_q`, `hex_r`，並呼叫 `fetchHexView()` 重新取得以新座標為中心的視野。

## 五、前端狀態機

```
[格內移動]
    │
    ▼ 碰到黑格邊界
[邊界停止] ──→ 自動發送 scout
    │
    ├─ 不可走 → [秒開轉彩] → 回到 [格內移動]（字圓不動）
    │
    └─ 可走 → [灰霧格出現]
                 │
                 ▼ 玩家點擊灰霧格
         [踏入移動]（30 px/s）
                 │
                 ▼ 到達中心 + 靜止
         [讀秒中]（3 秒環形進度）
                 │
                 ├─ 中斷 → 回到 [格內移動]（灰霧保留）
                 │
                 └─ 完成 → 發送 explore → [灰霧散去] → 回到 [格內移動]
```

## 六、渲染修改（canvas.js）

### 6.1 灰霧覆蓋

在 render loop 中，繪製 cell 後、繪製 entity 前：

```javascript
if (cell.fogged) {
    ctx.fillStyle = 'rgba(40, 40, 40, 0.45)';
    // 繪製與 hex 同形的半透明覆蓋
    ctx.fill(hexPath);
}
```

### 6.2 讀秒進度環

字圓在中心靜止且讀秒中時，以字圓為圓心繪製弧形進度：

```javascript
// progress: 0.0 → 1.0
ctx.beginPath();
ctx.arc(cx, cy, 20, -Math.PI/2, -Math.PI/2 + Math.PI*2*progress);
ctx.strokeStyle = 'rgba(255, 220, 120, 0.8)';
ctx.lineWidth = 3;
ctx.stroke();
```

### 6.3 邊界碰撞擴充

現有 `checkCollision()` 需擴充：除了不可走地形，**黑格也是碰撞**（字圓不得越入未偵查區域）。

## 八、驗收標準

- [ ] 字圓走向黑格方向時，在彩格邊緣停止，不越線
- [ ] 停止後自動偵查，不可走地形秒開為彩格
- [ ] 可走地形出現灰霧覆蓋，地形字和底色隱約可見
- [ ] 點擊灰霧格，字圓以 30 px/s 緩慢進入
- [ ] 灰霧格內中心靜止 3 秒後，灰霧散去
- [ ] 讀秒中途移動，進度歸零，灰霧保留
- [ ] 跨格後 hexView 重新取得，新視野正確渲染
- [ ] 連續探索多格，每格獨立走完偵查→踏入→讀秒流程
- [ ] 手機觸控與桌面滑鼠行為一致（touchend preventDefault 已修復）
- [ ] 不可走地形秒開後，字圓不卡住，可繼續往其他方向移動

## 九、不動的東西

- `generate_wild_cell()` 現有邏輯不改，它已能依 world_seed + 座標決定性產出地形
- `reveal_hex_disk()` 保留但本工單不使用（它是批量揭露，探索是逐格）
- hexView 回傳格式維持不變，僅新增 `explored` 欄位
- 雙擊快跑機制在**彩格內**不變，僅灰霧格強制 30 px/s

## 十、技術提示

1. **邊界停止判定**：render loop 每幀算 `nextX, nextY` → `pixelToHex()` → 查 `hexView.cells`。不在 cells 中 = 黑格 = 停
2. **scout 請求去重**：同一黑格只發一次 scout，用 `Set` 記錄已發送的座標
3. **灰霧格 fogged 狀態**：存在前端 `state.hexView.cells` 陣列中，加 `fogged: true` 屬性
4. **讀秒計時器**：用 `requestAnimationFrame` 累計時間，不用 `setTimeout`，避免背景 tab 計時漂移
5. **跨格時機**：字圓越過格中心線時觸發 `/api/hex/move`，不是到達中心時
6. **相機跟隨**：跨格後 `cameraX/Y` 需平滑過渡到新格中心，避免跳切
