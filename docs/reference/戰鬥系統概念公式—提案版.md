# 戰鬥系統概念公式 — 提案版

> 本文件為對齊現有 `combat.ResolveV2` 與 entity（Vit/Qi/Dex）的**一版可實作**戰鬥公式提案，與 [戰鬥系統概念設計—提取自gemini概念檔](戰鬥系統概念設計—提取自gemini概念檔.md) 可並存。**盡可能將已知概念元素融入核心公式；未實裝的概念，數值以 1（或下表註明之預設）代入即可。**

---

## 一、設計原則

- **同一套規則**：玩家 vs NPC、NPC vs NPC、玩家 vs 玩家皆用同一組公式（決策 001）。
- **無副作用**：Resolve 只做計算與產出 log，不寫 DB；扣血／死亡／扣鎂由呼叫方依回傳結果處理。
- **概念全納**：下列概念元素皆出現在核心公式中，未實裝時以預設值代入，不刪項。
- **文字戰報**：回傳 winner + 一段可直送前端的敘事字串。

| 符號 | 語義 | 來源 | 未實裝預設 |

## 三、核心公式一式化（全概念代入）

下列各式已納入上列所有概念；**未實裝項目以 §二 預設代入**，常數可調。

### 3.1 先手與行動資格

- **先手**：`EDex_Atk >= EDex_Def` 則 Atk 先攻，否則 Def 先攻；相等時約定 Atk 先。
- **可出手**：當前 `AP >= T_base`（基礎）或 `AP >= T_skill * C_combo`（技能／連擊）；未實裝時序時視為每輪皆可出手。
- **可放技能**：當前 `EQi >= Qi_Drain`；未實裝時 Qi_Drain=0 恆可。

### 3.2 命中

- **判定係數**  
  `K_Hit = Atk_EDex / (Atk_EDex + Def_EDex)`  
  若分母為 0 則 K_Hit := 1。
- **命中率**  
  `P_Hit = clamp(0.05, 0.95, K_Hit * 1.2) * (1 + Skill_γ_match)`  
  Skill_γ_match 未實裝時為 0。
- **命中判定**：隨機 r ∈ [0,1]，r < P_Hit 則命中，否則該次 D_Final := 0。

### 3.3 傷害鏈（單次攻擊）

- **基礎傷害**  
  `D_Base = (Atk_Power + Atk_Gear) * R * M_Lush`  
  R、M_Lush 未實裝時皆為 1。
- **爆發係數**  
  `K_Impact = (0.8 + 0.4 * α)`  
  α 未實裝時為 1 → K_Impact = 1.2（或 α=0.5 → 1.0）。
- **原始傷害**  
  `D_Impact_raw = D_Base * K_Impact`
- **破甲**  
  `Pen = Atk_Penetration + (1 - Def_β) * Const_pen`  
  Const_pen 為常數；β 未實裝時為 1 → 第二項 0。
- **減傷率**  
  `mit = Def_EVit / (Def_EVit + Pen * 20)`  
  分母為 0 時 mit := 0。
- **最終傷害（未相位）**  
  `D_Final_base = D_Impact_raw * (1 - mit)`  
  若命中且 D_Final_base > 0 可設至少 1。
- **相位干涉**：  
  - 若 γ 觸發 **Deflect**（未實裝則不觸發）：`D_Final := 0`。  
  - 若 γ 觸發 **Crit**（未實裝則不觸發）：`D_Final := D_Final_base * Crit_mult`（例 1.5）。  
  - 若 γ 觸發 **ArmorBreak**：Pen 可再加成一次（未實裝則不加）。  
  γ、M_Chaos、M_Silent 可共同決定觸發機率；未實裝時 Crit/Deflect 皆不觸發 → D_Final := D_Final_base。
- **姿態損耗**（未實裝時不計）：  
  `Posture -= f(D_Final)`；Posture ≤ 0 → 觸發 Stagger，下一 Tick AP 不恢復。

### 3.4 氣脈消耗與回復（未實裝時不扣）

- **本動消耗**  
  `Qi_Drain = Skill_Cost * (2 - β) * M_Lush`  
  未實裝時 Skill_Cost=0 或 β=1、M_Lush=1 → 0。

### 3.5 勝負與狀態歸零

- **扣血**：受擊方 `HP -= D_Final`；若觸發 **Reverse** 則攻方也受部分傷害（未實裝則不反彈）。
- **勝負**：任一方 HP ≤ 0 即敗；雙方同時 ≤ 0 為平手。
- **EQi ≤ 0**：可標記虛弱（減傷/命中下降），未實裝可不實作。
- **Posture ≤ 0**：可標記僵直（AP 停 1 Tick），未實裝可不實作。

## 四、核心公式彙總（單式鏈，未實裝項以 1 或 0 代入）

依序代入即可得到單次「攻方→守方」的最終傷害與是否命中、是否暴擊/偏轉：

```
K_Hit     = Atk_EDex / max(Atk_EDex + Def_EDex, 1)
P_Hit     = clamp(0.05, 0.95, K_Hit * 1.2 * (1 + Skill_γ_match))
命中      = random() < P_Hit

D_Base    = (Atk_Power + Atk_Gear) * R * M_Lush
K_Impact  = 0.8 + 0.4*α
D_Impact  = D_Base * K_Impact
Pen       = Atk_Penetration + (1 - Def_β) * Const_pen
mit       = Def_EVit / max(Def_EVit + Pen*20, 1)
D_Final_base = D_Impact * (1 - mit)   [若未命中則 0]

[相位] 若 γ 觸發 Deflect → D_Final=0；若 γ 觸發 Crit → D_Final = D_Final_base * 1.5；否則 D_Final = D_Final_base

Qi_Drain  = Skill_Cost * (2 - β) * M_Lush
[姿態] Posture -= g(D_Final)；若 Posture≤0 則 Stagger
```

未實裝時：Skill_γ_match=0, R=1, M_Lush=1, α=1(或0.5), β=1, γ=0（不觸發 Crit/Deflect）, Atk_Power=1, Atk_Gear=0, Pen 可簡化為 0, Skill_Cost=0, 姿態/Stagger 不計。

## 五、單輪對撞（簡化實作範例）

單輪指：雙方各出手一次，依結果決定勝負或進入下一輪（由呼叫方迴圈或一次結算多輪）。

### 5.1 先手判定

- **先手權**：`Dex_A >= Dex_B` 則 A 先攻，否則 B 先攻。  
  若相等，可約定 ID 字典序或隨機，建議固定一方（如 attacker 先）以利重現。

### 5.2 命中與傷害（單次攻擊）

- **命中率**  
  `P_hit = clamp(0.05, 0.95, (Atk_Dex / (Atk_Dex + Def_Dex)) * 1.2)`  
  未命中則該次傷害為 0。

- **基礎威力**  
  `P_base = 1 + floor(Atk_Vit / 10)`  
  （體質高者「拳頭重」，可替換為固定常數或裝備加成。）

- **共鳴倍率**  
  `R ∈ {1.0, 1.5, 2.5}`，對應一階／二階／三階，無詞盤時 R = 1.0。

- **爆發係數**  
  `K_impact = 0.8 + 0.4 * α`，預設 α=0.5 時 K_impact = 1.0。

- **原始傷害**  
  `D_raw = P_base * R * K_impact`（再乘命中判定 0/1）。

- **減傷**  
  `mit = Def_Vit / (Def_Vit + 20)`，常數 20 可調為平衡用。  
  **單次實際傷害**  
  `D = round(D_raw * (1 - mit))`，至少 0，至少 1（若命中且 D_raw>0 可設 min 1）。

### 5.3 相位擾動（可選）

- 若引入 γ：  
  `r = random([0,1])`  
  - γ > 0.3 且 r < 某閾值 → 暴擊，D 乘 1.5。  
  - γ < -0.3 且 r < 某閾值 → 偏轉，D = 0。  
  未實作 γ 時此步略過。

### 5.4 單輪結算與勝負

- 先手方對後手方結算一次 D1，後手方對先手方結算一次 D2。
- **當前血量**：雙方各有一條 HP（可設為開戰時 HP = Vit，或由呼叫方傳入）。  
  `HP_A -= D2`，`HP_B -= D1`。
- **勝負**：若 HP_A <= 0 且 HP_B <= 0 → 平手；若僅一方 <= 0 → 該方敗；否則可回傳「未終結」與剩餘 HP，由呼叫方決定是否再呼叫下一輪。

## 六、與現有 Resolve 的對接方式

現有簡化簽名可保留；主流程使用 **ResolveV2**（Terrain、Gamma 暴擊／偏轉已實作）：

- **方案 A**：新增 `ResolveV2(attackerVit, attackerDex, defenderVit, defenderDex, opt *CombatOpt)`，opt 含 α/β/γ/R、是否單輪等；內部依 opt 選簡化或完整公式。
- **方案 B**：現有 Resolve 改為「第一階段公式」的實作（例如先手 Dex、每輪固定扣 1 或依 Vit 比例扣），待詞盤與三軸接上再抽成參數化。

建議**第一階段**實作：

1. 先手：Dex 高者先；相等時 attacker 先。
2. 每輪雙方各打一次：  
   `D = max(1, round((1 + Atk_Vit/10) * (1 - Def_Vit/(Def_Vit+20))))`，再依先手順序扣對方 HP。
3. HP 初值 = Vit（或由呼叫方傳入），任一方 HP <= 0 即結束，回傳 winner + log 字串。

這樣可直接替換目前「輪流扣 1」的邏輯，數值仍簡單、易調。

## 七、戰報產出約定

- 每輪可 append：先手方名、是否命中、傷害、受擊方名、剩餘體感（如「體質渙散」）。
- 結束時 append：勝方名、「取得了勝利」／「敗下陣來」。
- 標籤可沿用概念檔的 `[Initiative]`、`[Result]` 等，或先產純文字，前端再依關鍵字樣式化。
