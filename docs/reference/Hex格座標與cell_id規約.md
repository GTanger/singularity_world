# Hex 格座標與 `cell_id` 規約

> **用途**：`failure_cells`、`ValidationReport`、錨點、API 與 **同一字串** 互通；對齊 `src/hex/coord.rs` 之 `HexCoord`（axial、平頂）。  
> **關聯**：[人類活動地帶聚落五級—規格草案](../design/人類活動地帶聚落五級—規格草案.md) §15.4；[Hex地形與移動係數表](Hex地形與移動係數表.md)；[Hex探索揭露與漸進生成—規格草案](Hex探索揭露與漸進生成—規格草案.md)。

---

## 1. 座標語意

- 與 **`HexCoord { q, r }`** 一致：`q`、`r` 為 **32 位元帶符號整數**可表示範圍內之整數（JSON 以 number 傳輸時不得丟精度）。
- **不**在此檔另定義投影或 even-q／odd-r 偏移——若與 Watabou 等外掛資料對表，在 **匯入管線** 單點換算為本專案 axial 後再產生 `cell_id`。

### 1.1 螢幕上的「方位」怎麼說

本專案地圖為 **平頂（flat-top）** 六角：格與格之間是 **六向鄰接**，沒有「純上／純下」一格一邊的鄰居（與方格不同）。協作時建議：

- **最精準**：直接報 **`cell_id`**（`q,r`）或「從 `(q,r)` 往 **東／東北／西北／西／西南／東南** 一格」——六向與 `src/hex/coord.rs` 之 `HexDir` 一致。
- **粗略**：可說「畫面上**偏左／偏右／偏上／偏下**那一塊」，但同一句話請盡量補上 **座標或截圖**，避免歧義。

---

## 2. 正規 `cell_id`（字串，建議預設）

**格式**：`{q},{r}`

- **無空白**、無前後缀。
- **負數**直接寫負號，例如 `-3,12`。
- **正則**（建議實作驗證）：`^(-?\d+),(-?\d+)$`

**範例**：

| `q` | `r` | `cell_id` |
|-----|-----|-----------|
| 0 | 0 | `0,0` |
| 5 | -2 | `5,-2` |
| -10 | 7 | `-10,7` |

---

## 3. JSON 物件形式（可選）

請求／回應 body 內可同時接受：

```json
{ "q": 5, "r": -2 }
```

與字串 `cell_id` **互轉規則**：`format = "{q},{r}"`；解析時依 §2 正則還原 `q`、`r`。

**同一事件／同一 log 欄位**建議 **擇一貫通**（要嘛全字串、要嘛全物件），避免混用增加除錯成本。

---

## 4. 與 `data/hex/grid.json` 的關係

- 檔案內每格 **`HexCell.coord`** 與其 `cell_id` **一一對應**。
- 目前 schema **無**獨立 `cell_id` 欄位——執行期由 `coord` 依 §2 序列化即可。

---

## 5. `chunk_id`（可選，另軌）

- **不**併入 `cell_id` 字串；若需分塊載入，在 cell 上另加 `chunk_id` 或維護獨立 chunk 索引表。
- 拓撲與依附檢核仍以 **世界座標 `q,r`** 為準，與 chunk 無關。
