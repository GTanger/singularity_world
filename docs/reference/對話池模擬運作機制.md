# 對話池模擬運作機制

本文說明「搭話」時，從客戶端發送 Talk 到回傳敘事句的完整流程，以及佔位符與詞表如何產生組合變化。

---

## 一、相關檔案位置

| 用途 | 路徑 |
|------|------|
| 佔位符詞表 | `data/templates/dialogue_slots.json` |
| 職業→對話檔對照 | `data/templates/occupations.json` |
| 各職業對話模板 | `data/templates/dialogues/<職業>.json`（如 `beggar.json`、`waiter.json`） |
| 載入／抽句／填佔位符 | `db/dialogue` |
| 搭話敘事組裝 | `server/handler` 的 `buildTalkNarrative`、`handleDoAction` case "Talk" |

---

## 二、整體流程（從玩家點「搭話」到回傳一句話）

```
客戶端送 do_action { action: "Talk", entity_id: "王五" }
        ↓
handleDoAction 解析目標、取得玩家所在房間 playerRoom、target（王五）、personality
        ↓
buildTalkNarrative(database, playerRoom, target, personality, cfg)
        ↓
┌─────────────────────────────────────────────────────────────────┐
│ 1. 有無指派？                                                     │
│    assignments := GetAssignmentsForEntity(database, "王五")       │
│    若 len(assignments)==0 → 用 8 句硬編碼 fallback，結束。        │
└─────────────────────────────────────────────────────────────────┘
        ↓ 有指派（例如 assignments[0].OccupationID == "乞丐"）
┌─────────────────────────────────────────────────────────────────┐
│ 2. 情境參數                                                      │
│    roomName, _ := GetRoomName(database, playerRoom)  // 例："城隍廟前" │
│    hour := GameTimeNow(now, epoch, scale) 的 hour    // 例：12 → "正午" │
└─────────────────────────────────────────────────────────────────┘
        ↓
┌─────────────────────────────────────────────────────────────────┐
│ 3. 抽一句並填佔位符                                              │
│    line := PickFromDialogue(database, "王五", playerRoom,         │
│             "乞丐", "talk", personality, "", roomName, timeLabel) │
│    若 line=="" → 仍用 8 句 fallback。                             │
└─────────────────────────────────────────────────────────────────┘
        ↓
回傳 "你向【王五】搭話。" + line
        ↓
客戶端收到 action_result { narrative: "你向【王五】搭話。【王五】……" }
```

## 三、PickFromDialogue 內部模擬（乞丐＋talk）

假設：

- `entityID = "王五"`
- `roomID = "room_001"`（玩家所在房間 id）
- `occupationID = "乞丐"`
- `key = "talk"`
- `roomName = "城隍廟前"`
- `timeLabel = "正午"`
- `personality.Boldness = 0.3`

### 步驟 A：職業 → 對話檔

- `LoadOccupations("data/templates/occupations.json")` 回傳 `occupations` 對照表。
- `occs["乞丐"].DialogueFile == "dialogues/beggar.json"`。
- 路徑 = `data/templates` + `dialogues/beggar.json` → `data/templates/dialogues/beggar.json`。

### 步驟 B：載入對話檔與詞表

- `LoadDialogue("data/templates", "dialogues/beggar.json")` 讀取並快取 `DialogueFile`，取出 `d.Talk.Lines`（約 50 句）。
- `LoadDialogueSlots("data/templates/dialogue_slots.json")` 僅執行一次，快取 `verb`、`mood`、`time`、`thing` 陣列。

### 步驟 C：算 seed（決定「哪一句」與「詞表隨機」）

```text
seed = 0
for _, r := range "王五" { seed = seed*31 + int64(r) }  // 依 rune 累積
seed += int64(len("room_001"))<<8 + int64(len("talk"))<<16
```

同一 NPC、同一房間、同一 key，seed 固定 → **同一情境下重複搭話會得到同一句**（可重現）。不同 NPC 或不同房間會不同 seed。

### 步驟 D：PickLine（從 talk.lines 選一句）

- `lines = d.Talk.Lines`（例如 50 句，索引 0～49）。
- `idx = rng.Intn(50)`，再用 `personality.Boldness` 往後偏移：  
  `shift = int(0.3 * 25) = 7` → `idx = (idx + 7) % 50`。
- 假設得到 `idx = 42`，對應模板句：
  - `"【{name}】在{room}的{time}時分{verb}：『{thing}？呵，你問對人了。』"`

### 步驟 E：FillPlaceholders（填 name / room / time / mood / verb / thing / goods）

- `PlaceholderCtx` 傳入：`Name="王五"`, `RoomName="城隍廟前"`, `TimeLabel="正午"`, `Mood=""`, `Verb=""`, `Thing=""`, `Goods=""`。
- 有傳的：`{name}`→王五、`{room}`→城隍廟前、`{time}`→正午。
- 沒傳的從詞表用 `seed+1` 的 RNG 抽：
  - `{verb}` ← slots.Verb 中抽一個，例如「頓了頓」
  - `{mood}` 此句未出現，不影響
  - `{thing}` ← slots.Thing 中抽一個，例如「這兒的規矩」
- 替換後得到：
  - `"【王五】在城隍廟前的正午時分頓了頓：『這兒的規矩？呵，你問對人了。』"`

### 步驟 F：回傳

- `PickFromDialogue` 回傳上面這一句。
- `buildTalkNarrative` 再前綴 `"你向【王五】搭話。"`，最終敘事為：
  - `"你向【王五】搭話。【王五】在城隍廟前的正午時分頓了頓：『這兒的規矩？呵，你問對人了。』"`

## 四、組合數為何能遠大於「句數」

- **僅 {name} / {room} / {time}**：同一句模板會因「房間名」「時段」而不同；若 room、time 由情境決定，同一句在 4 個時段 × N 個房間 = 4×N 種呈現。
- **再加上 {mood} / {verb} / {thing}**：若這三類由詞表隨機（例如 8×8×5），同一句理論上可產生 8×8×5 = 320 種用詞組合；再乘上房間、時段，組合更多。
- **多句模板**：若有 50 句 talk.lines，每句又有多種佔位符組合，總呈現方式 ≈ 句數 × 各槽位選項數的乘積，故「約 50 句的對話池」能產生遠多於 50 種的實際句子。

---

## 五、重要行為整理

| 項目 | 說明 |
|------|------|
| 無指派 | 不查對話檔，直接使用 handler 內 8 句固定 fallback。 |
| 有指派、無對話檔或載入失敗 | `PickFromDialogue` 回傳 `""`，同樣走 8 句 fallback。 |
| 可重現性 | 同一 entityID、roomID、key 下 seed 固定，同一情境重複搭話會得到同一句與同一組詞表填充。 |
| 性格影響 | `personality.Boldness` 只影響 PickLine 的索引偏移（偏後半），不改變 seed。 |
| 詞表補填 | 僅當 `PlaceholderCtx` 該欄為空時，才從 `dialogue_slots.json` 對應陣列隨機抽。 |
| 快取 | 對話檔按路徑快取在 `dialogueCache`；詞表全域只載入一次（`slotsOnce`）。 |

## 六、模板與詞表格式速查

**單一職業對話檔**（如 `beggar.json`）：

- `greet.lines`：見面用。
- `talk.lines`：搭話用（本機制目前使用此 key）。
- 每句可含 `{name}`、`{room}`、`{time}`、`{mood}`、`{verb}`、`{thing}`、`{goods}`。

**詞表** `dialogue_slots.json`：

- `verb`、`mood`、`time`、`thing` 各一陣列；後端在情境未提供時從對應陣列抽一項填入。

以上即為對話池從「JSON 模板 + 詞表」到「一句情境化敘事」的完整模擬與說明。
