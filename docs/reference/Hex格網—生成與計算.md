# Hex 格網：生成與計算（收斂說明）

> **定位**：只談 **B 軸**——**1 格 = 1 個六角格**（axial `q,r`），與 [野外大地圖區域與場所分級規格](../design/野外大地圖區域與場所分級規格.md) 之 **Field Node「格」**（hop 圖）**不同量綱**；兩者接軌規則見 [人類活動地帶聚落五級—規格草案](../design/人類活動地帶聚落五級—規格草案.md) §十七。  
> **關聯**：[Hex探索揭露與漸進生成—規格草案](Hex探索揭露與漸進生成—規格草案.md)（主規格）；[Hex格座標與cell_id規約](Hex格座標與cell_id規約.md)；[Hex地形與移動係數表](Hex地形與移動係數表.md)；聚落五級 §1.1／§12.4（**官方聯外子圖**）。

---

## 1. B 軸 Hex 格是什麼

- **資料**：`HexCell`（`coord`、`terrain`、`zone`、`tags`…）存在 `HexGrid` 的 `cells` 裡；鄰接由幾何決定，**屏障**以 `(coord, dir)` 單向擋、**portal** 做非相鄰連通。見 `src/hex/grid.rs`、`src/hex/cell.rs`。  
- **語意**：相對於「城鎮內部語意節點」，**非聚落核**常指 `Urban` 聚落核以外的格（實務上多以 `zone`／`tags`／世界分區區分，細則依專案命名）。  
- **座標字串**：API／log 用 [Hex格座標與cell_id規約](Hex格座標與cell_id規約.md) 之 **`cell_id`**（預設 `{q},{r}`）。

---

## 2. 生成方式（揭露驅動，非一次全圖骰完）

對齊 [Hex探索揭露與漸進生成—規格草案](Hex探索揭露與漸進生成—規格草案.md)：

| 階段 | 行為 |
|------|------|
| **黑格** | 尚未有契約層內容；可迷霧或低保真預覽，**不**寫死可走／不可走等承諾。 |
| **首次揭露 → 彩格** | 依 **種子 + 已揭露邊界** 在規則內算出結果並 **釘死**（契約層）。 |
| **之後** | 僅允許 **單調精煉**（補敘事、補子物件、數值抖動），**禁止**推翻已釘死契約。 |
| **觸發** | 修路、開霧、接軌、後台分段 B 等皆可當觸發點；對齊觸發表 **1 主 + 1 副**。 |
| **過嚴** | 走 **FallbackMin**（最小合法骨架），標 `tier: minimal`，不整區失敗或空白。 |

**重點**：Hex 格網 **不是**「開局就算滿全世界再裁切」，而是 **觀測／揭露邊界** 逐步餵給生成器，屬增量世界線。

## 3. 「計算」在算什麼（可重現、可驗收）

### 3.1 單步能否走（物理層）

- **函式語意**：`HexGrid::can_walk(from, to)` — 目標格存在、相鄰、目標地形 `walkable`、該向無 **barrier**。  
- **移動成本**（尋路加權用）：`Terrain::move_cost()`；**與 §一 官方幹線無關**——聚落門檻用的是 **官方子圖**，不是單純「成本最低路」。見 [人類活動地帶聚落五級—規格草案](../design/人類活動地帶聚落五級—規格草案.md) §15.5。

### 3.2 兩張連通圖（定案）

| 圖 | 邊來源（摘要） | 用途 |
|----|----------------|------|
| **官方聯外子圖** | 合法鄰接步 + `link_class: official` 之 `transport_edges`；`portal` **預設不計入**，除非標 `counts_as_official_link` 且驗證通過 | §一 幹線計數、**§二 依附**、降級、Gate |
| **探索／玩法圖** | 上列 **併入** 捷徑邊、`shortcut`、`portal` 等 | 事件、AI、玩家抄近路 |

捷徑 **可通** 但 **不當官方聯外**；升格須明流程與資料標記。見聚落五級 §1.1、§12.4、§16。

**程式**：`HexGrid::find_path_layer(_, _, LinkLayer::Official | Exploration)`；`find_path`／`reachable_from` 預設 **Exploration**。僅雙端皆 `Cell` 之 `transport_edges` 參與格上 BFS；`settlement_id` 端點待聚落表再接。

### 3.3 拓撲指紋

- **`topology_hash_public`**：僅已揭露＋對玩家可見之邊。  
- **`topology_hash_authoritative`**：伺服器已落盤之全圖（含未開霧之幹線）。  
依附與 Gate 以 **authoritative + official** 為準。見聚落五級 §12.2、§10.5。

### 3.4 全域多樣性（跨足夠樣本）

- **配額（Quota）**、**IOU（延遲兌現）**、**種子哈希** 等擇一或並用，避免某類可玩點在已揭露區域內 **全系統性缺席**。見 Hex 探索 §四。

---

## 4. 與 Field Node、接軌的關係（邊界）

- **Field Node 圖**：城際 **hop**、Town／City **外連 Node 數**——**不**等於單張 Hex 圖上「幾步」。  
- **接軌**：兩區 Hex 聯外圖合併後 **`on_topology_changed`**；野外標籤與 `effective_tier` **同步收斂**（聚落 §十七）。  
- **未定案**：chunk／宏區與 `grid.json` 邊界對齊、多人與 IOU 決定性等，見 Hex 探索 **§八**。

---

## 5. 實作檢查清單（組員）

1. 觸發 → 寫入契約層前跑硬約束（山貫穿、水岸、城牆門…對齊聚落五級 §四／Hex §五）。  
2. 聚落驗證只讀 **`build_transport_graph(..., authoritative, official)`**。  
3. `transport_edges`／`portal` 與 `can_walk` 幾何矛盾 → `a-global-edge-geometry-mismatch`（聚落 §16.3.1）。  
4. `cell_id` 與 `HexCoord` 單一格式（cell_id 規約）。
