> **分級文件別搞混**：**探索式野外／大地圖**以 [野外大地圖區域與場所分級規格](../design/野外大地圖區域與場所分級規格.md)（Region／Field Node／Site、城際距離與接線）為**現行**主參考。[城鎮區域與場所分級規格](../design/城鎮區域與場所分級規格.md)為較早**房間式／MUD 城內區域**脈絡之討論，**不作**本文件接軌門檻之唯一依據。以 **Hex 格數**定義的 **村／鎮／市／府／都**、**區域 v0.1、生成管線 v0.2、驗收 v0.3、觸發表 v0.1** 見 [人類活動地帶聚落五級—規格草案](../design/人類活動地帶聚落五級—規格草案.md)。

## 一、名詞

| 名詞 | 意義 |
|------|------|
| **黑格** | 玩家／系統尚未取得該格**確定內容**；可顯示迷霧或低保真預覽，但**不寫入契約層**。 |
| **彩格** | 已揭露：地形與該次揭露範圍內允許釘死的屬性已寫入，**後續只允許精煉化補細節**，不可推翻。 |
| **契約層** | 已對玩家或模擬器承諾為真的狀態（可走／不可走、是否已有設施大類等）。 |
| **精煉層** | 在契約不變前提下，補敘事、補子物件、補數值抖動（例如同一「礦脈」的品質池）。 |
| **黑海**（舊稱**黑格海**） | **新玩家**首次登入時的生成語境：四周皆為未揭露之黑格，彷彿置身黑海；與一般「黑格」共用資料意涵，但帶有**開局／孤立**的敘事與系統語意。見 §七。 |
| **新玩家** | **新帳號**首次進入遊戲者；與「同帳號第二隻角色」無關（見 §七 帳號規則）。 |
| **遺落之地** | 某帳號已刪除，其區域曾開出之**彩格**仍未與**大世界**（多個已對接區域之聯通體）接軌時，該批版圖在後台保留為**無主、待接**的區塊；**不得改寫已釘死之彩格**。直至某玩家之區域或大世界擴張與其邊界接縫為止。見 §七。 |

## 二、單調精煉（Monotonic refinement）

**原則**：彩格數量與邊界約束單調增加時，世界描述只應變得更**自洽、細緻**，不應與既有彩格矛盾。

- 允許：在黑格上首次揭露時，依種子＋已揭露邊界算出合法結果並釘死。  
- 允許：在仍為黑格的鄰域上，因新路徑揭露而**補齊**先前未觸發的大結構（例如山體邊界閉合）。  
- 禁止：改寫已彩格上的契約（例如把可走的變不可走、把已對「洞口」**結清為無**改成「有洞口」——見下節三態）。

## 三、設施／特徵的三態語意（未結／結清／存在）

避免把「還沒生成」誤當成「這裡本質上沒有」。命名從敘事可讀性優先：**未結**＝帳還沒算完；**結清**＝就「有沒有這一類」已結案且結論是沒有；**存在**＝有。

| 狀態 | 對玩家敘事 | 生成器允許的行為 |
|------|------------|------------------|
| **未結** | 尚未觀測到／尚未結算 | 下次揭露時再算；不輸出「保證無礦」的硬句。 |
| **結清** | 此脈絡下已結案：確定沒有該類設施 | 寫入契約；之後不得在同格補出該類（除非世界規則允許極少數「發現秘道」類事件並另定義）。 |
| **存在** | 有 | 寫入契約；細節可精煉。 |

**與英文草稿對照（僅供實作溝通）**：未結 ≈ deferred；結清 ≈ absent；存在 ≈ present。

**範例（山與礦坑）**：  
- 某座山體在完整邊界揭露後，演算法判定 **結清** → 該山體範圍內無礦坑入口，合理。  
- 全域若長期在所有山體均為 **結清**，且未觸發任何「礦脈在別類地形」的 **存在** → 違反**全域多樣性保證**（見 §四），屬驗收失敗，而非敘事特色。

## 三點五、觀測驅動、增量與「模糊計算」

後台世界並非一次算完；它**等待**玩家（現單人、日後多人）開出彩格，邊界條件一點一點進來，再在種子與規則下補結構——像加料一樣，世界漸漸變清楚、變豐富。這在資訊科學上接近 **增量計算**、**線上演算法**（資料邊到邊算）、或在**部分資訊**下做**約束滿足**；遊戲界也常說 **戰爭迷霧驅動／揭露驅動生成**。

一般口語或科普裡的「模糊計算」若指的是數學的 **模糊邏輯／模糊集合**（隸屬度介於 0～1 的那套），與上述**不是同一個專有名詞**——後者是「界線不清的命題怎麼算」，你這裡是「**還沒揭露的格子＝資訊尚未到齊**」。若只想表達「未算死、隨資料變清楚」，用 **未結 → 結清／存在** 比較貼，也不易跟模糊數學混淆。

## 四、局部缺席 vs 全域多樣性

**可並存的兩句話**：

1. **局部**：單一連通山塊可以沒有礦坑（或只有採石場等替代敘事）。  
2. **全域**：在**世界種子**與**區域鹽值**下，跨足夠大的已揭露樣本，特定可玩要素（礦坑、渡口、聚落級設施等）的出現頻率不得恆為零，除非設計明文規定「本世界線無該要素」。

**實作取向（擇一或並用，實作階段定案）**：

- **區域配額（Quota）**：將世界劃為宏區（chunk／biome 區），每區對「礦／大聚落／主水路交會」等設**下限或目標分佈**；觸發時先查配額再擲隨機。  
- **延遲兌現（IOU）**：早期證據不足時只記「本區尚欠 1 個礦類可玩點」，待彩格覆蓋到合法候選後再兌現，避免「全世界山都長完才發現沒坑可填」。  
- **種子哈希**：同一種子可重現；改種子改分佈，但不依賴玩家順序洗結果（與「釘死」並存時，IOU 須在第一次需要兌現的觸發點決定位置並寫死）。

## 五、觸發與 FallbackMin（骨架）

與對談中的「觸發表」對齊：**每次觸發建議 1 主＋1 副**；嚴苛規則只約束**硬幾何／硬連通**，不約束「理想豐富度」。

| 觸發類型 | 硬約束（例） | FallbackMin（最小合法解） |
|----------|----------------|---------------------------|
| **路／陸連通** | 聚落對外至少一條可走聯絡 | 最小長度的單一路徑或暫時土路，標記為「可升級」。 |
| **水／岸** | 渡口、碼頭須落在合法水岸幾何 | 單一岸格＋最小連接段；敘事標「簡陋渡口」。 |
| **山／障礙** | 主線不可貫穿；洞口／坑道在允許深度與邊緣帶內 | 要嘛本區 IOU 記欠、要嘛單一邊緣洞口滿足連通；**禁止**為了美觀改牆體契約。 |

**回退過嚴時**：優先產出 **FallbackMin**，並在 debug／日誌標記 `tier: minimal`，而非整區失敗或默默空白。

## 六、驗收方向（草案）

以下為**方向性**指標，數值待與世界尺寸、chunk 劃分一併定標。

- **C1**：任意連通、已完全揭露的障礙體（山、城牆等），其「不可貫穿」與門／洞口規則與世界觀一致。  
- **C2**：已彩格與後續揭露不衝突（單調精煉）。  
- **C3**：在「未對該要素一律結清為無」的世界線下，於足夠大的已揭露區域內，可玩要素類型不呈現**全系統性缺席**（以 §四 配額／IOU 驗證）。

## 七、黑海與版圖擴張（設定草案）

**世界尺度**：不預設「地圖有邊」；版圖可隨人口／帳號擴張而長。

### 帳號與角色（定案）

- **新帳號即新玩家**：每位新帳號首次進入遊戲，適用 **黑海開局**（見下）。  
- **同帳號僅能擁有單一角色**，與既有文字版規則一致；不討論「同帳多角切換」。  
- **刪帳**：該帳號曾開出、但**尚未與大世界接軌**之彩格所屬版圖，不隨刪帳而抹除地形契約；該區塊改標為 **遺落之地**（無主、待接），**仍遵守彩格釘死**。之後可由**其他玩家之區域**擴張接縫，或由**大世界**（已對接區域之聯通體）擴張接上。

### 新玩家與黑海

- 每位 **新帳號** **初次登入**時，生成位置落在 **黑海**（舊稱黑格海）：在體感上四周皆迷霧／黑格，**尚未**與「早已存在於伺服器上的其他已對接區域」在敘事或 UI 上接通。  
- 黑海中的格子仍遵守 **未結 → 彩格揭露 → 契約釘死**；黑海不是「無規則區」，而是**開局包膜**的一種。

### 後台視角（版圖）

- 每多一名 **新帳號**，世界在資料結構上多一塊 **區域（chunk／宏區）**；這些區域在**拓撲上彼此相鄰**（後台知道拼圖怎麼接），但**身陷黑海的玩家不知道**自己離「別人的區域」多近、何時會接上。  
- 設計意圖：**增量世界**＝玩家帶來觀測與邊界條件，同時也帶來**新地塊的種子**；與 §三點五 觀測驅動一致。

### 接軌條件（定案方向，須與現行野外分級合流）

- 玩家不能永遠困在「只有自己的黑海」而不與更大世界發生關係。**接軌**指：在邊界上生成合法出口／敘事事件／地理縫合，使可走連通至 **大世界／他區** 之已對接版圖。  
- **對表對象**：須與 [野外大地圖區域與場所分級規格](../design/野外大地圖區域與場所分級規格.md) 合流（世界層 Region、野外節點、城鎮接線規則等）。該檔仍使用 **Town／City** 作為城鎮規模標籤（例如外連節點數、城際距離），但**不等同**於舊版 [城鎮區域與場所分級規格](../design/城鎮區域與場所分級規格.md) 裡「幾區幾場所」的房間式配方。  
- **先前口語「鎮級／市級」**：在探索式路線下，**不得**逕自套用舊 MUD 城內分級檔的區域數來當唯一扳機；應改以**現行野外規格**中已定義之 Town／City 語意（或日後另立之「探索式聚落階級」專檔）為準。  
- **初步傾向**（仍待與現行分級精確 hook）：以較輕門檻為優先候選（對應口語「鎮級」）、較重門檻為備選（對應「市級」）；**更高階**預設**不作**接軌必要條件（達成週期過長）。Town／City **擇一或階梯**——**實作前再定一版**。  
- 接軌須遵守 **§二 單調精煉**：不得推翻該玩家已揭露之契約；僅在未結之黑格與接縫帶上補齊結構。  
- **接軌合併當下**：兩張版圖的 **聯外圖合併** 後，須 **立即重算** 受影響聚落之 **可達依附** 與 **effective_tier**（與 [人類活動地帶聚落五級—規格草案](../design/人類活動地帶聚落五級—規格草案.md) §二 **官方子圖**依附、§十 `on_topology_changed` 一致）；路斷靠遊戲內修復，無系統緩衝。合併寫入須與 **野外 Town／City** 等標籤 **同步收斂**（§十七），**捷徑／portal** 不當官方幹線者 **不**滿足 §一 計數（見該檔 §1.1、§12.4）。

### 玩家體感（定案）

- 對玩家而言，無論後台是否已把某格標為彩格、是否遺落之地再接上，**體驗上都仍是「可探索的未知」**——不預設在 UI 上揭露「這是別人舊地圖」；敘事上以世界內發現、邊疆、廢土、傳送等語彙承接即可（細節另案）。
