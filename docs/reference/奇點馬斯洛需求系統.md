# 奇點馬斯洛需求系統

> 本文件定義《奇點世界》中**角色（NPC＝玩家）的需求層級**，作為**決策引擎**的底層依據：需求未滿足 → 產生意圖 → 驅動行為（求職、乞討、採集、帶貨兜售等）。行為意識與身份湧現皆由此支撐。
> 
> **🏆 核心哲學：世界改變了，相對位置沒變；環境富態了，生存規律依舊。**
> 
> **世界的強度全面通膨**：高密度 Token 灌注導致萬物「富態生長」。野獸更強、植物更韌、礦物琉璃化，環境的基礎強度（Intensity）已全面攀升。
> 
> **同頻相斥與被動耀變**：人類作為「高頻有念生物」，與 Token **同頻相斥**，天然具備阻隔游離輻射的屏障。為了在生存競爭中不被更強大的掠食者淘汰，凡人的肉體與意念已**被動地發生了耀變**。雖然他們的身軀強度遠超舊世，但在此時空下，他們依然是相對弱勢的底層凡人。
>
> **見怪不怪的日常**：凡人的生活型態什麼都沒變。他們不需要「對抗輻射」，只需要對付飢餓與貧窮。他們生活在「東西一直長，但沒把自己吃掉」的靜謐豐饒中。他們的動機依然是：**肚子餓、想安穩、想湊熱鬧、想發達、以及最終的求道轉變。**

**對齊**：[討論 002 NPC 需求驅動與求職機制](../discussions/002_NPC需求驅動與求職機制.md)、[狀態_指派_身份_核心概念](狀態_指派_身份_核心概念.md) §六、[經濟彙整](經濟彙整.md)、[世界觀：Token降維與生命演化](世界觀：Token降維與生命演化.md)、[世界觀：富態與拉鋸](世界觀：富態與拉鋸.md)。

## 一、需求層級定義（奇點收斂版）

| 層級 | 名稱 | 滿足條件（狀態） | 市井情境與行為意圖 |
|------|------|------------------|------------------------|
| **1. 生存** | 溫飽與代謝 (維持耀變) | 鎂 > 閾值（如 > 0）；若實作消耗則「鎂足以覆蓋下一週期消耗」 | **情境**：肚子會餓，肉軀不吃「富態化」的高能食物就會衰弱。一旦生命信號微弱（斷氣或斷念），「同頻相斥」的保護將消失。<br>**意圖**：賺錢（賺鎂）。去四路街口乞討、去惡地邊緣拾荒（採集）、或當行腳商倒賣。這純粹是為了支持「耀變肉身」的日常代謝。<br>**湧現**：玩家眼中的「乞丐」、「流民」、「打雜者」。 |
| **2. 安定** | 職缺與屋簷 (拉鋸防護) | 有至少一筆 assignment（有職） | **情境**：野外雖然不致被「沖刷」，但「耀變後的猛獸」是致命的。一份職缺（Assignment）意味著能待在「平衡拉鋸」的建築內。這不是魔法護盾，而是一個能安穩過日子、有穩定鎂收入的社會槽位。<br>**意圖**：應徵工作、努力留任；一旦失職則面臨經濟崩潰重回底層的風險。<br>**湧現**：玩家眼中的「夥計」、「店員」、「守衛」。 |
| **3. 社交** | 頻率錨定 (觀測共振) | 近期有與人交談／同房有人 | **情境**：這世界的物質在靜謐中過度增生。長期孤身一人，心念容易發散。凡人本能地需要去客棧、茶館聚在一起說廢話（Talk），用同類的人氣、人聲與情緒來「錨定」彼此的理智，對抗孤寂與虛無。<br>**意圖**：移動到帶有 social 標籤的地方；釋放 Idle 閒置對話與八卦。<br>**湧現**：玩家眼中的「酒客」、「旅人」、「街頭閒漢」。 |
| **4. 尊重** | 支配與有序 (身份權威) | 存款達標、身上裝備高級【附詞】法器、或擔任**高階**指派（掌櫃、朝奉等） | **與安定區別**：安定＝有無職缺（有屋簷）；尊重＝職級／財富／裝備的**相對高度**。<br>**情境**：手頭寬裕了就想顯擺。凡人追求的是支配那些混亂的富態物。穿上經「剝名」提煉、提取了有序能量的【附詞】服飾，當上掌櫃。這是對「靜謐豐饒」環境的逆向掌控與世俗優越感。<br>**意圖**：儲蓄購買有序、高價的裝備；攀比社會階級，對低頻底層展現世俗的傲慢。<br>**湧現**：玩家眼中的「朝奉」、「掌櫃」、「教頭」。 |
| **5. 實現** | 點火與降維 (主動演化) | 鎂與俗世地位已無法滿足（依 soul_seed 偏好） | **情境**：看透了這見怪不怪的平凡生活。這類人決定主動放棄保護性的「高頻頻率」（**止念**），引導高密度混沌 Token 降維入體。這是從「抵抗環境」到「融合環境」的終極演化博弈。<br>**意圖**：辭去客棧與當鋪的安穩工作，化作修士四處遊歷探險；尋找點燃「生之奇點」並探明星盤的契機。<br>**湧現**：玩家眼中的「隱世高手」、「修真狂人」。 |

**第一版實作**：只做**生存＋安定**兩層；決策優先序 = 先看生存（鎂低 → 觸發賺錢意圖），再看安定（無職 → 求職意圖；有職 → 上班／留任）。社交層可在 Idle 機制中自然展現。

## 二、需求與狀態變數

| 需求 | 對應狀態變數 | 消耗與閾值（第一版要點） |
|------|--------------|---------------------------|
| 生存 | `magnesium`（鎂）、可選「下一週期消耗量」 | **鎂消耗**：定期 tick 扣減（購買物資、糧食消耗）；**閾值**：低於某值觸發賺錢意圖。 |
| 安定 | `assignments`（有無指派）、可選「收入預期」 | 無 assignment → 安定未滿足 → 求職意圖；有職 → 滿足，行為為上班或閒逛。 |
| 社交（進階） | 可選：`last_talk_at`、同房人數或近期互動次數 | 未滿足 → 移動至 social 場所、觸發 Idle／Talk。 |
| 尊重（進階） | 可選：存款閾值、裝備品質／附詞、assignment 職級 | 未滿足 → 儲蓄、換高階職、購買高價裝備。 |
| 實現（完整） | 依 soul_seed 或長期目標旗標（止念／星盤由世界觀與後續系統定義） | 實作可簡化為「依 seed 的離職探險意圖」；避免需求系統與修真系統過度耦合。 |

實作時需：**鎂的定期消耗**（驅動力）、**生存閾值**（如 `magnesium < 50`）、**安定**（依 `len(assignments)` 直接判斷）。層級 3～5 之狀態變數與閾值於進階／完整版再實作。

## 三、需求 → 行為意圖（決策優先序）

決策引擎每 tick／每輪依**需求滿足情況**產生意圖；優先序與 [討論 002](../discussions/002_NPC需求驅動與求職機制.md) §D 一致：

```
1. 生存未滿足（鎂低於閾值）？
   ├→ 附近有空缺場所？ → 求職 (寫 assignment) → 安定可一併滿足
   ├→ 背包有貨？ → 賣貨 (Trade) 
   ├→ 附近有可採集資源？ → 採集 (Gather)
   ├→ 附近有可狩獵目標？ → 狩獵 (Attack) (注意：底層凡人實力依然有限)
   ├→ 在 gate/social 區域？ → 乞討 (Beg)
   └→ 以上都沒有 → 移動到其他區域重試
2. 生存滿足、安定未滿足（無職）？ → 求職意圖（路過或撮合 tick）
3. 生存與安定皆滿足？ → 閒逛 (pathfind)、上班 (若有排班)、或前往社交場所
```

**進階／完整版**：在「生存與安定皆滿足」之後可擴充分支——依 soul_seed 或 Personality 決定是否優先前往社交場所（滿足社交層）、或累積存款／換職（尊重層）、或觸發實現層意圖（探險、離職求道）；具體優先序與閾值由實作階段定義。

**身份是結果**：因為生存未滿足且選了乞討 → 玩家感受為乞丐；因為有貨且選了賣貨＋移動 → 感受為行腳商。見 [狀態_指派_身份_核心概念](狀態_指派_身份_核心概念.md) §6.4。

## 四、與行人／乞討／行腳商的對應

| 現象 | 需求系統中的位置 |
|------|------------------|
| 行人為何去乞討 | 生存未滿足（鎂低）＋決策選「乞討」意圖（在 gate/social 時可行）→ 執行 Beg。 |
| 行人為何帶貨兜售 | 生存可滿足或已滿足，但「有貨要變現」或「利差可賺」→ 決策選「賣貨」意圖 → 移動＋Trade。 |
| 行人如何背包有貨 | 先前 tick 依決策做過採集／製作／購買，或生成時給初始背包。 |

整套**行為意識**（乞討、採集、賣貨、求職…）都由**需求層級未滿足**＋**決策優先序**產生，不需先給身份標籤。

## 五、實作階段與依賴

| 階段 | 內容 | 依賴 |
|------|------|------|
| **第一版** | 生存（鎂消耗＋閾值）、安定（有無 assignment）；決策優先序固定；求職撮合 tick。 | 鎂消耗周期任務、閾值數值、決策函式(狀態, 世界) 回傳**意圖**（如：求職、乞討、賣貨、採集、閒逛）。 |
| **進階** | soul_seed 權重偏移、目標堆疊；離職與流動。 | Personality、場所 max_staff。 |
| **完整** | 社交／尊重／實現層；長期目標、規劃與記憶。 | 背版、Archival 記憶庫；實現層與止念／星盤機制之邊界見 §二 備註。 |

**第一版可驗收條件（建議）**：(1) 鎂低於閾值之 NPC 在下一 tick 會產出賺錢意圖（求職／乞討／賣貨／採集之一）；(2) 無 assignment 且鎂充足時產出求職意圖。可與 [NPC 活化模擬測試報告](../testing/NPC活化系統模擬測試報告.md) 對齊擴充「需求驅動」測試案例。
