## 六角格尺度（N＝6 作輸入）

**N＝6 在此的用途**：和美術／介面一起決定**一格要多大**（螢幕 px 或世界單位）——預期一格裡要容納約 **6 個角色印記**時，反推邊長、相機與字級；**不是**單句定玩法或碰撞規則。

### 預設邊長（可先改）

**目前預設：正六角邊長 s＝100**（世界座標／美術基準；不夠再調）。**`/hex-editor/`**（`editor-leptos`）Canvas 以 **`HEX_R`＝外接圓半徑** 與 `hexToPixel` 對齊；正六角邊長等於外接圓半徑，故 **s＝100 ⇔ `HEX_R`＝100**。螢幕上單格視覺大小由縮放決定，與「邊 100」的世界約定可分開想。

**幾何（正六角、邊長 s）**：

- **尖頂 pointy-top**（常見於上下為角）：水平 **flat-to-flat** 寬＝**s√3**；垂直對頂高＝**2s**。
- **平頂 flat-top**（常見於左右為角）：水平對頂寬＝**2s**；垂直 **flat-to-flat** 高＝**s√3**。

**範例：每邊 s＝100**：

| 朝向 | 寬 | 高 |
| --- | --- | --- |
| 尖頂 | ≈ **173.2**（100√3） | **200** |
| 平頂 | **200** | ≈ **173.2** |

實作時以專案既有 **even-q／投影**（見 **`editor-leptos`**、`hexToPixel`）為準，上表為「邊長→外接矩形」對照。

### 新角色出生（權威在六角）

**唯一規則**：新角色出生在**草原**。實作固定世界座標 **(q,r)＝(0,0)**：該格契約為 `Terrain::Grassland`（`hex_editor::ensure_player_spawn_grassland_coord`）；`entities.hex_q`／`hex_r` 於創角成功後寫入 PostgreSQL。**創角不再寫入 `entity_rooms`**。舊版 MUD **房間視野**仍於**首次登入**時由 `ensure_entity_in_room` 填預設房，待 WebSocket 改為純六角視野後可移除。

### 主介面願景（與地圖同屏）

**全畫面即大地圖**；與玩家自身相關的（狀態、背包、設定、隊伍等）**不佔固定欄**，而收在**點擊玩家角色**後彈出的選單／面板。具體欄位與層級另開 UI 規格；此處只定「地圖優先、玩家資訊次層」。

### 與後端接線順序（不必「hex 全跑通才接畫面」）

**地圖畫面與 hex 後端可並行**：視距、黑格、邊長等屬**顯示契約**，可先寫死在前端／文件；伺服器只需日後對齊「玩家當前格、格資料、揭露集合」等 API，**不必**等整條 hex 模擬完才換主畫面。缺資料時可用假資料或唯讀地圖驗收手勢。

### 玩家視距（以當前格為中心，可設定圈數）

**中心**：玩家**當下所站**之六角格（`q,r`，與 even-q／`HexGrid` 一致）。

**距離 d**：該格與中心格之 **六角最短步數**（cube／axial 距離，與專案 `hex` 座標定義一致）。

**設定**：**VIEW_MAX_RING**＝**R**（正整數，例：**5** 或 **10**，可日後改）。

**顯示規則（畫面層，優先於「已開啟／彩格」記憶）**：

- 若 **d ≤ R**：進入一般繪製（地形、河流、單位等）；若專案另有「未揭露迷霧」等，**在 d ≤ R 內**再疊加。
- 若 **d > R**：該格**一律畫成黑格**（不繪地形、不顯示「已開啟」的彩格內容）。**即**：曾經走過、存檔裡已揭露的格，只要超出最遠視距，**畫面上仍強制為黑**——這是**遠距裁切**，不是存檔被刪除。

**例**：

- **R＝5**：第 **6** 圈起（**d ≥ 6**）全黑。
- **R＝10**：第 **11** 圈起（**d ≥ 11**）全黑。

相機可拉多遠另由 UX 決定；**黑格規則只依 d 與 R**，不依縮放倍率改寫。

**設計意圖（為何要有這道裁切）**：

1. **體感**：表達「遠處看不清／不必在腳下畫面裡看清全世界」——黑格是**距離上的不可辨識**，與「迷霧＝從未走過」可分屬兩層語意（實作上皆可用暗色，但規格上不同）。
2. **效能**：主畫面只保證 **d ≤ R** 這一圈的資料與繪製負載，**避免**把整張開放世界以全細節持續掛在主循環；圈外不必載入細節（或僅保留最小占位）。
3. **全圖另開**：玩家若要**看全圖、拉遠戰略視角**，走**單獨的「全地圖」入口**（選單或鈕），與平常走路的主畫面分開；全圖可用縮略、低頻更新或靜態快照，**不**要求與主畫面同一套細節與載入策略。

## 四、移動與 UI 設計（2026-04-09/10 定案）

### 4.1 視覺模式

**眼圖**（字圓模式）。畫面上是玩家字圓、NPC 字圓、格內物件，直接在 Hex 彩格上呈現。
文字敘述不佔固定欄位，改為**觸發浮現**——踩進功能格時底部浮出一行簡述，點擊 NPC/物件展開互動面板。

### 4.2 三層地圖

| 層級 | 範圍 | 用途 |
|------|------|------|
| **大地圖** | 全部已探索彩格 | 戰略總覽、回顧、路線規劃。選單進入，可縮放 |
| **視距地圖** | 玩家中心 5 格（VIEW_MAX_RING=5） | **主遊戲畫面**。固定比例尺、不縮放、可拖曳查看點選 |
| **瓦片地圖** | 技術層，玩家不感知 | 載入/渲染優化 |

- 視距地圖玩家字圓**錨定畫面中心**，世界繞玩家滑動
- 超出視距 5 格的彩格在視距地圖上**強制黑格**（遠距裁切，非存檔刪除）
- 已探索但超出視距的格子，只在大地圖可見

### 4.3 尺寸定義

字圓直徑的世界語義 = **成人平均一步跨距（≈ 0.65m）**。

| 參數 | 螢幕值 | 真實值 | 備註 |
|------|--------|--------|------|
| HEX_R | 57 px | 2.65 m | 世界座標 s=100 不變，螢幕比例另定 |
| 格寬（flat-to-flat） | 98 px | 4.6 m | 約 7 步跨距 |
| 字圓直徑 | 14 px | 0.65 m | 一步跨距 |
| 字圓半徑 | 7 px | 0.325 m | |
| 比例尺 | 21.5 px/m | — | |
| 手機可見格數 | ≈ 4 橫排 | — | 390px 寬基準 |

### 4.4 移動操作

- **點擊移動**：點螢幕上目標位置，字圓朝該方向**直線移動**
- **無自動尋路**：系統不替玩家規劃路線。撞到實體（NPC、物件、牆）即停止，玩家自行點擊繞開
- **格間/格內統一操作**：不區分模式。點哪走哪，碰到格邊界自動跨格，碰到實體自動停止
- **格內子座標**：格內有連續座標，物件各佔位置。字圓和物件都是**實體，阻擋移動**

### 4.5 移動速度

| 參數 | 值 |
|------|-----|
| base_speed | **60 px/s**（真實步行速度 ×2 倍率） |
| 實際速度 | `actual_speed = base_speed / move_cost` |

| 地形 | move_cost | 實際速度 | 穿越一格耗時 |
|------|-----------|---------|-------------|
| 道路 Road | 0.5 | 120 px/s | 0.8 秒 |
| 平原 Grassland | 1.0 | 60 px/s | 1.6 秒 |
| 森林 Forest | 1.5 | 40 px/s | 2.5 秒 |
| 沼澤 Swamp | 2.0 | 30 px/s | 3.3 秒 |

路快野慢，move_cost 本身就是「有路不走自找苦吃」的機制。不需要額外的快速旅行系統。

### 4.6 互動模型

- 所有插頭插座（功能建築、NPC、物件）都是格內實體，都有互動選單
- 玩家走到目標實體旁即可點擊互動
- 玩家自身資訊（狀態、背包、設定）收在點擊玩家字圓後彈出的選單/面板
