# 詞盤造句與技能編譯概念設計

本設計定義了如何將玩家（或 NPC）在詞盤上排列的「Token 敘事」轉化為戰鬥引擎可識別的「SkillObject」。

## 1. 造句：從詞元到敘事 (From Tokens to Narrative)

玩家將蒐集到的 **Token (磁元)** 鑲嵌在 **竅穴 (Acupoints)** 中。當這些竅穴透過連線形成語意序列時，即產生「造句」。

### 1.1 語意結構 (Semantic Structure)
系統預設幾種中文語意模板（Template）：
- **[主語] + [動作] + [目標/屬性]** (例：我 以 火/擊之)
- **[屬性] + [屬性] + [動詞]** (例：疾 疾 如律令)

### 1.2 共鳴階級 (Resonance Tiers)
- **一階 (微弱)**：詞元雜亂排列，無語意連貫。僅獲得基礎屬性加成（體/敏/氣）。
- **二階 (共振)**：符合語意模板。觸發「技能化」，編譯出具備主動效果的 SkillObject。
- **三階 (純粹)**：同一屬性或特定高級詞元的完美造句。觸發「核心變異」，產生無視減傷或真實傷害的效果。

---

## 2. 技能編譯器：SkillObject 的誕生

當玩家點擊「祭煉 (Refine)」時，後端執行編譯過程：

### 2.1 自動命名 (Auto-Naming)
系統從語意序列中萃取關鍵字彙，生成 2~4 字的簡名。
- 例：「我 以 火 焚 敵」 -> 系統授名：**【烈焰焚心】** 或 **【火焚】**。

### 2.2 數值對照與係數化
- **威力 (Power)**：由詞元本身的「能階價值」加總，再乘上 **能階係數 (α)**。
- **消耗 (AP/Qi Cost)**：由詞元數量與複雜度決定，再除以 **時脈係數 (β)**。
- **變異機率**：受 **相位係數 (γ)** 影響，決定技能是否具備特殊偏置。

---

## 3. SkillObject 結構定義

一個編譯完成的技能對象應包含以下底層數據：

| 欄位 | 說明 | 對戰鬥公式的貢獻 |
| :--- | :--- | :--- |
| **base_dmg** | 基礎傷害量 | 進入 `D_Base` 計算。 |
| **ap_threshold** | 發動門檻 | 進入 `Action Threshold` 計算。 |
| **qi_cost** | 消耗氣脈 | 進入 `Qi_Drain` 計算。 |
| **resonance_tier** | 共鳴階級 | 決定 `Resonance_Multiplier` (1.0~2.5)。 |
| **attribute_tags** | 元素/類型標籤 | 與環境標籤 (Terrain Tags) 產生共鳴。 |
| **effects** | 附屬效果 (Buff/Debuff) | 如「姿態損耗加倍」、「AP 恢復減緩」。 |

---

## 4. 戰鬥中的執行流

1. **蓄能**：角色 AP 達到該 SkillObject 的 `ap_threshold`。
2. **檢核**：檢查當前 `Qi` 是否足以支付 `qi_cost`。
3. **結算**：調用 `combat.ResolveV2`（現有戰鬥結算），將 SkillObject 的屬性代入公式。
4. **回饋**：產出包含「系統授名」與「敘事結果」的戰報。
