# 決策 011：世界場所與居民位置採單一真相

**狀態**：已定案；場所單一真相持續有效，舊方格暫存狀態已由決策 013 取代  
**日期**：2026-07-19  
**取代**：[決策 005：空間單位與視野範圍](005_room_cell_view_scope.md) 對世界位置的定義；舊房格只保留相容視圖身分

## 問題

實作前，世界同時存在四種沒有共同權威的位置表示：

- 白塔半島 37 個已接受地理拓撲節點；
- 舊方格 runtime 的 119 個格子與 304 條有向出口；
- `entities.grid_x/grid_y`；
- `entity_rooms.room_id` 與 NPC 記憶體路徑。

這會造成三個根本錯誤：把半島級地理容器當成房間、讓玩家與 NPC 活在不同的
移動系統，以及重啟後人物無法解釋自己為何在某處、要去哪裡、走哪條路。

本決策承接以下已定產品要求：世界先成立，人物再在其中自主生活；沒有玩家時世界
仍運轉；玩家與 NPC 使用同一套世界規則；移動的基礎語彙是東、西、南、北、上、
下、進、出。

## 決策

### 1. `world_places` 是位置主資料

每個可被人物、物件、工作或事件指向的地方，都以穩定 `place_id` 表示。場所可以
形成多尺度父子關係：

`白塔半島 → 地理區域 → 地方 → 場所 → 出入口`

`parent_place_id` 表示容納關係，`topology_node_ref` 表示場所屬於哪個已接受大地理
節點。座標可以是場所屬性，但不再是場所身分。

白塔半島的 37 個 `topology:*` 節點是已接受、正典、不可直接通行的地理容器。
拓撲關係描述山海、水系、鄰接與包含，不冒充人物一步能走過的旅行路線。

### 2. `world_routes` 是唯一通行關係

人物只能沿明示的有向路線移動。每條路線保存：

- 起點與終點 `place_id`；
- 八個方向詞之一；
- 通行方式；
- 正整數旅行成本；
- 正典、狀態與來源。

最短路徑依旅行成本計算，不把拓撲父子關係或任意座標鄰接偷當道路。地形阻礙先以
成本形成停留時間；無有效路線就不能抵達。

### 3. `entities.place_id` 是人物所在位置

玩家與 NPC 都由同一欄位回答「現在在哪裡」。`grid_x/grid_y` 與
`entity_rooms.room_id` 只是舊 runtime 的相容鏡像；位置變動由同一交易原子更新，
不得再各自寫入造成漂移。

永久角色 `codex` 受遷移驗收保護：場所升級前後舊座標必須完全相同。

### 4. 玩家與居民共用 PlaceGraph

玩家方向指令與居民自主移動都查詢同一份 `world_places + world_routes`，並走同一個
位置寫入入口。NPC 不再維護一份座標專用世界；目的地選擇、可達性、加權路徑、
移動成本、在場人物與抵達後果都以 `place_id` 判定。

### 5. 旅程必須可查詢、可續行

`entity_journeys` 保存人物目前移動的：

- 原因 `reason`；
- 目的地 `destination_place_id`；
- 尚未走完的 `planned_path`；
- 最近後果 `consequence`；
- 更新時間 `updated_at`。

服務重啟時恢復未走完的路徑，而不是重新擲骰一個行為。人物查詢可以同時回答位置、
當前活動、原因、目的地、路徑與後果。

## 舊資料處置

2026-07-19 稽核的 119 個舊格，沒有一個能誠實對應白塔半島已接受地理節點。因此：

- 全數升為 `legacy:grid:x:y` 場所，狀態是 `material`、`canon=false`；
- 保留原名稱、地形、描述、標籤、座標及 304 條有向出口；
- 不改名、不假接 `topology_node_ref`，也不宣稱它們是白塔半島；
- 既有 1,573 名實體先無損遷移到這批相容場所，等待真正的白塔地方與場所內容成立。

這不是把舊方格升格為正典，而是讓既有居民先有一致、可追查、可替換的位置身分。

## 沒有採用的方案

| 方案 | 未採用原因 |
|---|---|
| 在 `grid_cells` 增加拓撲欄位並繼續以座標為根 | 把大地理、地方與房格壓成同一尺度，無法容納室內、樓層、入口及非幾何場所 |
| 讓 37 個拓撲節點直接成為可走房間 | 山脈、水系與半島容器不是一步移動距離；拓撲關係也不是旅行路線 |
| 玩家保留房間移動、NPC 另做世界旅行 | 同一人物會因是否由玩家控制而換物理規則，違反玩家＝NPC |
| 把 119 個舊格批次改名成白塔地點 | 沒有地理證據，會把測試素材偽造成正典並污染後續世界內容 |
| 只把 NPC 目的地放在記憶體 | 重啟即失憶，無法倒查人物行為，也不能證明世界在玩家離線時是同一個世界 |

## 驗收快照

2026-07-19 正式服務冷重啟後：

| 檢查 | 結果 |
|---|---|
| 場所分層 | 37 個 `accepted/canon` 拓撲容器；119 個 `material/non-canon` 可通行相容場所 |
| 通行關係 | 304 條有效有向路線，旅行成本 1～3；3 條舊山地明示通道以 `passage` 保留 |
| 人物位置 | 1,573／1,573 實體有 `place_id`；與座標、room 鏡像漂移為 0 |
| 居民旅程 | 1,553 名 NPC 均有持久化旅程紀錄；進行中數量隨世界 tick 改變 |
| 冷重啟 | 抽查中的五步旅程於重啟後消耗第一步並繼續，不重新選目的地 |
| 每日經濟 | `world_daily_economy` 每遊戲日只結算一次；重啟沒有重複扣款 |
| 永久角色 | `codex` 保持 `legacy:grid:1:-2` 與 `(1,-2)` |
| 品質閘門 | `cargo check --all-targets`、全測試、專案 clippy、`./start` 全部通過；服務為 active |

## 邊界

本決策完成的是世界的場所、路線與居民位置承重層；決策 013 已用完整 Azgaar 作者
資料建立正式可通行的白塔低層底盤。這仍不等於 305 個描述性區域名稱、政治文化與
精確邊界全數升格正典，不能靠 runtime 身分偷渡內容定案。

本決策也不決定文字 GUI 的版面、八方向的控制元件、自由輸入、玩家可見資訊密度、
座標投影或地圖外觀。
