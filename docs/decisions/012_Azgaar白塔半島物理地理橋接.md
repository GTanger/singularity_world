# 決策 012：Azgaar 完整作者資料作白塔半島底稿

**狀態**：完整作者資料採用方式已定案；作者包邊界有效，runtime 啟用由決策 013 承接  
**日期**：2026-07-19；2026-07-20 改為完整保留、局部調整並完成一次產出驗收  
**承接**：[決策 011：世界場所與居民位置採單一真相](011_世界場所與居民位置單一真相.md)

## 問題

白塔半島已有 37 個正典大地理節點，但尚未有能承載人物移動、地形阻礙、河流與
後續場所設計的低一層物理地理。直接手填會失去海岸、集水區、山脈、濕地與陸塊
之間的計算關係。先前為防止生成內容偷渡成正典，錯把 Azgaar 已算好的名稱、聚落、
道路、國家、文化等層直接丟棄，等於一面採用專案、一面重做它已完成的工作。

## 決策

### 1. Azgaar 是離線作者工具，不是 runtime 或玩家表面

固定使用 `Azgaar/Fantasy-Map-Generator` commit
`73e43d2b44b9b85b42c5394a0476d90bb22d688e`、seed
`white-tower-peninsula-v1` 與 `whiteTowerConstrained` profile。一次產出包含可回載
`.map`、Full JSON、五種 GeoJSON、政治／生態／高度／正典疊圖的 SVG 與 PNG，並另產
`data/world/white_tower_physical_geography_v1.json` 作奇點橋接。現行文字主要表面
不變，服務啟動也不依賴 Azgaar、Node、Playwright 或 SVG renderer。

### 2. 37 個正典拓撲節點仍是權威

每個物理區塊必須掛回 `white_tower_topology_v1.json` 的既有節點。Azgaar 可以計算
海岸、陸塊、海拔、生態、河系和相鄰關係，不能新增或改寫正典地名與大地理關係。

### 3. cell 不是世界場所

本輪 100,000 個生成格、57,623 個 packed cells、54,911 個主要陸地 cells，先依
作者正規化空間聚合，再把小於 24 cells 的同拓撲相鄰碎片併回，形成 305 個物理區塊
候選。它們可轉成既有 `WorldPlace`，但保持 `material/canon=false`。

相鄰區塊產生 1,642 條雙向陸路候選，風舶嶼與風舶角另經天然港灣道補上雙向渡船，
總計 1,644 條 `WorldRoute` 候選。它們保持 `candidate/canon=false`，不會被現行
`PlaceGraph` 當作 active 路線。1,129 條河流保留來源、父河、流域、源頭、河口、
長度、流量與寬度；黑沼林是濕地，湖泊數為 0。

### 4. 完整原生資料保留，身分分三類

- 保留：cell 鄰接、高度、生態、河流層級、陸塊、固定來源證據。
- 只作候選：聚合物理區塊、方向提示、相對旅行成本，以及 Azgaar 生成的名稱、burgs、
  routes、states、provinces、cultures、religions、politics、markers、zones、notes、
  goods、markets 與 deals。它們完整留在作者包內，之後可逐項校正，不因尚非正典而刪除。
- 拒絕：只拒絕把 Azgaar renderer 當成玩家 UI，或把任何候選直接冒充奇點正典／runtime。

本次原生作者包實際保留 1,666 個聚落、1,244 條原生道路、23 個國家、487 個行省、
9 種文化、14 種宗教、456 個標記、15 個區域覆蓋層、1,129 條河流、71 種商品、54 個市場與
25,808 筆交易候選。這些數字是可編輯底稿，不是奇點世界已接受的內容數量。

2026-07-21 全量正式化稽核補正：marker `id=0` 與 zone `id=0` 都是真實來源記錄；
舊驗證把零誤當空值，才少算為 455／14。來源包未重生，正確數量是 456／15。

### 5. 先用現有資料，再做局部細節調整

同一種子產物是後續優化底稿。遇到白塔設定衝突時，先在既有 cells、地形、道路、聚落
與其他層中找可用資料並局部調整；只有地理依存關係真的受影響時，才重算受影響層。
不得因單一缺陷重抽整張地圖，也不得繞過 Azgaar 自己手寫一套世界生成器。本次文曜與
南哨即改採附近既有乾地格：文曜高度 41、非河道；南哨高度 38、非河道且非濕地，
底層地形與其餘原生層沒有重生。

### 6. 約束輪廓通過，仍不自動升格正典

代理實際觀看三輪高度圖與生態圖後才收斂 profile。最終版本把白塔雪冰候選由 6,903
cells 收到 1,945 cells，最南只到作者座標 `y=0.24973`，不再沿青脊山形成巨大冰帶；
黑沼林濕地候選由 8,946 cells 收到 4,686 cells，改由下游主幹、不對稱回水支汊與
南部池沼構成，不再是規則橢圓，且中央森林仍與黑沼林分開。

這代表 `whiteTowerConstrained` 作者 profile 已通過本輪視覺驗收，不代表每條海岸、
河道或濕地邊緣已成正典。`runtimeAuthority=false`、`playerFacingMap=false` 必須保持。

### 7. 三源匯流已能由生成河網重現，精確線位仍是工作提案

生成器不再只保存 1,129 條互不解釋的河流碎片，而會沿 Azgaar 的 cell 流向追蹤並
辨識四個既有拓撲角色：北來源、西來源、東來源與共同下游。三條來源河的起始河段
互異，但同屬流域 `592`，在作者座標 `(0.481031, 0.51889)` 的同一個 cell 真正匯流；
共同下游距黑沼林錨點最近 `0.023738`，並在 `(0.497, 0.99755)` 由半島南界接續，
沒有再錯向西南海岸流出。南界只表示縮略圖外仍有河道，不表示在此入海或世界結束。

代理另實際觀看五輪水文疊圖與最終重跑證據。前四輪分別抓出「到南哨附近才合流」、
「文曜周圍低地被壓平」與「主幹只擦過黑沼林後逃向西南海岸」等假通過；最終高度圖
與生態圖才同時通過三源、匯流、單一主幹、黑沼林核心與南界接續的視覺檢查。

四個拓撲角色是既有正典；`majorHydrology` 只把一組可重現的生成河段掛回這四個角色，
本身保持 `working_proposal/canon=false`。它沒有替河流命名，也沒有決定河段、渡點、
沿岸聚落或玩家畫面。

## 驗證與重現

- `cargo run --bin white-tower-map-generate` 一次完成固定 Azgaar 來源、原生 build、
  完整匯出、staging 驗證、安全替換、正式橋接驗證、伺服器停止與暫存清理。
- `scripts/azgaar/white-tower-bridge-export.mjs` 只調用 Azgaar 原生存檔／匯出能力並
  加上白塔約束與收據，不另造聚落、道路、國家、文化或交易層。
- `white-tower-package-check` 驗 15 個原生輸出、SHA-256、Full JSON 層數、GeoJSON、
  1600×1000 SVG／PNG、可回載 `.map` 與非正典／非 runtime 邊界。
- `src/world/physical_geography.rs` 驗證來源、拓撲、守恆、錨點、陸塊、河流、
  路線、連通性、雪域／濕地比例、四段主要水系與禁止升格邊界。
- `white-tower-geography-check` 實際建立含 305 個節點的候選 `PlaceGraph`。
- 邊界測試會拒絕 runtime／精確河道升格、斷裂路線、一 cell 一場所膨脹、雪域再次
  南伸、三源延後匯流、下游錯向西南海岸、文曜落回河道或南哨落回濕地。
- Azgaar 名稱生成偶發的 `Name is too short` fallback 只保存在
  `rejectedSurfaceErrors`；名稱層仍完整保留為候選，不會因此升格正典。其他
  console/page error 仍會阻擋。

## 尚未決定

### 2026-07-20 後續決策

[決策 013：白塔半島正式活世界啟用](013_白塔半島正式活世界啟用.md) 將本作者包
編譯成獨立的 `white_tower_runtime_v1.json`：305 個物理區域與 1,644 條路線現已
全部進入 active runtime，所有作者層則逐一標成 runtime、runtime evidence、retained
candidate 或 rejected surface。

因此，本頁的 `runtimeAuthority=false` 是指 **Azgaar 原始作者包與物理橋接本身**，
不再表示它們不能作正式世界的來源。編譯後 runtime 具有運作權威，但仍是
`canon=false`：生成的政治、文化、名稱與精確輪廓沒有因此成為正典。

仍未決定的是 305 個區域的正典地名與精確尺度、哪些 operational 路線日後獲得正典
道路身分，以及哪些海岸、雪線、河網與濕地邊緣要升格。它們不阻擋人物在完整物理
底盤上生活，也不能由技術生成結果代答。
