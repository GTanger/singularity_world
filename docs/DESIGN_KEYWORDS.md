# 奇點世界 — 設計關鍵字

以下為遊戲核心設計關鍵字，供企劃與開發對齊方向使用。

## 2026-07-13 畫面方向補正

- 使用者決定重啟最初概念：**2D 平面大地圖、開放世界**。
- 主要遊戲畫面原則上採全螢幕、可縮放的大地圖；玩家與 NPC 以小型角色
  或圖標直接存在其中。
- 純文字 MUD 不再是主要玩家畫面；文字改為對話、狀態、互動選項與結果
  回饋層。
- 此補正不自動決定 Hex／方格、角色圖像、美術風格、移動方式或遊戲引擎。
- 詳見 [2D 平面大地圖開放世界主畫面](design/gdd/21-2d-open-world-primary-surface.md)。

## 設計核心

**從有限框架延伸出無限可能。**

### 緣起與訴求

- 緣起曾是**將文字 MUD 放在手機上玩**並省略輸入指令；現行本體已重啟為
  **手機上的 2D 平面大地圖開放世界**，仍以點擊、拖曳等指觸操作取代繁瑣指令。
- 不想讓旅途只是**一長串方向指令**；也不想世界顯得過小，或**大卻空蕩蕩無聊**。
- 因此才有**萬名以上異步 NPC** 的設計：用他們把世界撐滿、有生命感。且是**多差異個性**的 NPC，**不是萬名以上複製人**。

**用語**：本文件所稱**離線／下線**，皆指**玩家本身中斷操作角色**（非泛指登出或關閉 app 等）。

## 視角與畫面

- **Top-down 的 2D 平面大地圖視角**
- **全螢幕、可縮放的大地圖是主要遊戲畫面**
- 畫面上出現的**每個東西都是可互動的物件**
- 玩家與 NPC 原則上以**小型角色或圖標**存在地圖上；舊「圓形＋中文字」
  只是歷史候選，不再是未經重審即可沿用的定案外觀
- 凡是大於人形體積的固體物件都是**實體、不可穿越**
- 地形由 2D 地圖直接呈現；字符、tile、向量或其他美術語言仍待決定
- **前端僅是顯示窗口**，全靠後端計算與設計
- **單一地圖渲染**：**玩家介面**與**地圖編輯器**共用同一套後端契約與地圖渲染語意（不各做一套格網合成規則）；可先以編輯器調後台，再接玩家端。見 [地圖渲染—單一管線與雙前端共用](design/地圖渲染—單一管線與雙前端共用.md)。
- **深度沉浸**。**重體驗、輕操作**；GUI 直接承載空間、人、物與狀態，
  文字承載對話、選項與結果，不再以「重文字、輕畫面」限制主要呈現

## 世界

- **環境基調舊素材：沃土風（非廢土）**：本條原本與「能量充沛」設定對齊；2026-06-24 聯合創作重啟後，**不得再把能量充沛、能量像空氣、沃土風或常理化奇幻＋能量充沛當成預設世界根**。若使用「能量充沛」，窄義是世界走向**個人運用能量的發展**，不是環境肥沃或富態生長。核心是**運用能量的方式不同**，不是能量種類不同；不得回退成元素表、咒語決鬥單系統、職業表或「法師 vs 武者」。詳見 [open-personal-energy-use-framework-v0](design/world/open-personal-energy-use-framework-v0.md)。以下「富態生長、靜謐豐饒、無廢土感、豐饒≠安全、亞馬遜級生機」只保留為可回看素材與待驗假說，未經玩家角度重新確認前不得支配新世界本體。
- **城鎮即大地圖的真開放世界**：首版先嘗試**城鎮與野外同一張大地圖**，不切換成另一張「城鎮內」地圖；一圖到底、真開放。（詳見 [決策 003：地圖模型](decisions/003_map_town_as_world.md)）
- **世界就一個平面**：建築是**立於地圖上的實體物件**；**不設計進出建築**（無室內、無進出切換）。**功能建築**＝玩家接觸後點擊，提供可交互選項（依插頭／插座）；**不可交互建築**＝地圖上擋路實體，不調整移動方向就會撞牆。
- **無縫大世界**
- **開放世界**
- **世界永遠在線模式**：世界時間不因玩家下線或無玩家觀測而停止；角色、NPC、氣候、經濟與事件仍依後端全域時鐘推進。
- **同服在線玩家**：可能最多約十人，最少僅我一人
- 數萬人隨意在世界遊走，**多差異個性 NPC**
- NPC 模擬玩家，產生**亂數、可觀察、可參與的事件**
- **探索**：在大世界漫遊探索
- **冒險**：在區域地點的冒險

### NPC 故事線：觀測與坍縮

- **觀測坍縮不等於未被觀測者時間停止**：未被玩家看見的人、事、物仍隨全域世界時間推進；坍縮處理的是「玩家觀測時，哪一條可追溯故事線被承認為當下事實」，不是把場外世界凍結。
- 在**玩家視線未及之處**或**玩家下線後**，NPC 處於**多重疊加態的故事線**（多條可能並存）。
- **玩家上線且觀測到**（線索觀測到）該 NPC 時，**坍縮成現在態單一故事線**。
- **玩家實際接觸**該 NPC 時，**連過去態都坍縮成單一故事線**。
- 當玩家**離開視線或離線**，該 NPC 的**現在態與未來態**再度恢復為**多重疊加態的故事線**。

## 角色與物件

- **遊戲內任一角色都是實體**：玩家與 NPC 碰觸時產生**真實物理現象**——輕則推擠、重則撞開，須謹守；屢次此類行為可能觸發衝突乃至戰鬥。
- **萬人萬相**：沒有任何一個人是一模一樣的。即使同一套功法、同一個老師、同一種訓練，每個人學起來、用起來也不同；可用護法咒作比喻：同一個咒，每個人的護法不同。功法只是共同文本與共同起點，不是把人分類的盒子；制度可以命名、教學、考核，但不能窮盡或凍結一個人的相。這不是反制度或反功法，不是固定路徑分類，也不是換皮特效或外觀隨機化。壓縮句：**同法不同相；制度教法，個體成相**。
- **功法有高下，勝負無定式**：沒有抽象意義上永遠最強的咒語，只有在某個人、某個時刻、某個問題面前最恰當的咒語。功法也許有優劣，但強弱與輸贏不能只看功法；人的相、理解、熟練、臨場判斷、對手、環境、時機、代價承受與恰當使用都會改變結果。制度可以評鑑功法，但排名不等於世界真理。
- **成熟不是只會更強**：功法優劣不只看威力，也看穩、快、省、隱蔽、易教、容錯、後勁、代價與失控風險；相性比等級更活。成熟的能量使用者知道何時不用、少用、慢用、借物用、借地用、借人用，甚至讓對方失去出手條件。恰當性不只服務勝負，也服務救人、封鎖、修復、偵查、搬運、遮蔽、溝通、立信與取證。
- **全物件化、可動作交互**
- **不可僅憑文字創造物件**（不可無中生有）
- **不可無中生有**（思維邏輯閉環）
- **玩家不是上帝，玩家不是主角**；玩家與 NPC 都是**自己故事的主角**（例：如《魔獸世界》設定，哪怕玩家完成 A 地全任務，在 B 地仍是一名陌生過路人）
- **玩家等於 NPC，NPC 等於玩家**
- **既有 NPC 暫存不刪**：目前資料庫／runtime 內已有一批 NPC，先保留作為位置、排程、互動、經濟與 UI 測試載體；之後再「洗白」其人格／記憶／背景，重新灌入新的靈魂資料。清地圖、清 UI、清舊系統時不得把這批 NPC 誤刪。
- 玩家下線後**角色變成在線 NPC**，執行玩家下線前設定的**簡單任務**
- **全身多部位裝備**
- **裝備 = 工具**；**工具熟練度**
- **無職業綁定**

## 架構與數據

- **設計架構嚴謹**
- **思維邏輯閉環**

  不直接把後端欄位與量化表格丟給玩家

## 戰鬥

- **戰鬥規則統一**：**玩家 vs NPC**、**NPC vs NPC**、**玩家 vs 玩家**皆同一套規則；不因身份區分。（詳見 [決策 001：戰鬥規則統一](decisions/001_combat_unified_rules.md)）
- **PvE 不等於安全區養老**：本作不採 EVE／Albion 式全開放 PK 作為核心壓力，但也不讓 PvE 玩家只能待在安全區。荒野探索、NPC／勢力事件、資源競逐、建設／物流／救援與城鎮／門派戰事，才是 PvE 玩家可長期參與的高張力內容。
- **戰鬥全自動、文字 log**
- 分秒輸贏靠**裝備、技能等數據（後端）屬性配置**（類似**田忌賽馬**概念）
- **自創技能**（非「耶穌說有光，於是就有光」式的憑空創造，需符合世界規則）
