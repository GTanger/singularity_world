# 交易 — 從對話到交易與面板設計

## 共識與收斂摘要

以下為「從對話到交易」與「交易面板」的設計共識，實作時以本摘要＋各節細節為準。

### 從對話到交易

| 面向 | 共識 |
|------|------|
| **雙入口** | 有 Trade 插座的 NPC：**一**直接點「交易」按鈕（do_action Trade）；**二**在 Talk 中選可對話主題「想看看你有什麼」等，後端辨識意圖後回傳 **open_trade: true**，前端開同一套交易面板。兩者並存，不互斥。 |
| **可對話主題** | Talk 的預設主題清單中，對**有交易標籤的 NPC** 增加一項「想看看你有什麼」／「有什麼可以買？」；送給後端時以約定句或 topic_id 辨識為「開啟交易」。 |
| **協定** | 後端在 `action_result` 帶 **open_trade: true**（或 **suggested_action: "Trade"**）＋ **entity_id**；前端收到即開交易面板並可依 entity_id 請求商品清單。直接點 Trade 時 do_action `action: "Trade"` 回傳商品清單或交易 payload，前端開同一套面板。 |
| **進階（可選）** | 日後 CallAITalk 若回傳結構化 `suggested_actions: ["Trade"]`，可依對話脈絡由模型建議開啟交易；第一版採「可對話主題＋協定」即可。 |

### 交易面板

| 面向 | 共識 |
|------|------|
| **形式** | **頁面彈窗**（modal），與裝備頁、背包頁同級。 |
| **陳列** | **手風琴式**（accordion）：商品以分類或單品為一組，預設收合；玩家**點開**該項再展開**詳述＋價格**。 |
| **單品** | 展開後：**名稱、描述、價格**；**可堆疊**商品另提供**數量**選擇（數字或加減鈕）、小計。 |
| **資料** | 店舖 NPC → 店舖庫存（場所）；行腳商／一般 NPC → 該 NPC 背包。API 回傳 items（含 id, name, description, price, stackable, max_stack）供前端渲染。 |
| **一致性** | 彈窗、關閉鈕、手風琴與裝備／背包頁同一套 UI 語言；無障礙（焦點、鍵盤、ARIA）對齊。 |

**未決／可選**：購物車一鍵結算或逐筆確認依產品決定；topic_id 與可對話主題清單由前端寫死或後端提供。

## 一、問題與目標

- **目前**：討論多聚焦在「純對話」（Talk）；有**交易標籤**（或 Trade 插座）的 NPC 該如何**從對話進入交易**？
- **面板**：交易介面希望與裝備頁、背包頁一致——**頁面彈窗**、**手風琴式陳列商品**，點開商品再顯示詳述與價格，可堆疊商品另加數量選擇。

以下為從對話到交易的流程設計與交易面板設計要點。

---

## 二、從對話到交易

### 2.1 原則

- **有 Trade 插座的 NPC**：在房間內、且符合場所時（店舖 NPC 在店內）具備 Trade 動作；玩家可**直接點「交易」**，或**在對話中觸發**。
- **從對話開啟交易**：不取代「直接點 Trade」，而是多一種入口——在 Talk 裡表達意圖（例如選「想看看你有什麼」、或輸入「我要買東西」）後，由**後端或前端**辨識為「開啟交易」並打開交易面板。

### 2.2 三種接法（可並存）

| 作法 | 說明 | 優點 | 備註 |
|------|------|------|------|
| **A. 可對話主題含「交易」** | 在 Talk 的**可對話主題**清單中加一項「想看看你有什麼」／「有什麼可以買？」；後端辨識到該句（或約定 topic_id）→ 回傳**特殊結果**（如 `action_result` 帶 `open_trade: true` 或 `suggested_action: "Trade"`），前端收到即**打開交易面板**，不顯示一句 NPC 回覆或同時顯示一句＋開面板。 | 與現有「主題＋其他」UI 一致；玩家先選話題再進交易，脈絡自然。 | 需協定一個「意圖＝開交易」的約定（例如固定 topic 或 player_input 白名單）。 |
| **B. 對話模型回傳結構化** | CallAITalk 回傳除 narrative 外可選 **structured**（如 `{ "narrative": "…", "suggested_actions": ["Trade"] }`）；前端若見 `suggested_actions` 含 Trade 且該 NPC 有 Trade 插座，則顯示「要與他交易嗎？」或直接開交易面板。 | 模型可依對話脈絡建議「現在可以交易」；體驗最彈性。 | 需模型輸出格式穩定、後端解析與 fallback。 |
| **C. 永遠並列「交易」按鈕** | 點 NPC 後，動作列同時顯示 **Talk** 與 **Trade**；不從對話「進入」交易，而是並列入口。對話與交易分離。 | 實作最簡單；與現有插座一致。 | 不算是「從對話開啟」，但可與 A/B 並存。 |

**建議**：**A ＋ C**。可對話主題加一項「想看看你有什麼」等，送給後端；若該 NPC 有 Trade 插座，後端回傳 `open_trade: true`（或等價），前端開交易面板；同時房間／人物欄仍顯示 Trade 按鈕，玩家也可直接點 Trade 進入。B 可列為進階（模型結構化輸出穩定後再接）。

### 2.3 協定要點

- **後端**：辨識「開啟交易」意圖（例如 `player_input` 為約定句或 topic_id 對應「交易」）且該 NPC 具 Trade 插座時，在 `action_result` 或另欄帶 **open_trade: true**（或 **suggested_action: "Trade"**）；前端據此開面板，並可帶 **entity_id** 請求該 NPC 的買賣清單。
- **直接點 Trade**：現有 do_action `action: "Trade"` 維持；後端回傳該 NPC 的「想買／想賣」清單或直接回傳交易面板所需 payload（商品列表、價格），前端開同一套交易面板。

## 三、交易面板設計要點

與裝備頁、背包頁一致：**彈窗**、**手風琴式**、**點開商品再詳述與價格**、**可堆疊＋數量**。

### 3.1 整體形式

| 項目 | 設計 |
|------|------|
| **呈現** | **頁面彈窗**（modal），與裝備頁、背包頁同級；不佔滿畫面時可與背後場景並存。 |
| **商品陳列** | **手風琴式**（accordion）：商品以**分類或單品為一組**，預設收合或僅顯示標題／名稱；玩家**點開**該項再展開**詳述＋價格**。 |
| **單一商品** | 展開後顯示：**名稱、描述（詳述）、價格**；若為**可堆疊**商品，再提供**數量**選擇（數字輸入或加減鈕），並顯示小計。 |
| **操作** | 選數量後「加入」或「購買」；可設購物車一鍵結算或逐筆確認，依產品決定。 |

### 3.2 資料與後端

- **商品來源**：店舖 NPC → 店舖庫存（場所／venue 持有）；行腳商或一般 NPC → 該 NPC 背包。經濟彙整已區分「店舖庫存」與「NPC 個人背包」。
- **API**：例如 `GET /api/npc/:entity_id/trade` 或 do_action `Trade` 回傳 `{ items: [...], prices: {...} }`；每筆商品含 `id, name, description, price, stackable, max_stack` 等，前端依此渲染手風琴與數量欄位。

### 3.3 與裝備／背包的一致性

- **同一套 UI 語言**：彈窗、標題列、關閉鈕、區塊收合（手風琴）與裝備／背包頁風格一致，僅內容改為「商品＋價格＋數量」。
- **無障礙**：焦點管理、鍵盤可操作、ARIA 標籤與裝備／背包頁對齊（見專案 a11y 規範）。

---

## 四、流程摘要

```
玩家對有 Trade 插座的 NPC：
  ├─ 方式一：直接點「交易」→ do_action Trade → 後端回傳商品清單 → 前端開交易面板（手風琴＋詳述＋價格＋數量）
  └─ 方式二：點 Talk → 選「想看看你有什麼」或輸入意圖 → 後端辨識 open_trade → 回傳 open_trade: true ＋ 可選一句 NPC 回覆
       → 前端開同一套交易面板（並可帶 entity_id 請求商品清單）

交易面板：
  → 彈窗、手風琴陳列、點開商品 → 詳述＋價格、可堆疊則選數量 → 購買／加入購物車 → 後端扣鎂、增減物品、回傳結果
```
