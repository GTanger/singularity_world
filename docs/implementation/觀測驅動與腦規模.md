# 觀測驅動與腦規模

> 觀測、坍縮，往小裡說跟「身份」一樣：是玩家在操作與體驗時產生的**感受**。感受是玩家的；**發生是事實的**——誰的事實？被觀測角色的事實。他只會從無限可能中被玩家觀測到「當下」；那個當下、他的過去隨即收束成單一線性。只要持續被觀測，連未來的每一個當下都是收束的。直到玩家不再觀測……**他的事實仍在持續發生**。

## 結論

- **觀測**：只影響玩家收到什麼（敘事、視野、收束成的一條線）。不改變「角色的事實是否在發生」。
- **事實持續**：未觀測時我們仍用輕量方式讓角色的事實繼續——**不亂來**（上班時間不會被抽樣成「隨機出去逛」、睡覺時間不會被拉出門）。排班者依 gameHour 朝 work_room／rest_room 走一步；無排班者才做抽象效果（加鎂／採集／求職／隨機鄰房）。
- **規模**：有人觀測時只驅動「觀測圈」內 NPC 的完整腦＋尋路；無人觀測時不跑九萬腦，改跑抽樣式背景模擬，且尊重排班與身份。

## 作法

- **觀測圈** = 有玩家在的房間 ∪ 這些房間的**鄰房**（一階鄰接）。
- **有人觀測**：`TravelerManager.Tick(..., activeRoomIDs)` 只對「當前房間 ∈ 觀測圈」的 NPC 做完整尋路／Decide／移動與到達後行為；只對這些移動發敘事。
- **無人觀測**：觀測圈為空，不跑 Tick（不跑九萬腦）；改跑 **RunUnobservedWorldTick(database, g, gameHour, maxNPCs)**：
  - **有排班**的 NPC：依 gameHour 決定目標（在班→work_room，下班→rest_room），**朝目標房走一步**（FindPath 取第一步）。事實＝他正在上班或回家的路上，不會被當成「隨機閒晃」或半夜被拉出門。
  - **無排班**的 NPC：抽樣施加一項抽象效果（加鎂／採集／求職／隨機鄰房），不發敘事。
- 觀測只決定「誰的當下被玩家收束成一條線」；後端不讓角色的事實因無人看而停止或違背身份／時段。

## 規模直觀

- 有人觀測：僅觀測圈內 NPC 跑完整腦＋移動（數量 ≈ 觀測圈房數 × 每房 NPC，遠小於九萬）。
- 無人觀測：每輪抽樣最多 N 個 NPC（如 50）做輕量模擬，其中排班者只做「朝班表目標走一步」，無排班者四效果擇一。

## 相關程式

- `db/npc_movement.go`：`Tick(..., activeRoomIDs)` 的觀測圈篩選。
- `main.go`：`buildActiveRoomIDs(...)`；觀測圈為空時呼叫 `RunUnobservedWorldTick(database, roomGraph, hour, ...)`。
- `db/unobserved.go`：`RunUnobservedWorldTick(database, g, gameHour, maxNPCs)`——有排班則依 gameHour 朝 work/rest 走一步，無排班則加鎂／採集／求職／隨機鄰房。
