# 對話池：從固定句到組合句

> 目標：在**不寫無限條句子**的前提下，讓既有約 50 句的對話池產生**遠多於 50 種**的實際輸出，接近「無限組合」的體感。

**對齊**：[模板 README](../../data/templates/README.md) §5 佔位符、[NPC有嘴—設計與實作規劃](NPC有嘴—設計與實作規劃.md) §3.3。

---

## 一、思路：組合 > 數量

與其寫 500 句，不如：

- **50 條模板**，每條裡有 **2～4 個可替換的槽位**；
- 槽位由**小詞表**或**情境變數**填滿（房間名、時段、情緒、物品、動作詞等）；
- 同一條模板在不同情境下輸出不同句子，**組合數 = 模板數 × 各槽位選項數**。

例：1 條模板 + 3 個槽位各 5 選項 = **1×5×5×5 = 125** 種結果；若 50 條中有一半是「2 槽位、每槽 5 選」，則光這 25 條就貢獻 **25×5×5 = 625** 種，再加上其餘 25 條固定句，整體體感遠大於 50。

---

## 二、做法一：擴充佔位符（推薦先做）

### 2.1 現狀

- 已有：`{name}`（NPC 名）、`{goods}`（販賣品類）；behaviors 有 `{dest}`、`{from}`。
- 抽句時後端替換後回傳，前端看到的是「已填好的」一句話。

### 2.2 新增佔位符（由後端依情境填入）

| 佔位符 | 來源 | 範例值 |
|--------|------|--------|
| `{name}` | 實體 | 已有 |
| `{goods}` | 職業／archetype goods_pool | 已有 |
| `{room}` | 當前房間 name 或簡稱 | 「浮生客棧」「打鐵巷」 |
| `{time}` | 遊戲時段 | 「清晨」「正午」「傍晚」「夜裡」 |
| `{weather}` | 若實作天氣 | 「晴」「陰」「輻射雨後」 |
| `{mood}` | 依 Personality 或隨機抽 | 「沒好氣」「懶洋洋」「熱絡」 |
| `{verb}` | 小詞表：動作 | 「擦了擦汗」「嘆了口氣」「瞇起眼」 |
| `{thing}` | 小詞表：物品／話題 | 「這把劍」「今天的生意」「奇點」 |

同一句模板例如：

- 「【{name}】在{room}裡{verb}，{mood}地說：『……』」
- 替換後可得：「【王鐵】在打鐵巷裡擦了擦汗，沒好氣地說：『……』」等數十種。

**實作要點**：

- 在 **dialogues/*.json** 裡允許句子出現上述佔位符；
- 後端 **PickFromDialogue**（或等同函式）在回傳前：先抽句，再依 **entity、room、gameTime、personality** 等決定 `{room}`、`{time}`、`{mood}`、`{verb}`、`{thing}`，最後做一輪字串替換。
- 詞表可放在 **data/templates/dialogue_slots.json**（或依職業分檔），例如：

```json
{
  "verb": ["擦了擦汗", "嘆了口氣", "瞇起眼", "點點頭", "搖搖頭"],
  "mood": ["沒好氣", "懶洋洋", "熱絡", "心不在焉", "壓低聲音"]
}
```

這樣 **50 句 × 5×5×…** 立刻放大，且**不需改對話檔結構**，只擴充「替換表」與後端邏輯。

## 三、做法二：片段組合（進階）

把「一句話」拆成 **前段 + 中段 + 後段**，每段從**小池子**裡抽一項再拼起來。

### 3.1 格式

例如某條不再是一整句，而是一個**陣列**，表示「可選片段」：

```json
[
  ["【{name}】", "只見{name}", "那{name}"],
  ["擦了擦汗", "嘆了口氣", "瞇起眼"],
  ["，說道：「今天{room}人真少。」", "：「{time}了，該收攤了。」"]
]
```

後端：從每個子陣列各抽 1 個，依序拼接 → 3×3×2 = **18** 種結果（若同一 key 有多條這種陣列，再乘上條數）。

### 3.2 優缺點

- **優**：少數片段就能組出大量句子，體感「無限」。
- **劣**：要小心**語法與語意**（主詞、動詞、句尾搭配），否則易出現不自然句；且需約定格式（陣列 vs 字串），後端要能辨識並做「抽一拼一」。

建議：**先做做法一**，驗收體感與效能；若仍希望更多變化，再在**部分** pool（例如 idle）試行片段組合，並限制在「語法安全」的幾種句型。

## 三之一、有限框架無限延伸：可以怎麼拉桿？

框架 = **固定數量的模板 + 固定幾種佔位符 + 固定詞表**。不增加「寫死的句子數量」，只靠**組合方式**與**抽樣規則**讓體感趨近無限。以下由易到難、由已做到可做排列。

| 手段 | 做法 | 效果 | 現狀／備註 |
|------|------|------|------------|
| **1. 多槽位 × 大詞表** | 同一句多個 `{mood}`、`{verb}`、`{thing}`；詞表每槽 8～15 選項 | 1 句 → 數百～數千種呈現 | ✅ 已做：dialogue_slots + 填空句 |
| **2. 情境注入** | `{room}`、`{time}` 由遊戲狀態決定，不寫死 | 同一句在不同地點、時段不同 | ✅ 已做：房間名、清晨/正午/傍晚/夜裡 |
| **3. 擴詞表、加佔位符** | 增加 `{weather}`、`{topic}`；在詞表加選項 | 組合數再乘一層 | ✅ 已做：dialogue_slots.json + FillPlaceholders |
| **4. 片段組合** | 一句拆成「前段／中段／後段」各從小池抽一項再拼 | 少數片段 → 大量句型 | ✅ 已做：talk_fragments，probFragment=0.25 |
| **5. 池子混用** | talk 時有小機率從 greet 或 idle 抽一句 | 同一套句數，體感更不重複 | ✅ 已做：probGreet=0.12、probIdle=0.08 |
| **6. 情境權重** | 依時段／房間提高「含關鍵字」那句被抽中的權重 | 同一 50 句在不同場合分布不同 | ✅ 已做：PickLineWeighted(timeLabel, roomName) |
| **7. 微變體（引擎層）** | 填完佔位符後做小改寫（句尾啦、這兒/那兒） | 同一輸出多一點口語變化 | ✅ 已做：ApplyMicroVariants |
| **8. 子槽位** | 例如 `{verb}` 由「方式 + 動作」兩層詞表組成 | 詞表不爆量，但組合再乘一層 | ✅ 已做：verb_manner + verb_action，40% 機率組合成 verb |

**一句話**：有限框架下，「無限延伸」= **多槽位 + 大詞表 + 情境注入 + 抽樣/混池/權重**；若要再往上，就加**片段組合**或**引擎微變體**，仍不必寫無限句、也不必上 LLM。

**實作狀態**：上述 1～8 已全部接入 `db/dialogue`：擴詞表與 weather/topic、池子混用（talk 時 12% greet / 8% idle）、情境權重（PickLineWeighted）、微變體（句尾啦、這兒/那兒）、片段組合（talk_fragments）、子槽位（verb_manner+verb_action）。參數見該檔常數 probGreet、probIdle、probFragment。

## 四、做法三：LLM 動態擴寫（可選、成本較高）

- 以現有 50 句當**範例／風格**，在需要時呼叫 LLM 產出「同風格、同情境」的一句，再快取或落檔。
- 可得到真正「無限」不重複句，但需處理：延遲、成本、一致性、審核（避免出格內容）。

適合當**進階選項**，不建議取代現有池子，而是「偶爾用 LLM 補一句」的擴充。

---

## 五、建議實施順序

| 階段 | 內容 | 產出 |
|------|------|------|
| **1** | 擴充佔位符：在專案中定義 `{room}`、`{time}`、`{mood}`、`{verb}`、`{thing}` 等；後端在回傳對話前依情境替換。 | 同一句在不同房間／時段／情緒下自動變體，組合數 ≈ 50 × 各槽位選項數。 |
| **2** | 新增 **dialogue_slots.json**（或同名的詞表）：為各佔位符提供 5～10 個選項；可依職業或共用。 | 詞表集中、易調教，不污染既有 50 句內容。 |
| **3** | 在**部分**模板句中試用新佔位符（例如先改 10 句 greet、10 句 idle），驗收體感與可讀性。 | 確認無錯替換、無缺值後，再逐步擴大。 |
| **4**（可選） | 對 idle 等池子試做「片段組合」格式，約定陣列結構與拼接規則。 | 進一步放大組合數，需維護語法與語意。 |

## 六、對話池整頓紀錄

- **結構統一**：所有職業對話檔一律為 `greet: { lines: [] }`、`talk: { lines: [] }`，與 `db/dialogue` 的 `DialogueFile` 對齊。已修正 **gatherer.json**（原為頂層 `greet`/`talk` 陣列）。
- **填空句**：在 **乞丐、拾荒者、守衛、服務生、行腳商** 的 `talk.lines` 中，各加入數句使用 `{room}`、`{time}`、`{mood}`、`{verb}`、`{thing}` 的模板；情境由後端依房間名、遊戲時段與 `dialogue_slots.json` 填入，同一句可產生多種組合。
- **詞表**：`data/templates/dialogue_slots.json` 提供 verb、mood、time、thing 選項；未傳入情境時由系統隨機抽選填入。
- **運作說明**：見 [對話池模擬運作機制](../reference/對話池模擬運作機制.md)。

---

## 七、小結

- **50 條句子**不必改成 500 條寫死；用**佔位符 + 情境變數 + 小詞表**就能讓 50 條變成 **50 × N × M × …** 的組合句。
- 先做**擴充佔位符**與**詞表**，不改現有 JSON 結構，只擴後端替換邏輯，即可逼近「無限組合」的體感；若再引入**片段組合**，可進一步放大。
- 若未來要「真正無限」且接受成本，再考慮以 LLM 動態擴寫為輔助。
