## 一、角色屬性總覽

### 外顯三維：體質、氣脈、靈敏

角色對戰鬥與生活系統暴露的**有效屬性僅三項**，後端唯一真理依此結算：

| 維度 | 說明 | 主要影響 |
|------|------|----------|
| **體質** | 承傷、負重、耐性 | 減傷、霸體、生存 |
| **氣脈** | 續戰、技能消耗與回復 | 續戰力、詠唱、回氣 |
| **靈敏** | 命中、閃避、行動序 | 命中、閃避、先手 |

有效屬性公式（每維相同結構）：

```
有效屬性 = 基礎值（三軸映射） + 竅穴普通加成 + 詞元／連線加成 + 裝備加成
```

### 四相（資源系統）

四項消耗資源統稱「四相」，由體質(V)、氣脈(Q)、靈敏(D)推算最大值：

| 資源 | 公式 |
|------|------|
| 氣血 | `ceil(((0.7V)+(0.3Q)) * ((0.05D)+1) * V)` |
| 內力 | `ceil(((0.7Q)+(0.3V)) * ((0.05D)+1) * Q)` |
| 精神 | `ceil(((0.6D)+(0.4Q)) * ((0.05V)+1) * D)` |
| 體力 | `ceil(((0.5V)+(0.4Q)+(0.3D)) * ((V+Q+D)/3))` |

### 內在與外在的關係

```
SoulSeed（先天種子）
  ├── 三軸信號光譜 → 基礎體質/氣脈/靈敏 + 性格 + 本源語感
  └── 760 條邊權 → 個人專屬拓撲阻力（命盤）
            │
      功法路徑 → 打通竅穴 → 竅穴普通加成
            │
      詞元入竅 → 語意判定 → 詞元/連線加成 + 技能(SkillObject)
            │
      + 裝備加成
            ↓
      有效體質/氣脈/靈敏 → 戰鬥結算
```

## 二、SoulSeed 與三軸信號光譜

### SoulSeed（`已實作`）

每個角色誕生時，後端寫入並永久保存一筆 `soul_seed`（int64），此後不變。由此 seed 以固定 RNG 順序決定性展開：

- **前 3 次 RNG** → 三軸信號光譜（Amplitude, Frequency, Phase）
- **第 4～763 次 RNG** → 760 條拓撲邊權（歸一化後總和恆為 10000）

實作可只存 seed 載入時重算，或創角時展開並快取。

### 三軸信號光譜（念紋）（`已實作`）

念紋為三軸浮點數，表示靈魂在詞盤網路中的語意向量，除產出基礎體敏氣外，與詞元互動時決定消耗、變異與敘事。

| 軸向 | 系統名 | 區間 | 語感（低 → 高） |
|------|--------|------|------------------|
| 能階係數 | Amplitude | [0.1, 3.0] | 幽微／綿長 → 霸道／爆發 |
| 時脈帶寬 | Frequency | [0.5, 2.0] | 渾厚／重劍無鋒 → 洞察／千絲萬縷 |
| 順逆向量 | Phase | [-1.0, 1.0] | 順流／秩序 → 逆流／混沌 |

基礎體敏氣由三軸線性映射產出，不隨等級膨脹，無出身表。

### 本源（UI 呈現）（`已實作`）

後端 `GenerateOriginSentence(amp, freq, phase)` 將三軸轉為形容詞拼成一句話（如「霸道、洞察、混沌」類語感），以 `origin_sentence` 傳前端。**絕不**將數字傳前端，維持神祕感。僅自己可見。

**已廢除**：四型念紋、出身×念紋加權。

## 三、三軸推導性格

由同一 SoulSeed 的三軸值正規化至 [0,1] 推導性格維度，供 NPC 決策權重、對話語氣、求職偏好使用。不新增儲存欄位。

| 軸 | 性格維度 | 低 (0~0.33) | 高 (0.66~1) |
|----|----------|-------------|-------------|
| Amplitude | **Boldness**（強勢度） | 保守、忍讓、少議價 | 敢衝、愛議價、易換工作 |
| Frequency | **Sensitivity**（敏感度） | 遲鈍、穩定、少反應 | 易被情境影響、反應明顯 |
| Phase | **Orderliness**（秩序感） | 隨性、偏自由業/行腳 | 守規、偏固定場所/留任 |

### 性格對行為的影響

- **對話選句**：Boldness 影響句池偏移（溫和↔強勢）；Sensitivity 影響熱絡程度；Orderliness 影響正式/隨性語氣（`Boldness 偏移已實作`）
- **求職偏好**（`設計中`）：Orderliness 高偏好固定場所，低偏好行腳/自由業；Boldness 高偏好高風險高報酬
- **留任/離職**（`設計中`）：Orderliness 提高留任權重，Boldness 提高離職意圖權重

## 四、361 拓撲系統

### 總覽

人體為 361 節點的拓撲網格。連線規則（誰連誰）全服一致（萬人一相）；每條連線的阻力(Cost)由 SoulSeed 決定性生成（萬人萬相）。

### 四區分層結構

| 區域 | 節點數 | 代碼範圍 | 概念 |
|------|--------|----------|------|
| **Zone 0** (紅) | 1 | N000 | **生之奇點**：靈魂降臨的唯一起點，預設貫通 |
| **Zone 1** (橘) | 20 | N001~N020 | **二十主樞**：接收電漿流的處理核心 |
| **Zone 2** (藍) | 100 | N021~N120 | **五常邏輯閘**：每主樞 5 個（起/承/轉/協/合） |
| **Zone 3** (綠) | 240 | N121~N360 | **十二微型狀態**：末端接口，煉化詞元的實體槽位 |

### 系屬收斂

N000 無系屬。其餘 360 節點依所屬主樞收斂為三系：

- **體系**（體質）：5 主樞（天極、震淵、鎮閾、穹壁、重塑）→ 25 藍 + 60 綠 = 90 節點
- **氣系**（氣脈）：9 主樞（曜核、凜晶、淵流、萬象、解離、衡定、逆熵、神淵、坍縮）→ 45 藍 + 108 綠 = 162 節點
- **敏系**（靈敏）：6 主樞（脈衝、游離、弦絲、識閾、無相、越權）→ 30 藍 + 72 綠 = 108 節點

### 二十主樞四大陣列

| 陣列 | 主樞 | 傾向 |
|------|------|------|
| **動能/輸出** | 天極、脈衝、震淵、游離、弦絲 | 攻擊、閃避、暴擊 |
| **塑能/環境** | 曜核、凜晶、淵流、萬象、解離 | 元素攻擊、控制、分解 |
| **維穩/容錯** | 鎮閾、衡定、穹壁、重塑、逆熵 | 防禦、回復、淨化 |
| **特權/覆寫** | 神淵、識閾、坍縮、無相、越權 | 精神攻擊、隱身、規則覆寫 |

### 五常邏輯閘（藍區）

每主樞下 5 個藍點決定能量流轉的性質變換，不存詞元：

| 邏輯閘 | 功能 |
|--------|------|
| **起** Initiate | 指令握手，判定技能意圖 |
| **承** Buffer | 能量緩衝，決定持續時間 |
| **轉** Transform | 語意編譯，決定變異方向 |
| **協** Coordinate | 路徑塑型，決定影響範圍 |
| **合** Commit | 執行觸發，決定暴擊/穿透/最終威力 |

> **轉與協之間為絕對斷點**：輸入編譯段與輸出執行段在縱向上無直接連線，須經造句邏輯或橫向跳線跨越。

### 十二微型狀態（綠區）

綠點為煉化詞元的實體槽位。詞元鑲嵌在不同綠點（如「蓄」vs「釋」）會經藍色邏輯閘得到不同解釋。

- **輸入段**（起/承/轉管理，7 接口）：探、觸、納、蓄、濾、析、融
- **輸出段**（協/合管理，5 接口）：衍、律、束、釋、散
- **3:2 陣列咬合**：前三藍共兩綠（納、濾）為輸入段共用點；後二藍共一綠（束）為輸出段共用點

### 連線與邊權

共 760 條邊，分五類：

| 類型 | 連線方向 | 數量 |
|------|----------|------|
| A | 紅→橘（N000→主樞） | 20 |
| B | 橘→藍（主樞→邏輯閘） | 100 |
| C | 藍→綠（邏輯閘→末端） | 300 |
| D | 綠同層環（末端內環流） | 240 |
| E | 藍同層環（邏輯閘內環流） | 100 |

邊權生成：SoulSeed 第 4~763 次 RNG 依固定邊序抽取原始權重 r_k (均勻分布 [0.1, 1.0])，歸一化為 `Cost(e_k) = (r_k / S) * 10000`。**總阻力恆為 10000**，無絕對廢柴或天才，只有偏科。

### 能量循環

- **微循環**（綠點表層）：N000 背景輻射浸潤綠點。僅走綠連綠的功法（爛大街功法）只借用表層能量，不需打通橘藍，僅基礎數值加成（一階語意）
- **大循環**（橘→藍→綠）：消耗氣脈/鎂打通橘藍，經主樞加壓與邏輯閘編譯，觸發二階/三階語意共振，對應頂級功法

### 繞路與自創功法

若官方功法路徑上某段 Cost 極高，玩家可利用同層橫向跳線繞路。繞路改變節點數，須重新湊詞元造句，可觸發不同語意與變異技能——此即自創功法的來源。

同一本功法在不同 SoulSeed 下路徑/造句長度不同 = **萬人萬功法**。頂級功法的「頂級」分靜態潛力（全服定義）和動態匹配（你的 SoulSeed 下 Cost 是否可負擔）兩層。

## 五、星盤與命盤機制

### 星盤（UI 分頁）（`部分已實作`）

星盤為 361 竅穴網路的前端層級式呈現（第四分頁）。代碼邏輯層用 **InnerPlate**（內盤），UI 層用**星盤**。

**區塊結構**：

1. **宏觀進度**：星盤貫通率（已貫通/360）、N000 生之奇點（已點亮）
2. **二十主樞目錄**（可摺疊）：依四大陣列分組，每項顯示貫通進度、適性、操作按鈕
3. **觀測儀**（展開後）：樹狀顯示 5 藍 + 12 綠，綁定 Topology Cost

### 迷霧機制（名存實未知）（`設計中`）

所有 361 個節點名稱恆顯，但功能性內容（Cost、適性、屬性加成）在未被探明前顯示為 `[未知]`。

三層狀態：
- **未探明**：名稱可見，Cost 顯示 `[未知]`，無法打通
- **已探明**：Cost 正常顯示（語意標籤 + 精確值），可打通
- **已貫通**：節點 ID 在 `activated_nodes` 中

探明方式為 `[內視]`：消耗氣脈或鎂，將目標節點加入已探明清單。只能探明與已探明/已貫通節點直接相連的節點。

### 命盤

「命盤」是世界觀對 SoulSeed → 760 Cost 這一機制的文學稱謂。每個人的星位距離不同（Cost 不同）、方位不同（哪些主樞親近/疏遠），且命中注定（SoulSeed 創角即定，此後不變）。

**萬人萬相鐵律**：任何設計不得 (1) 為三軸賦予職業/流派映射 (2) 以預設模板覆蓋 SoulSeed 結果 (3) 讓後天操作改變 SoulSeed 或 760 Cost。

### Cost 文字化（通暢度標籤）（`已實作`）

全域平均 Cost 約 13.16，以此為中位劃分五級：

| 等級 | Cost 範圍 | 標籤 | 語意 |
|------|-----------|------|------|
| 1 | ≤ 7 | **暢流** (綠) | 極佳通道 |
| 2 | 7~11 | **順通** (青) | 阻力偏低 |
| 3 | 11~16 | **平穩** (灰) | 適中 |
| 4 | 16~21 | **滯澀** (橙) | 阻力偏高 |
| 5 | > 21 | **險阻** (紅) | 嚴重受阻 |

### 創角 Onboarding 敘事

系統日誌依序呈現：止念狀態 → 生之奇點激發 → 瞬間瞥見 360 星體 → 氣體噴湧遮蔽 → 迷霧籠罩。純文字系統日誌，不需動畫或特效。

## 六、狀態、指派與身份分離

### 核心公式

```
[ 本體狀態 (State) ] + [ 情境指派 (Assignment) ] = 系統行為 → 玩家觀測到的「身份」(Identity)
```

### 三者定義

**狀態 (State)**：實體客觀存在的資料（背包、鎂、屬性、SoulSeed 性格傾向）。狀態是觸發一切行為的根源（需求驅動）——角色不因「我是員工」而工作，而因「鎂餘額極低」觸發求職行為。

**指派 (Assignment)**：連接實體與場所(Venue)及職務(Occupation)的暫時性槽位綁定。資料結構為 `Assignment{EntityID, VenueID, OccupationID}`。系統依此為實體開放特定動作插座。拔除指派，角色立刻失去相關職能。

**身份 (Identity)**：基於狀態+行為+指派環境動態推導的觀測結果。不是資料庫中的獨立字串。客棧經理下班離開後，在他人眼裡就是路人——身份隨情境消散。

### 對話與動作模板分離

| 模板類型 | 綁定依據 | 生效範圍 |
|----------|----------|----------|
| 職業對話模板 | 職業（任命） | 任時任地 |
| 職業動作模板 | 場所綁定 | 僅在綁定場所的 room_ids 內 |
| 公共對話模板 | 無 | 任時任地（fallback） |
| 公共動作模板 | 無 | 即 Agent 預設插座（Talk, Look, Attack, Trade） |

### 場所（Venue）

場所帶一組 `room_ids`，僅列出的房間算「在場」（不採 zone，避免地圖色塊過多）。NPC 在場時獲得職業動作插座，不在場時僅預設插座。

### 無職行為的湧現

無指派的 NPC 依狀態驅動行為：鎂極低 → 乞討或求職；有貨有利差 → 帶貨移動+開放 Trade → 玩家觀測為行腳商。身份是觀測結果，不需標籤欄位。

## 八、NPC 生成流程

### 設計原則

NPC 生成與玩家一致：**只帶 SoulSeed 的實體**，職業與身份不在生成當下綁定。

### 調整後流程（`部分已實作`）

1. **生成實體**：`InsertNPC(id, displayChar, gender)` — 不寫 displayTitle，與玩家創角同邏輯（seed → 屬性/穿搭）
2. **建立場所**：Venue 帶 room_ids（如浮生客棧）
3. **指派職務**：Assignment（entity_id, occupation_id, venue_id, assigned_by）
4. **掛載模板**：依指派的 occupation 掛載對話/行為模板

### 身份解析

`GetNPCTitle` 改為查詢 assignments → occupation 名稱。無指派時 fallback `display_title` 或預設「路人」。（`已實作`）

### 插座解析

`GetSocketsForNPC(db, entityID, roomID)` — 預設插座 + 在場時加職業 action_sockets。非預設動作執行時檢查是否在綁定場所內。（`已實作`）

### 對話介面

支援雙模式：
- **自由輸入**：玩家打字 → 系統抓關鍵字 → 搜回應池 → 回傳（`設計中`）
- **點選對話**：可選關鍵字列表 → 對應池取句（`設計中`）
