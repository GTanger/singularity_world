## 0. 本檔回答什麼

本檔只回答遊戲設計問題：

- 玩家登入後到底在玩什麼。
- 玩家看見什麼、點什麼、承擔什麼後果。
- 角色、物件、NPC、經濟、探索、戰鬥、建造如何互相支撐。
- 一個場景卡怎樣才是可玩的狀態，而不是一段漂亮文字。
- 後續任何第一屏或地圖設計如何判斷自己有沒有遊戲性。
- 玩家會不會願意再點一次、再登入一次、再走深一點。

本檔所謂「完整設計」不是概念完整，而是設計層完整：骨、筋、肉、皮都要成立。骨是實體與狀態；筋是行動到後果的牽動；肉是具體玩法模組；皮是玩家畫面與文字回饋。詳見 [gdd/00-design-layer-bone-muscle-flesh-skin.md](gdd/00-design-layer-bone-muscle-flesh-skin.md)。

## 0.1 玩家角度 × 關鍵字清單雙重門

任何設計同時要過兩道門：

1. 玩家角度：使用者作為玩家看這個設計，是否看得懂、想點、點了有差、願意再玩。
2. 關鍵字清單：內容是否能追溯 `DESIGN_KEYWORDS.md`，並落到 2D 平面大地圖開放世界、輕操作、重體驗、全物件化、後端真理、永遠在線、NPC 同律、真實經濟、探索/冒險/經營/建造/戰鬥等核心方向。

雙重門的最低驗收欄位：

| 欄位 | 必須回答 |
|---|---|
| 玩家看到什麼 | 玩家不用讀文件，只看畫面能否理解自己、地點、人物、物件與路 |
| 玩家想點什麼 | 畫面是否提供明確、少量、可理解的入口，而不是散文或名詞堆 |
| 玩家做了改變什麼 | 至少一個錢、物、路、人、風險、關係、時間或痕跡發生變化 |
| NPC 是否同規則 | NPC 是否也會使用、搶先、拒絕、避開、記住或被同一狀態影響 |
| 是否有回訪痕跡 | 下次登入或重訪能否看見玩家行動或場外推進的可讀結果 |
| 是否願意再玩 | 這件事是否提供目標、取捨、未知、風險、關係、收益或非日常可為性 |
| 關鍵字追溯 | 能否指出它對應 `DESIGN_KEYWORDS.md` 哪些原始關鍵字，而不是 Codex 自創概念 |

若設計只是合理、順、漂亮、完整，但玩家角度無感，視為未通過。若設計看似有趣但不符合關鍵字清單，也視為未通過。

本檔不做：

- 不改 runtime。
- 不指定北岸渡口為唯一出生點。
- 不從任一局部場景反推整張地圖。
- 不在本檔本體展開材料百科；材料 v2 見 `world/materials-encyclopedia-v2.md`，舊 v1 只作降格素材。
- 不把上一份「設計正典」視為已被接受。
- 不把舊世界特殊設定自動接回來。
- 不用抽象詞宣稱玩家會沉浸；只接受玩家實際看到、能點、會變、會想再玩的證據。

## 1. 遊戲一句話

奇點世界是手機上的 2D 平面大地圖開放世界：玩家不是讀 AI 寫出的故事，
而是直接在持續運轉的大地圖上看見並接觸人、物、路與自己，介入 NPC、
物件、經濟、危險與場所狀態，並在下次登入或重訪時看見自己的行動和
世界自走留下的痕跡。

## 2. 玩家想像

玩家不是救世主，不是劇本主角，也不是上帝視角管理員。

玩家是一個在世界裡有身體、有錢、有工具、有關係、有去處的人。玩家登入時應該立即感到：

- 我現在在哪裡。
- 我身上有什麼。
- 我能碰什麼、問誰、去哪裡。
- 有些人正在做自己的事，不是在等我開任務。
- 我如果現在不做，可能會錯過一件事。
- 我如果做了，世界會留下可回查的改變。

這份想像是奇點的代入感來源。不是「世界表演給我看」，而是「我撞進一個局部事實裡」。

## 4. 遊戲內容的最小單位

奇點的內容單位不是「場景描述」，而是可運作的世界切片。

### 4.1 場景卡

場景卡是一段可被閱讀的當前狀態。它包含：

- 穩定地點骨架：這裡是什麼地方。
- 當下現象：時間、氣候、水、風、霧、泥、光線、人流造成的狀態。
- 在場人物：誰在場、誰缺席、誰留下痕跡。
- 可互動物件：能看、拿、用、修、買、賣、問、避開、進入或阻擋的東西。
- 出口與路況：能去哪裡、是否安全、是否需要準備。
- 事件痕跡：近期玩家、NPC、天氣、交易或衝突留下的變化。

不合格場景卡：

- 只有地名和散文。
- 只有出口。
- 只有 NPC 背景句。
- 只有材料名。
- 玩家讀完無法判斷下一步。
- 玩家能判斷下一步，但那一步只是小額跑腿、交料或局部雜務，無法支撐再玩動機。

### 4.2 物件

物件是遊戲機制，不是美術名詞。

每個核心物件至少要有：

- 狀態：完好、損壞、空、滿、被佔用、濕、熱、缺料、堵住、有人守著。
- 歸屬：無主、公共、某人、某店、某組織、暫由玩家使用。
- 動作：看、拿、用、修、搬、買、賣、掛牌、佔用、避開、破壞、求助。
- 條件：工具、金錢、關係、時間、天氣、風險、權限。
- 結果：錢、物、路、關係、風險、熟練、事件、場所狀態改變。
- 回訪差異：下次再看時不一定相同。

如果一個物件無法回答「玩家點它會發生什麼」，它只能當背景，不得佔第一屏核心位置。

如果一個物件只能回答「可以賣多少錢」或「可作材料」，但不能提供動詞、風險、關係、工具差異、NPC 同規則或回訪痕跡，它也不能當核心物件。

### 4.3 人物

人物包含玩家與 NPC。人物不是對話框，而是會佔用世界狀態的實體。

人物最低狀態：

- 位置。
- 身上錢。
- 所持物或空手。
- 當前目的。
- 下一個去處或時間義務。
- 對玩家的最小認知：陌生、見過、交易過、欠過、衝突過、合作過。
- 可被玩家觀察到的表面行為。

NPC 可以不理玩家。這不是缺內容；只要他不理玩家是因為他正在趕路、守物、避險、交易、休息、工作或等待，就比隨機台詞更像人。

NPC 若只是商店、任務入口、問答端點或台詞輪播，不能作為奇點 NPC 設計成果。

### 4.4 痕跡

痕跡是世界持續運轉的玩家可讀證據。

痕跡類型：

- 物件痕跡：少了、滿了、壞了、修好了、移位了、被佔用了。
- 人物痕跡：剛走、正在等、已成交、留下物、欠款、受傷、被認出。
- 路況痕跡：泥濘、封路、擁擠、危險、可通行、有人守。
- 經濟痕跡：缺貨、漲價、收滿、有人先交、有人壓價。
- 社會痕跡：告示、傳聞、稱呼改變、拒絕或協助。

痕跡讓玩家相信世界在場外有推進，但它不是系統通知，也不是 debug 摘要。

## 5. 玩家核心回圈

### 5.1 一分鐘回圈

1. 讀場景狀態。
2. 點一個人、物、出口或自己。
3. 看可用動作。
4. 選擇行動。
5. 立刻看到文字結果與狀態變化。

一分鐘回圈要回答：我剛剛做了什麼，世界哪裡變了。

### 5.2 十分鐘回圈

1. 選一條短期目的：賺一筆、過一段路、查一個人、修一件物、避一個風險。
2. 在 2 到 4 個場景間移動或等待。
3. 遇到至少一個 NPC 先於玩家或干擾玩家。
4. 得到錢、物、線索、關係、熟練、通行、風險解除或新的危險。

十分鐘回圈要回答：我這段時間做了一件對角色有意義的事。

### 5.3 一次登入回圈

1. 登入看到上次離線後的痕跡。
2. 決定今天要走哪條路：工作、交易、探索、修補、人際、危險處理。
3. 做 1 到 3 個小目標。
4. 設定離線前的簡單安排，例如等人、看守、委託、搬運、交易、休息、跟隨。
5. 下次登入時看到安排的結果或失敗。

一次登入要回答：我今天讓角色的位置、資產、關係或世界痕跡往某個方向推進。

### 5.4 長期回圈

玩家長期追逐不是單一等級，而是多條位置：

- 在某地被認得。
- 有可用工具與熟練。
- 有穩定賺錢方式。
- 掌握路線與危險。
- 有交易對象或信用。
- 佔用、維護或改善某個物件/場所。
- 參與某個組織、門派、氏族、城鎮或臨時人群。
- 有自己造成的歷史痕跡。

## 6. 玩家行為動詞

第一版應優先設計這些動詞，而不是先堆地圖或材料。

| 動詞 | 玩家意思 | 狀態結果 |
|---|---|---|
| 看 | 取得更多狀態與可用動作 | 揭露身份、風險、物件狀態 |
| 走 | 改變所在場景 | 位置、時間、路況痕跡 |
| 等 | 讓時間推進，等 NPC/天氣/隊列變化 | 時間、NPC 位置、事件痕跡 |
| 拿 | 取得可持有物 | 背包、來源庫存、目擊/歸屬風險 |
| 放 | 改變場景物件 | 地上物、權限、失物或誘因 |
| 用 | 以工具或物件改變狀態 | 工具耐久/熟練、物件狀態 |
| 修 | 改善損壞物件 | 材料消耗、場所可用性、名聲 |
| 買 | 用錢換物或服務 | 鎂、物品、交易關係 |
| 賣 | 用物換錢或信用 | 鎂、物品、需求狀態 |
| 問 | 從 NPC 取得資訊或態度 | 關係、線索、身份揭露 |
| 跟 | 讓人物路線成為玩家線索 | 位置、時間、被發現風險 |
| 避 | 避開危險或衝突 | 風險降低、時間成本、錯過機會 |
| 幫 | 替 NPC 或場所解決局部問題 | 關係、名聲、報酬、後續委託 |
| 擋 | 阻止人、貨、路、事件 | 衝突、關係、風險、戰鬥可能 |
| 戰 | 進入自動戰鬥結算 | 傷勢、物品、關係、事件痕跡 |
| 委託 | 把事交給 NPC 或離線角色安排 | 錢、時間、成功/失敗痕跡 |
| 掛牌/佔用 | 把場所或物件變成自己的短期據點 | 權限、租用、責任、他人反應 |

## 7. 角色設計

### 7.1 玩家角色狀態

玩家畫面需要讓玩家能查到：

- 姓名。
- 所在地。
- 鎂。
- 背包/所持物。
- 手上工具。
- 裝備/工具槽。
- 傷勢或明顯狀態。
- 已知人物。
- 近期事件。
- 已揭露路線。
- 離線安排。

不做通用生活條：不得把抽象需求條自動套入核心 UI。需要身體或精神狀態時，應以世界事件和具體狀態呈現，例如受傷、濕冷、疲乏、醉、被雨困住，而不是把遊戲退化成數值照顧表。

### 7.2 角色成長

角色成長來自：

- 工具熟練。
- 被人認得。
- 擁有或使用更好的工具。
- 掌握路線、行情、人物與危險。
- 能承接更複雜的委託。
- 能維護或佔用更重要的場所。
- 能在衝突中承擔更高風險。

不以職業鎖住玩家。職業若出現，只是社會認知或當前工作身份，不是限制玩家行動的永久類別。

## 8. NPC 設計

### 8.1 NPC 不是服務節點

NPC 不應先被設計成商人、任務人、對話人。先設計成世界居民：

- 正在工作。
- 正在搬運。
- 正在等人。
- 正在避險。
- 正在休息。
- 正在找東西。
- 正在交易。
- 正在回家。
- 正在守一個物件或路口。
- 正在跟另一個人產生關係。

商人只是居民的一種工作狀態。

### 8.2 NPC 的最低運作

每個進入玩家可觀測層的 NPC，至少要能回答：

- 他在哪。
- 他帶著什麼。
- 他想做什麼。
- 他接下來可能去哪。
- 他會不會跟玩家搶同一個機會。
- 玩家做了什麼會讓他改變行為。
- 玩家下次遇到他，他是否記得一件具體事。

### 8.3 NPC 行為不是輪播台詞

NPC 台詞只有在以下情況才有價值：

- 透露世界狀態。
- 表達他自己的目的。
- 回應玩家行動。
- 反映關係或記憶。
- 指向可行動作或風險。
- 留下可被後續引用的事件。

純粹「他說一句路人話」不算生活感。

## 9. 物件設計

### 9.1 物件等級

| 等級 | 說明 | 可否進第一屏核心 |
|---|---|---|
| 背景物 | 只提供地點辨識 | 否 |
| 觀察物 | 可看出狀態或線索 | 可少量 |
| 行動物 | 可被玩家操作並改變狀態 | 是 |
| 競合物 | NPC 也會使用、爭奪或改變 | 是，優先 |
| 長期物 | 可維護、佔用、修補、投資、留下回訪差異 | 是，核心 |

第一屏應優先放行動物、競合物、長期物，而不是堆觀察物。

### 9.2 物件設計模板

每個核心物件都要填：

```text
物件名：
玩家第一眼看到：
目前狀態：
誰也會使用它：
玩家可做：
需要條件：
成功結果：
失敗結果：
下次重訪可能看到：
它支撐哪條玩法路徑：
```

若填不出，物件不得進核心畫面。

## 10. 經濟設計

### 10.1 經濟不是收貨板

真實經濟的玩家感來自：

- 有人需要。
- 有人供給。
- 有人先一步行動。
- 價格或報酬有原因。
- 物流有成本。
- 缺貨/過剩會改變行為。
- 信用與關係會影響交易。
- 玩家可以選擇當供給者、搬運者、買家、修補者、轉賣者、委託者或競爭者。

### 10.2 玩家經濟路徑

| 路徑 | 玩家做什麼 | 長期吸引力 |
|---|---|---|
| 短工 | 用身體和工具換錢 | 快速理解世界需求與人際位置 |
| 採集者 | 從來源取得物資 | 熟悉地形、時間、天氣與風險 |
| 搬運者 | 把物資或訊息從 A 帶到 B | 掌握路線、隊列、路況、信用 |
| 修補者 | 用工具與材料改善物件 | 累積熟練、名聲、可回訪成果 |
| 交易者 | 利用缺貨、價格與人脈 | 形成自己的經濟位置 |
| 委託者 | 用錢和關係讓 NPC 做事 | 讓離線/等待也有策略 |
| 場所經營者 | 佔用、維護、掛牌、放置物件 | 形成局部根據地與社會位置 |

### 10.3 物資設計原則

物資不因現實用途多就有遊戲價值。物資只有接到以下至少一項才進遊戲核心：

- 工具使用。
- 交易需求。
- 建造/修補。
- 風險處理。
- NPC 競合。
- 路線/物流。
- 角色熟練。
- 社會關係。

否則它只是百科條目。

## 11. 工具與熟練設計

### 11.1 工具是動詞來源

工具不是裝備分數。工具讓玩家能做某些事，或把同一件事做得不同。

工具應影響：

- 可用動作。
- 成功/失敗原因。
- 消耗時間。
- 風險。
- NPC 評價。
- 報酬。
- 可修補/可建造物件。

### 11.2 熟練不是等級條

熟練應表現在：

- 玩家能看出更多細節。
- 操作失敗較少。
- 可接更難的活。
- NPC 對玩家稱呼或態度改變。
- 某些物件開放第二層動作。
- 同樣工具在玩家手上有更好結果。

## 12. 探索與冒險設計

### 12.1 探索是資訊優勢

探索的獎勵不是「又看到一個地名」，而是玩家掌握：

- 這條路何時安全。
- 哪個人常經過。
- 哪裡缺貨。
- 哪裡有人守。
- 哪個物件可修或可偷。
- 哪個天氣會造成機會或危險。
- 哪個傳聞能引向一件事。

### 12.2 冒險是承擔不確定性

冒險應包含：

- 前兆：玩家能讀出風險。
- 準備：玩家能帶工具、找人、等時間、繞路。
- 抉擇：走近、避開、求援、跟隨、觀察、攻擊。
- 代價：時間、錢、物、傷勢、關係、錯過。
- 痕跡：回來後世界留下結果。

不確定路不能只是另一個出口。

## 13. 戰鬥與衝突設計

### 13.1 戰鬥定位

戰鬥不是主要操作技巧，而是衝突升級的結算方式。

衝突來源：

- 搶同一個物件。
- 阻擋路線。
- 守護人物或場所。
- 資源競爭。
- 交易失信。
- 組織或地區事件。
- 野外危險。

### 13.2 玩家戰鬥選擇

戰鬥前玩家應能選擇：

- 不靠近。
- 觀察。
- 求援。
- 繞路。
- 交涉。
- 制止。
- 留人/制服。
- 攻擊。

進入戰鬥後，結算依後端規則自動產生文字 log。玩家的準備、工具、技能、狀態與關係影響結果，不靠反應速度。

## 14. 經營與建造設計

### 14.1 經營是持續責任

經營不是玩家交一次物品。它是讓某個人、物、地點、交易、路線持續運作。

經營行為：

- 掛牌。
- 委託。
- 補料。
- 維修。
- 佔用。
- 租借。
- 守護。
- 分配工具。
- 記帳。
- 跟 NPC 建立穩定交易。

### 14.2 建造是世界狀態改變

建造不一定一開始就是造房子。第一版可以是小型改變：

- 修好一段踏板。
- 補一盞燈。
- 放一個箱。
- 掛一張牌。
- 清掉障礙。
- 加固一個門。
- 整理一個可用角落。

重點是：其他人下次能看到或使用這個改變。

## 15. 社會與角色扮演設計

### 15.1 角色扮演來自位置

角色扮演不是讓玩家填設定，而是世界如何回應玩家。

玩家可能逐步變成：

- 陌生過路人。
- 常來的人。
- 可托付短工。
- 某人認得的幫手。
- 被懷疑的人。
- 有信用的搬運者。
- 某場所的維護者。
- 某條路的熟人。
- 某組織的外圍人。

這些身份必須由事件、關係、物件與名聲形成，不是創角時選職業。

### 15.2 社會系統的玩家可見面

低/中/高/巨型社會系統不應先做成大設定。第一版先落成玩家可見差異：

- 某些人互相認得。
- 某些地方有規矩。
- 某些物件有歸屬。
- 某些報價因關係改變。
- 某些路線有人看守。
- 某些事件會被傳開。
- 某些幫助會形成信用。

## 16. UI 與第一屏設計

### 16.1 畫面分工

第一屏需要分清三種資訊：

- 全局上下文：時間、天氣、必要的世界節奏，應獨立於場景正文，不混成場景散文。
- 當前場景：玩家所在局部的狀態、人物、物件、出口、痕跡。
- 自身入口：玩家姓名、角色面板、錢、背包、工具、狀態；玩家本人不是 L4 場景人物卡。

### 16.2 第一屏最低內容

任何出生/重登畫面至少要有：

- 自身入口：姓名可點，能看錢、背包、工具、所在地、近期事件。
- 場景狀態：一段可判斷局勢的文字，不是純氛圍。
- 最多 6 個核心入口：出口、人物、物件混排，但不要淹沒玩家。
- 至少 1 個 NPC 同規則行動者。
- 至少 1 個工具/熟練入口。
- 至少 1 個經濟入口。
- 至少 1 個探索或不確定路線。
- 至少 1 個風險、衝突或避開判斷。
- 至少 1 個可維護/可改善/可佔用物件。

### 16.3 第一屏不該有

- 玩家本人作為路上可見人物卡。
- 精確人群數字。
- 底部方向欄。
- debug、資料庫、起點、尚未接入等字樣。
- 一排只有名詞、沒有行為後果的物件。

## 17. 第一階段可玩切片設計標準

第一階段必須證明大地圖就是可玩的主要表面；驗收可以先集中在同一張大地圖
的一個可重訪、可狀態變化局部，但不能另切成房間清單或文字主畫面。

目前第一個具名內容包見 [world/world-content-bible-v1.md](world/world-content-bible-v1.md)。後續 runtime 或資料化前，必須先從該檔拆出場景卡、NPC 卡、物件卡、事件卡與玩家表層回饋，不得只引用本章的數量表。

一個合格切片必須包含：

| 項目 | 最低量 | 要求 |
|---|---:|---|
| 場景 | 3 到 5 個 | 每個場景至少 2 個可用入口 |
| NPC | 3 到 6 名 | 至少 2 名會在玩家不操作時推進 |
| 核心物件 | 8 到 12 個 | 至少 5 個可改變狀態 |
| 工具 | 2 到 3 類 | 至少 1 類有熟練回饋 |
| 經濟流 | 1 條以上 | 供給、需求、NPC 參與、成交/缺貨 |
| 探索路 | 1 條安全、1 條不確定 | 不確定路有前兆與代價 |
| 衝突 | 1 種以上 | 可避開、求援或承擔 |
| 建設/維護 | 1 個物件 | 投入後可重訪看到改變 |
| 離線安排 | 1 種 | 下次登入看到結果或失敗 |

## 18. 起手路徑設計

第一版至少要讓玩家在同一個出生局部看見五條起手路徑。

### 18.1 賺錢路

玩家看到：有人需要某件事被完成，且報酬或交換條件可理解。
玩家做：搬、賣、修、送、幫、等、談價。
狀態變：鎂、物品、NPC 目的、需求、名聲。
回訪理由：需求可能被別人先完成，或因時間/關係改變。

### 18.2 工具路

玩家看到：一件工具或可借用工具能打開某些動作。
玩家做：拿、借、買、修、使用、練手。
狀態變：工具持有、熟練、成功率、NPC 評價。
回訪理由：工具讓玩家能接更好的事或處理風險。

### 18.3 人際路

玩家看到：某個人不是服務員，而是有自己的目的。
玩家做：看、問、幫、跟、避、交易、承諾。
狀態變：關係、記憶、稱呼、報價、協助。
回訪理由：人會記得玩家，並提供或阻擋未來機會。

### 18.4 探索路

玩家看到：一條不確定路或一個未明狀態。
玩家做：觀察、問路、準備工具、等待時機、走近或避開。
狀態變：已知路線、風險、位置、線索、時間。
回訪理由：新資訊讓玩家之後做更好的選擇。

### 18.5 維護/建設路

玩家看到：一個地方或物件可被改善。
玩家做：修、補、放、掛、佔、委託。
狀態變：物件狀態、場所功能、NPC 使用、玩家名聲。
回訪理由：玩家能看到自己的投入留在世界裡。

## 20. 內容驗收規則

任何設計稿、場景卡、物件表、NPC 設定，必須逐項回答：

1. 玩家看到什麼。
2. 玩家能點什麼。
3. 點了有什麼選擇。
4. 成功改變什麼。
5. 失敗或錯過改變什麼。
6. NPC 是否也能介入。
7. 世界時間、歷史、沿革、上一秒/上一 tick/上一動作是否會改變它。
8. 下次登入或重訪是否看得出差異。
9. 它對應哪個關鍵字。
10. 刪掉它會不會影響玩家決策。

第 10 題若答案是「不會」，該內容不是核心玩法。

第 9 題必須明確指回 `DESIGN_KEYWORDS.md` 的原始關鍵字簇。不得只寫「沉浸」「活世界」「模擬」這類助手摘要詞；具名內容包必須像 `world-content-bible-v1.md` 一樣列出關鍵字追溯表，讓每個場景、NPC、物件、事件、路線與玩家腳本都能被反查。

## 21. 明確禁止

- 用地圖數量冒充開放世界。
