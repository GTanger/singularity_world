# M3-031 第一屏玩法骨架審查

狀態：設計審查稿，未進 runtime
日期：2026-06-16
範圍：只審查登入後第一屏與北岸渡口既有局部，不新增地圖、不新增 runtime、不用新名詞包裝玩法。

## 審查結論

目前北岸第一屏不是「手機文字 MUD 的第一個世界切片」，而是「局部可操作的渡口工作站」。它已經有可點物件、金錢變化、背包材料、排船狀態、跨物件回聲與一個同規則 NPC 搬貨人，但玩家主要能做的事仍集中在採集、交料、搬貨、排隊與過河。

這些內容能證明程式可以承載狀態，不能證明遊戲已經好玩。依照 `docs/DESIGN_KEYWORDS.md`，第一屏至少要同時露出：自身錨點、全物件互動、永遠在線的 NPC/世界後果、玩家等於 NPC、探索/冒險、真實經濟、經營/模擬/建造/戰鬥的延伸鉤子。現在只落到其中一小段。

因此 M3-030 命名修復只能作為清理項，不能當下一個玩法目標。下一個 runtime 前必須先用本審查決定第一屏最低可玩面。

- 玩家可透過採集得到 `蘆草束`、`麻袋布`、`麻繩卷`，並把它們交給需求板換鎂。

- `QueueFerry`、`BoardFerry`、`StepAshore` 會寫入隊列、上船、上岸狀態。
- `Rest`、`BuySoup`、`QueueBroth`、`DryOff`、`WarmHands` 只留下身體/場景回聲，沒有角色能力或風險層。

## 明確砍掉的方向

以下不是奇點第一屏的玩法主軸：

- 跑腿賺鎂：可以保留為世界行為之一，但不能是第一屏主要答案。
- 單一收貨牌：可以作交易物件，不能作出生點核心。
- 純場景文字：不導向選擇、不改變狀態的漂亮句不得佔第一屏核心。
- NPC 背景表演：NPC 必須持有狀態、資產、目的和後果；公共人群/微動作只能當呈現層。
- 地圖數量：119 個可站入目標不得再被當作「世界已完成」。
- 材料百科：材料只有接到工具、建造、交易、風險、關係或經濟位置時才有用。
- 任務板式需求：玩家看見一張需求板然後補料，不足以代表真實經濟。

## 第一屏最低可玩面

下一步 runtime 必須讓登入後第一屏同時成立以下七面。每一面都要回答：玩家看到什麼、點什麼、狀態怎麼變。

### 1. 玩家自身

玩家看到：

- 姓名、位置、鎂。
- 背包或空手狀態。
- 手上工具/無工具。
- 一條身份或關係線索，例如陌生過路人、候渡者、臨時搬工、被某人認住的位置。

玩家可點：

- 自己姓名或角色面板。

狀態變化：

- 至少能看見鎂、背包、工具、所在位置與最近一次被世界承認的行動。

### 2. 全物件互動

玩家看到：

- 第一屏核心物件不超過 6 個，但每個都不是純名詞。
- 每個核心物件至少有一個動詞，且至少三個物件有第二層結果。

玩家可點：

- 看、拿/採、用、交付、排隊、交易、修補/改造、避開/靠近。

狀態變化：

- 錢、背包、位置、通行、工具、關係、風險、場景狀態至少改一項。

### 3. NPC 同規則

玩家看到：

- 至少兩個不是背景的 NPC/公共身份：一個和玩家競合資源，一個和玩家共享通行/風險。

玩家可點：

- 觀察、交易/詢價、跟隨/避開、阻擋/讓位、交付或求援。

狀態變化：

- NPC 的位置、持物、鎂、目的或下一步會因時間或玩家行動改變。

### 4. 探索/冒險入口

玩家看到：

- 一條安全路和一條不確定路；不確定路必須有可讀風險，不只是另一個出口。

玩家可點：

- 走、觀察路況、詢問/偷聽線索、準備工具、避開風險。

狀態變化：

- 位置、路況知識、通行權、風險標記或消耗資源改變。

### 5. 經營/建造鉤子

玩家看到：

- 一個可被改善或維護的物件，不是一次性交料板。

玩家可點：

- 修補、補料、佔位、掛牌、委託、放置、維護其中之一。

狀態變化：

- 該物件的狀態可跨場景回聲；其他 NPC 或玩家後續會讀到它。

### 6. 戰鬥/衝突鉤子

玩家看到：

- 第一屏附近有衝突或危險的可見線索，例如推擠、搶位、獸/人阻路、護送風險、外路危險。

玩家可點：

- 避開、靠近、求援、留人、攻擊/制止其中至少一種。若不開放戰鬥按鈕，也必須有避戰判斷。

狀態變化：

- 風險、關係、位置、血量/傷勢、通行或事件痕跡改變。

### 7. 永遠在線與觀測

玩家看到：

- 同一地點重訪時，不是換一句氛圍，而是因世界時間、NPC 交付、資源、隊列、天氣或玩家舊行為而不同。

玩家可點：

- 觀察痕跡、追人、查看物件、沿線索移動。

狀態變化：

- 觀測會承認一條當下事實；接觸會留下可回查痕跡。第一版可先做局部，不宣稱完整坍縮系統。

## 下一步 runtime 閘門

進 runtime 前，必須先選定一個第一屏骨架，不得邊寫邊漂：

- 第一屏核心物件最多 6 個，避免把所有已做物件都堆上去。
- 至少 1 個自身錨點。
- 至少 1 個 NPC 競合者。
- 至少 1 個通行/探索入口。
- 至少 1 個工具或熟練入口。
- 至少 1 個經營/建造入口。
- 至少 1 個風險/戰鬥/避戰入口。
- 至少 3 個操作會改變後端狀態，且重看物件時能讀到變化。

若某項只能寫成場景描述，不能落成狀態、動作或回聲，就不放進第一屏核心。
