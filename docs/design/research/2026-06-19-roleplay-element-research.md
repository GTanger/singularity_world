# 角色扮演與元素系統研究摘記

日期：2026-06-19
用途：校準奇點世界的「角色扮演 × 元素」設計，不作為 `docs/DESIGN_KEYWORDS.md` 的上位來源。

## 研究問題

使用者修正：元素設計不能再滑成自然物理現象。這次查證的問題是：

```text
在角色扮演遊戲中，元素如何變成玩家角色、選擇、戰鬥、探索與世界互動的一部分？
```

本摘記不回答元素自然成因，不整理百科式元素表。

## 外部參照

### Dungeons & Dragons：角色扮演的基本迴圈

D&D 2024 Basic Rules 將遊玩節奏拆成三步：描述場景、玩家描述角色要做什麼、DM 敘述行動結果；社交、探索、戰鬥都用這個節奏運作。

奇點轉譯：

- 元素必須進入「場景可讀 -> 玩家選擇 -> 世界結果」迴圈。
- 元素不是先問「它怎麼自然形成」，而是先問「玩家看見後，這個角色能做什麼」。
- 元素若不造成下一個 decision point，就只是描述詞。

來源：
https://www.dndbeyond.com/sources/dnd/br-2024/playing-the-game

### Dungeons & Dragons：傷害類型本身不是玩法

D&D 2024 Rules Glossary 說明：damage type 本身沒有規則；其他規則會讀取這些 type，例如 resistance。

奇點轉譯：

- `火 / 水 / 風 / 土 / 雷 / 毒 / 冰` 這些標籤本身不是遊戲設計。
- 標籤只有被物件、工具、NPC、戰鬥、交易、路線、關係或回訪規則讀取時，才成為玩法。
- 因此元素檔必須寫「誰讀取它、讀取後發生什麼」，不能只列元素名與效果名。

來源：
https://www.dndbeyond.com/sources/dnd/br-2024/rules-glossary

### Pokemon：元素作為角色/隊伍/招式身份

Pokemon 官方對戰指南將 type 放在寶可夢本身、招式、隊伍組合與對手相性上；玩家的決策是派誰、用哪招、是否換人、隊伍是否覆蓋足夠類型。

奇點轉譯：

- 元素可以成為角色定位的一部分，但不必是職業或天生屬性。
- 在奇點裡，角色的元素關係應由持物、工具、熟練、已知規則、地方信用與反覆行動累積。
- 玩家不需要一開始選「火系角色」，但世界可以逐漸承認他是會處理火源、懂避雷、常修水路、善用土石工具的人。

來源：
https://diamondpearl.pokemon.com/en-us/trainersguide/fundamentals/battling/

### Nintendo / Hyrule Warriors：元素作為環境與工具互動

Nintendo 的《Hyrule Warriors: Age of Calamity》初學指南把 fire/ice/lightning rod 寫成玩家可選工具，並提醒玩家觀察草地、水、金屬等環境條件來使用元素。

奇點轉譯：

- 元素可以透過工具被玩家操作，而不是只存在於戰鬥傷害。
- 場景環境、物件材料、工具、NPC 位置與玩家選擇必須接在一起。
- 元素的價值來自「何時用、在哪用、用在誰/什麼上、用後世界怎麼改變」。

來源：
https://www.nintendo.com/au/news-and-articles/a-beginners-guide-to-hyrule-warriors-age-of-calamity/

## 對奇點的結論

角色扮演中的元素不是自然現象，也不是傷害顏色。元素是玩家角色與世界規則接上的介面。

合格元素設計要回答：

1. 角色如何知道這條元素規則存在。
2. 角色的持物、工具、熟練、關係或位置如何改變可用動作。
3. 玩家能做什麼選擇，而不是只能讀到一段描述。
4. NPC 是否也照同規則利用、避開、阻止或搶先。
5. 行動後錢、物、路、人、場所、關係、風險或痕跡是否改變。
6. 重複第二次時，玩家是否因工具、熟練、資訊、關係或世界狀態不同而有不同決策。

禁止轉譯：

- 不把元素與玩家關係寫成身體感覺或物理科普。
- 不把元素表當成內容量。
- 不把元素放進玩家面板做抽象需求條。
- 不把元素只做成戰鬥傷害類型。
- 不把元素描述當成空場景的氣氛補丁。
