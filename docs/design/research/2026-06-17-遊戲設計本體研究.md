# 2026-06-17 遊戲設計本體研究

狀態：外部研究筆記，用來補足 GDD 的遊戲設計基本功
第一權威：`docs/DESIGN_KEYWORDS.md`
修正原因：前一份外部參照偏向奇點局部系統校準，沒有完整回答「遊戲設計」本體問題。

## 研究問題

本輪研究不是查題材、材料、世界觀或 UI 文案，而是查遊戲設計本身：

- 玩家為何覺得一個行動有意義。
- 機制如何產生動態，再產生玩家感受。
- 核心循環如何服務玩家目標，而不是變成空口號。
- 什麼樣的選擇才算值得玩。
- MUD/持續世界要支撐哪些玩家動機。
- 文件如何從設計理論落到可驗收條件。

## 來源摘要

| 來源 | 核心觀點 | 奇點設計轉譯 |
|---|---|---|
| Hunicke, LeBlanc, Zubek, `MDA` | 遊戲可拆成 mechanics、dynamics、aesthetics；設計者操作機制，玩家感受結果 | GDD 每個系統不能只寫機制，必須寫會產生什麼玩家動態與玩家感受 |
| Salen & Zimmerman, `Rules of Play` | meaningful play 來自行動與系統結果的關係；結果要可辨識並整合進整體系統 | 奇點每個點擊都要有可見結果，且該結果要接回錢、物、路、人、時間、風險或長期痕跡 |
| Daniel Cook, `Loops and Arcs` | loop 可描述反覆行動結構，arc 可描述一次性進展與長程變化 | 一分鐘、十分鐘、登入、長期回圈要各自有目的；不能把「循環」當完成證明 |
| Celia Wagar, `Game Loops are an Illusion` | loop 概念若不能幫助判斷好壞或修改設計，就只是描述現象 | 奇點文件不能只說有核心回圈；要寫出玩家卡在哪、哪一步能改、什麼會變好玩 |
| Sid Meier 相關設計討論 | 好選擇通常不是明顯最優、也不是完全等價；玩家需要足夠資訊做取捨 | 第一切片的五條起手路徑要互有代價：錢、時間、關係、風險、錯過、工具門檻 |
| Raph Koster, `A Theory of Fun` | 樂趣與辨識、學習、掌握模式有關；純噪音與已解完的重複都會讓人流失 | 奇點要讓玩家逐步學會世界規則；不能只給隨機事件，也不能讓第一屏變成固定收料 |
| Richard Bartle, `Players Who Suit MUDs` | MUD 玩家動機可從 action/interacting 與 world/players 軸拆出多種類型 | 奇點不能只服務賺錢者；要同時有成就、探索、人際、競合/衝突的入口 |
| Fullerton, `Game Design Workshop` | playcentric design 重視經驗目標、原型、測試、修正 | 文件不能代替遊玩；設計拍板後必須做小切片並用玩家畫面驗收 |

## 奇點 GDD 必須補上的遊戲設計層

### 1. 有意義行動

每個玩家行動都要過兩道檢查：

- 可辨識：玩家立刻看得出發生什麼。
- 可整合：這件事會影響後續世界，而不是只顯示一句結果。

不合格：

- 點物件只得到氛圍描述。
- 交易只改錢，沒有供需、關係、庫存或價格後續。
- 探索只換地名，沒有路況、風險、線索或已知資訊。

合格：

- 玩家讓路後，隊列位置改變，某人記得，下一次報價或稱呼不同。
- 玩家修補物件後，NPC 使用效率改變，場景回訪文字不同。
- 玩家選風險路後，省時間但可能受傷、丟物、遇人或留下傳聞。

### 2. MDA 映射

每個 GDD 系統都要用三層寫清楚：

```text
機制：玩家/NPC/物件實際規則是什麼。
動態：這些規則在運行時會產生什麼局勢。
玩家感受：玩家會因此感到什麼可玩張力。
```

例：

```text
機制：路線有安全路與風險路；NPC 也會選路；天氣改變路況。
動態：玩家可以搶時間、避風險、等人同行、打探路況。
玩家感受：不是「走路」，而是在做有代價的去處選擇。
```

### 3. 核心循環不是口號

一個回圈必須回答：

- 玩家為什麼開始。
- 玩家每一步做什麼。
- 系統如何回應。
- 玩家如何學到新資訊。
- 玩家如何得到下一步目標。
- 重複第二次時為何不是同一件事。

若只能寫成「看場景 -> 點物件 -> 得結果」，仍然不夠。那只是互動流程，不是遊戲循環。

### 4. 選擇必須有取捨

第一切片的選擇不得只有正確答案。每條路都要有代價：

| 選擇類型 | 必須有的取捨 |
|---|---|
| 賺錢 | 快錢 vs 信用、時間、風險、別人先拿 |
| 工具 | 花錢/借用/修理 vs 打開新動作 |
| 人際 | 幫忙/拒絕/插手 vs 關係與後續稱呼 |
| 探索 | 安全慢路 vs 不確定快路 |
| 維護 | 眼前報酬少 vs 場所長期變好 |
| 衝突 | 承擔、避開、求援、談判各有成本 |

### 5. 玩家動機要覆蓋 MUD 基礎

奇點至少要支撐四種入口，不是分類玩家，而是檢查玩法是否偏食：

| 動機 | 奇點入口 |
|---|---|
| 成就 | 錢、工具熟練、信用、路線熟悉、場所改善 |
| 探索 | 路況、未知人物、價格差、危險前兆、區域知識 |
| 人際 | 稱呼、記憶、幫忙、拒絕、同行、交易信任 |
| 競合/衝突 | 搶先、阻擋、避險、談判、戰鬥、報復或和解 |

只有賺錢與收料，不足以支撐 MUD。

### 6. 樂趣來自學會世界，而不是看世界表演

奇點應讓玩家逐步形成可用的世界理解：

- 什麼天氣適合走哪條路。
- 哪些人可信。
- 哪些物件值得修。
- 哪些商品會缺。
- 哪些行為會被記住。
- 哪些風險可以準備或轉嫁。

玩家每次回來如果只看到新文案，沒有更懂世界，遊戲設計失敗。

## 反證與限制

- MDA 不是萬能模板；它只提醒「機制到感受」不能斷裂。
- 核心循環不是遊戲好玩的證明；很多爛設計也能畫成循環。
- Bartle 類型不是人格測驗；在奇點只用來避免玩法只剩單一路徑。
- 「有趣選擇」不能只靠隱藏資訊；玩家需要足夠線索，不然只是猜。
- 學習模式不等於教學文字；最好由結果、失敗、回訪痕跡讓玩家學會。
- 文件不是驗收終點；遊戲設計最後必須回到玩家畫面與實玩節奏。

## 對既有 GDD 的修正要求

1. `01-player-and-loops.md` 要把「回圈」改成可驗證的動機、行動、回饋、再目標。
2. `13-content-authoring-validation.md` 要加入 meaningful play、MDA、取捨、學習曲線、MUD 動機覆蓋檢查。
3. `14-first-playable-slice.md` 要要求第一切片同時證明：有意義行動、取捨、玩家可學、動態局勢、四類 MUD 動機入口。
4. 任何「物資」「地圖」「NPC」「場景」文件，都不能繞過「玩家玩什麼」這一層。
