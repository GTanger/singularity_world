# 奇點世界設計考古：縮放、觀看、接觸與觸發（第二輪）

日期：2026-07-16  
性質：使用者原意與版本演變考古；不是新互動規格，也不使舊設定自動復活  
前一輪：[奇點世界設計考古索引（第一輪）](2026-07-15-singularity-design-archaeology.md)

## 一、這輪要回答什麼

第一輪留下的題目原本寫成「遠看、近看、可走、可摸、可介入之間怎麼分層」。
這句本身已經犯了兩個錯：

1. 使用者明確校正過：探索的核心是**接觸**，不是帶著目的去**介入**。
2. 它預設所有概念都屬於同一條線性流程，但舊資料並沒有證明這件事。

因此這輪只查三件事：

- 地圖縮放、拖曳觀看與角色移動，原本是否有不同權限；
- 看見物件、靠近物件與取得動作，原本是否有距離分層；
- 「接觸後看看有沒有觸發」能保留到哪裡，才不會又被 AI 擴寫成搜查鍵、
  掉寶表或固定選單。

## 二、結論先行

現有證據**不支持一套已定案的線性狀態機**，例如：

`遠看 → 近看 → 可走 → 可摸 → 可介入`

最能承受反證的重建，是兩條彼此相關但不同的軸：

| 軸線 | 已有使用者證據 | 尚未重新決定 |
|---|---|---|
| 地圖／相機權限 | 可拖曳看遠方；舊設想曾限制只有目前載入區可下位移命令，縮小看世界時點擊只查看資訊 | 現行載入區邊界、縮放到哪一級仍可下移動命令、遠距點擊回傳什麼 |
| 物件／接觸權限 | 舊設想曾分為「看得到可觀察」與「靠近後才有進一步動作」；現行原話把探索核心鎖為接觸、摸一下、看看有沒有觸發 | 接觸距離、手勢、提示方式、是否先顯示動作、哪些接觸會有結果 |

兩軸會相交，但不能互相冒充：**鏡頭拉近不等於角色靠近，畫面上點得到也
不等於物理上接觸到了。**

## 三、直接證據

### 3.1 現行原話：接觸不是介入

2026-07-14，使用者直接校正：

> 不是介入，是接觸，探索型就是會讓玩家遇到任何物件都會想要「摸」一下，
> 看看有沒有任何「觸發」

緊接著，當助手把這句擴寫成完整玩法時，使用者又提醒「這是遊戲設計層，
先退回討論畫面風格」。所以這句可確認的是**探索意圖與用語**，不是完整 UI
或機制已拍板。

這裡至少能保留三個邊界：

- `接觸` 是未知導向：玩家還不知道物件會不會回應。
- `觸發` 是世界回應的可能性，不是每次接觸必有獎勵的承諾。
- `介入` 可能是某些行動造成的後果，但不是探索入口的總稱。

### 3.2 舊原話：縮放觀看與角色位移曾經分權

舊對話中，使用者說明：

- 角色只能在目前載入的地圖瓦片內接受點擊引導；
- 底圖縮小、看到更多世界資訊時，點擊只查看資訊，不能直接指定遙遠位移；
- 即使允許遠距直線位移，角色也會因房屋、山、樹、石、河流等物理障礙停下；
- 手動引導的目的，是讓旅途不退化成傳統 MUD 的重複方向指令與無意義填充。

這證明當初有一個清楚觀念：**看得到的地圖範圍，不必等於可直接下達位移命令
的範圍。**但「目前載入瓦片」屬於當時的技術想像，不能直接當成現行架構。

### 3.3 結構化回答：曾有「可觀測／可交互」兩層

舊 Q&A 中的使用者回答曾寫：

- 比例 1:1 時，出現在手機畫面內代表可觀測；點擊得到狀態、外觀等敘述；
- 角色靠近約一人寬後，點擊才產生進一步交互指令；
- 地圖至少支援按住拖曳，觀看遠方地圖；
- 戰鬥特例是雙方靠近接觸後，點擊對方取得按鈕，再選擇攻擊。

可保留的是「**觀看資訊與執行近身動作不是同一權限**」。不可直接復活的是
`1:1`、`一人寬`、所有物件共用戰鬥視窗等具體門檻，因為它們綁定舊尺度與舊
介面時期，且尚未在現行 2D 大地圖方向下重新確認。

## 四、最重要的拆分

| 詞 | 這輪能確認的意思 | 不能偷渡成 |
|---|---|---|
| 看見／在畫面中 | 玩家視覺上知道某物存在 | 一定可遠距操作、一定取得完整資料 |
| 觀看／觀察 | 讀取當下可被角色察覺的外觀或狀態 | NPC 故事必然坍縮、完整人格生成 |
| 移動命令 | 角色向玩家指定的位置作物理位移 | 相機拖到哪裡就能瞬移或自動尋路到哪裡 |
| 接觸 | 玩家因好奇而靠近、點選或嘗試碰觸某個有意義的實體 | 固定的搜查鍵、每件物品都有選單、已知目的的介入 |
| 觸發 | 後端世界依物件與當下狀態產生回應；也可能沒有可見結果 | 寶箱、任務、彩蛋或掉寶保證 |
| 動作／動詞 | 在條件成立後，後端判定可執行的 Talk、Take、Attack 等能力 | 玩家一看見目標就必須看到完整後端插座表 |
| 介入 | 某些接觸或動作實際改變正在發生的事 | 所有探索行為的總稱 |

其中「觸發也可能沒有可見結果」是從「看看有沒有」推得的保守重建，不是已
定義好的失敗回饋規格。

## 五、另一個同名陷阱：觀測有兩種

現有 wiki 的「觀測分級」處理的是後端模擬成本：無玩家時仍保存事實與節律，
同畫面、注視、對話時逐級增加可見細節與推理成本。它回答的是**NPC 要算多深**，
不是玩家點一棵樹時 UI 要怎麼操作。

因此後續必須區分：

1. **玩家感知／接觸**：玩家能看到什麼、點到什麼、靠近後能做什麼。
2. **後端觀測分級**：系統為了保持活世界，對場外與場內 NPC 算到什麼深度。

把兩者合併，會錯誤地讓一個 UI 點擊直接背負故事坍縮、人格生成與算力層級。

## 六、反證：過去怎麼被擴寫壞掉

舊對話裡，使用者只提出「每一格都值得停留，玩家願意為目標滿世界搜索」，
並用《金庸群俠傳》翻箱倒櫃形容那種探索感。助手立即擴寫成：

- 每格是容器；
- 長按／雙擊搜查；
- 每格有掉寶表；
- NPC 也搶寶、藏寶；
- 地毯式翻找成為循環。

使用者隨即糾正：「我只是在說個概念。」

這是本輪最強的反例。它證明「世界值得摸」不能被直接翻譯成「每個物件都配
一套搜查內容」。正確保留的是**玩家對世界細節有探索信任**；具體內容密度、
回應種類、動作入口與獎勵結構仍需另外設計。

## 七、插頭／插座放在哪裡才不會喧賓奪主

插頭／插座目前可保留為後端能力模型：目標有哪些可能動作、玩家或 NPC 發出
哪個動作、距離與狀態是否允許、最後由後端執行並回傳結果。

它沒有回答，也不應自行回答：

- 玩家在遠處是否先看到提示；
- 接觸前是否顯示可互動性；
- 點擊、長按或其他手勢怎麼分工；
- 接觸時先得到自然回應，還是直接彈出動詞；
- 無觸發時畫面如何讓玩家理解，而不誤以為操作失效。

所以：**插頭／插座是世界能做什麼，不是玩家如何發現世界能做什麼。**

## 八、目前可安全沿用與必須留白的部分

### 可安全沿用

- 主要畫面是可縮放的 2D 大地圖；圖像承載世界，文字承載細節。
- 鏡頭縮放不改變人形標記的螢幕大小，也不改變角色的世界物理尺度。
- 相機觀看與角色物理移動是不同權限。
- 探索入口的正確詞是**接觸**，不是**介入**。
- 玩家遇到有意義的物件時，應產生「想摸一下、看看有沒有觸發」的好奇。
- 物件狀態與可執行性由後端世界決定，不由前端無中生有。

### 必須留白

- 遠距點擊是否一律只觀察，以及「遠距」如何判斷；
- 角色多近才算接觸；
- 接觸與單擊走／雙擊跑如何避免手勢衝突；
- 是否、何時、以何種形式顯示動作；
- 沒有觸發、有微小觸發與產生正式動作時，各自怎麼表現；
- 觸發是否依時間、工具、人物與物件狀態改變。

最後一項很符合活世界方向，但目前主要來自助手延伸，不能冒充使用者定案。

## 十、本輪判決

**保留 H3，駁回完整 H1：**縮放／觀看／位移是一條權限軸；物件的觀察／接觸／
觸發是另一條權限軸。舊資料支持局部分層，但不支持一套已完成的線性狀態機。

因此下一次真正設計畫面時，應先處理一個很窄但關鍵的視覺問題：**地圖上的某個
東西，如何讓玩家覺得它值得接觸，卻不提前把「會觸發什麼」全說破。**這是後續
討論入口，不是本報告替使用者作出的答案。
