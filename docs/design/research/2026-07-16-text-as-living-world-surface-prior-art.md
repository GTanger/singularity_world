# 2026-07-16 文字作為活世界表面：外部先例與反證研究

狀態：完成兩輪有界研究（系統先例與實際 UI）；外部研究，不是奇點正典或實作授權

第一權威：`docs/DESIGN_KEYWORDS.md`

對接決定：`docs/design/gdd/22-return-to-text.md`

## 研究問題

本輪不是泛查「文字遊戲」或「活世界」，而是查有沒有成熟作品或研究完整做到：

1. 世界不是等玩家閱讀才成立，並能獨立持續或至少自行推進。
2. 玩家是世界裡的一名居民，不是全知管理者或故事外的導演。
3. 文字是主要的即時世界呈現，不只是對話框、任務文案或事後戰報。
4. GUI 負責接觸與行動，不要求玩家以傳統命令列猜動詞。
5. 文字來自玩家當下可感知的世界狀態，不靠預寫分支或模型臨場捏造事實。
6. 其他人物在同一世界規則內有自己的行動、記憶與關係。
7. 故事是生活、行動與交會留下的因果痕跡，不是事先塞給玩家的主線內容。

研究範圍包含公開產品頁、開源／公開原始碼專案、作者文件與學術論文。這是
有界搜尋結果，不是「網路上絕對不存在」的證明。

## 結論

**沒有找到一個已成熟、可玩的案例同時滿足七項。** 找到的是一條很清楚、但
分散在不同作品與研究中的技術及設計譜系：

- `Versu` 最接近「後端狀態 → 當下可用行動 → GUI → 動態文字」，但它仍是
  篇章式互動戲劇，有作者腳本與 drama manager，不是持續開放世界。
- `Usurper Reborn` 最接近「持續世界 + 自主人物 + 玩家也是居民」，但玩家
  表面仍是 BBS／終端機／選單系文字 RPG。
- `Talk of the Town` 最接近「世界事實、人物所知、目擊與傳聞彼此分開」，但
  玩家表面是等角地圖與對話，不是文字化的活世界表面。
- `Viv` 最接近「人物行動留下可追查因果、記憶與故事線」，但它是接到別的
  模擬器上的引擎，不提供世界、持久化或玩家介面。
- `Expressionist` 與 `Curveship` 證明「世界狀態／視角」和「實際文字怎麼說」
  可以分開處理，但沒有補上持續人物世界。
- 2026 年仍在 pre-alpha 的 `Allegory.js` 已明確走向「模擬而非故事樹、確定性
  世界狀態、感知後描述」；它顯示這個方向正在匯流，卻還不是完整反例。

因此，「前所未有」不能寫成歷史事實；更準確的說法是：**組成零件各有先例，
但奇點目前提出的整體組合，在本輪沒有找到成熟同類。它不是憑空發明，而是把
幾條長期分離的路線接到同一個玩家表面。**

## 最接近的先例：Versu

`Versu` 是本輪最值得細讀的玩家表面先例，不是因為它也是文字，而是因為它
已實作一條接近奇點的閉環：

1. 世界與社交狀態存於形式邏輯資料庫。
2. 狀態決定目前成立的社交做法與可用 action。
3. NPC 使用自己的 decision maker 選 action；玩家則在同一批 action instance
   中透過 GUI 選擇。
4. action 改變資料庫狀態。
5. 系統依角色、態度、關係與行動產生文字，而不是只顯示固定句。

它也明確主張文字不是 3D 做不起來時的退而求其次：文字能表達猶豫、態度、
內心與社交細節，這些往往比動畫更省資產且更精確。

但 `Versu` 的上位目標仍是 interactive drama。它的 episode 有作者設定的角色、
世界與腳本，系統也有 drama manager。奇點可以參照閉環，不能照搬它的「戲劇
必須被組織成一段好故事」前提。

## 研究對奇點真正增加的東西

以下是**研究推導出的候選能力鏈**，不是使用者已拍板的 UI、引擎或資料結構：

1. **世界事實**：人、物、位置、時間、關係、持有與事件先在後端成立。這是
   唯一真理，文字模型不能改寫它。
2. **人物所知**：每個人只保留自己看見、聽見、推斷或被告知的部分；可以不全、
   過時或錯誤，但要知道資訊從哪裡來。
3. **玩家可感知**：按位置、感官、遮蔽、注意力、能力與既有知識，切出玩家
   此刻有資格知道的事實。
4. **重要性篩選**：從可感知事實中挑出現在值得顯示的差異，避免把整個世界
   資料庫或事件 log 倒給玩家。
5. **文字實現**：用帶有明確語意與適用條件的小型文字單元組合表達；文句可以
   有風格，但每一句都能回指真實事實。
6. **GUI 行動**：同一份狀態產出現在能接觸的人、物與行動入口；GUI 不是另外
   編一套劇情選項。
7. **行動裁決**：玩家選擇只是一個嘗試；世界規則判定成功、受阻、代價與
   連帶影響，再寫回世界狀態。
8. **因果痕跡**：保留誰做了什麼、因何發生、誰知道、改變了誰或什麼，讓
   回訪、記憶、傳聞與玩家自己的故事都從同一條歷史長出來。

壓縮成資料流是：

`世界事實 → 人物／玩家可知 → 當下重要事實 → 文字與 GUI 行動 → 世界裁決 → 狀態差異與因果痕跡`

這條鏈不決定主畫面要像即時狀態、場景卡、事件流或其他形式；「主畫面主要
呈現現在、過去另行回看」仍未由使用者拍板。

## 反證與失敗警告

### 1. 深模擬不會自動變成好遊戲

[Open Design Challenges for Interactive Emergent Narrative](https://expressiveintelligence.github.io/papers/ryanEtAl_OpenDesignChallengesForInteractiveEmergentNarrative.pdf)
指出，豐富模擬的狀態與故事常對玩家不可見，形成 `Tale-Spin effect`：系統內部
很複雜，玩家只看到單薄或雜亂輸出。論文也指出，大狀態空間無法靠每種情況
手寫一整段內容；比較可行的是用帶狀態含義的小型內容單元重新組合。

**對奇點的約束**：不能先堆每個人物的幾百項資料，再假定文字自然會變豐富。
每一層人物深度都要能改變玩家可感知事實、可做行動或後續因果。

### 2. 事件總表不是故事，也不是可讀世界

同一篇研究指出，純 bottom-up 模擬很難從大量事件噪音中辨認真正有意義的
故事線；`Viv` 也因此把因果記帳與 story sifting 做成獨立能力。

**對奇點的約束**：文字主畫面不能退化成「某人走到某處、某人買了某物」的
滾動 log。必須區分當下局部狀態、值得注意的改變、可追問原因與可回看的
歷史。

### 3. LLM 不應擁有世界真理

[Can Language Models Serve as Text-Based World Simulators?](https://aclanthology.org/2024.acl-short.1.pdf)
在狀態轉移測試中，即使 GPT-4 對動作造成的變化表現較好，對環境自行造成的
狀態轉移仍明顯不可靠；論文結論是不足以當可靠世界模擬器。

**對奇點的約束**：LLM 日後可以協助理解輸入、選句或潤飾已驗證事實，但不能
臨場決定物件是否存在、人物做過什麼、交易是否守衡或行動是否成功。

### 4. 自製故事語言可能把作者成本推到失控

`Storytron` 的作者在[專案回顧](https://www.erasmatazz.com/personal/self/end-of-an-era.html)
中把十年投入、系統複雜度與作者／玩家難以進入列為失敗核心。`Viv` 雖以新的
專用語言處理同類問題，卻把自己定位成可插拔、無狀態的後台引擎，而非一款
包辦世界與玩家表面的產品。

**對奇點的約束**：現階段不因研究結果另造一套龐大 DSL（專用描述語言）。
先證明一小段世界事實能被可靠地感知、表達、操作與留下痕跡。

### 5. 「很多活人」會把內容與驗證成本同時放大

[Curating Simulated Storyworlds](https://escholarship.org/uc/item/4mr6c29j) 的回顧指出，
社會模擬容易同時擴張人物、物件、性格、行動與反應，最後把製作力量攤薄；
幾十至幾百人物與數千事件也不可能長期靠人工找故事。開源的
[Neighborly](https://github.com/ShiJbey/neighborly) 提供了居民、關係、職業與
生活事件的資料化參照，但專案已封存，且作者明說它不處理精確位置與玩家
體驗。

**對奇點的約束**：人物規模、模擬精度與文字量都不能拿來當「活」的代理
指標。應驗證的是人物是否有可追查的生活因果，以及這些因果是否真的改變
玩家遇見的世界。

## 回答三個競爭假設

### 假設 A：完整組合尚無成熟先例

本輪證據最支持。各關鍵能力分別存在，但沒有找到一款成熟作品把七項接成
同一個玩家表面。

### 假設 B：它其實就是 emergent narrative

只對一半。emergent narrative 研究明確支持「故事從人物互動中形成」；Ruth
Aylett 早期就提出故事應從角色互動過程中湧現，每個人只從自己的參與形成
故事（[研究頁](https://www.macs.hw.ac.uk/~ruth/narrative.html)）。但奇點的核心
問題還包括持續世界、具身居民、局部感知、GUI 接觸與文字作即時世界表面，
不能被 `emergent narrative` 一詞全部包住。

### 假設 C：它只是換皮 MUD

不成立。MUD 證明持續文字世界可行，但典型的房間、命令列、終端機回饋與
以其他真人玩家為主要社會內容，只涵蓋七項中的一部分。若奇點把介面做回
房間描述加命令／事件 log，才會重新落回 MUD 外殼；「回文字」本身不等於
這件事。

## 目前可引用、不可升格的判斷

- 可引用：本輪沒有找到完整成熟同類；最接近的是多個局部先例的交集。
- 可引用：狀態、感知、重要性、文字、行動與因果需要分層，否則深模擬會對
  玩家不可見或變成事件垃圾。
- 可引用：LLM 不適合作為唯一世界模擬與事實來源。
- 不可升格：奇點已成為一個新遊戲類型。
- 不可升格：必須使用 `Versu`、`Viv`、ECS、NLG 或任何特定引擎／語言。
- 不可升格：主畫面必須只顯示「現在」，過去必須放另一頁。
- 不可升格：「生活的世界／活的世界」已成為奇點整體方向；這仍是另一個
  未決問題。

## 2026-07-17：實際 UI 橫向掃描

這一輪不再只讀功能清單；實際檢視官方網站、商店頁或專案提供的玩家畫面，
研究各種文字遊戲 UI 到底把注意力放在哪裡。以下比較的是**整個介面在承載
什麼**，不是美術喜好，也不是要挑一套現成外殼。

| UI 家族與案例 | 畫面真正的主體 | 已證明的能力 | 整套搬進奇點會發生什麼 |
| --- | --- | --- | --- |
| 終端機優先：[Smudgy](https://www.smudgy.org/) | 大面積文字終端；地圖、生命值等工具退到邊緣 | 極度克制；遊戲內容而非客戶端介面取得注意力 | 仍把閱讀歷史、輸入命令與玩家熟練度當作基本前提 |
| 通用 MUD 工作台：[MudForge](https://mudforge.org/)／[Nexus](https://play.google.com/store/apps/details?id=com.ironrealms.nexus) | 終端文字加地圖、狀態、分頁、快捷鍵、可編程按鈕 | 一個客戶端能承載大量不同 MUD，手機也能替命令列加觸控捷徑 | 工具面板和文字爭奪空間；玩家像在操作一套客戶端，不是直接接觸世界 |

| 當下情境選單：[Usurper Reborn](https://github.com/binary-knight/usurper-reborn) | 狀態框、當前事件與一小組有效選項 | 用很少的字元把複雜系統壓成此刻可選的行動 | 世界容易被切成一連串 BBS 功能頁；玩家讀數值、選功能，而不是身處地方 |
| 功能入口清單：[Farm RPG](https://www.farmrpg.com/) | 農場、背包、工坊、城鎮、釣魚等穩定入口清單 | 極簡列表可以容納大量系統、通知與漸進解鎖，手機操作成本很低 | 「世界」被拆成產品功能目錄；豐富存在於選單數量，不在玩家身邊正在發生的事 |
| 圖像化手機 MUD：[GoMud / Drust](https://gomud.mlmc.nz/) | 場景圖、人物立繪、長段落、迷你地圖、方向鍵與多個面板 | 傳統房間移動、任務、裝備與 NPC 可被完整改造成觸控介面 | 立刻掉進美術素材、面板管理與閱讀故事三個坑；GUI 本身成為另一款要製作的遊戲 |
| 漸進揭露：[A Dark Room](https://github.com/doublespeakgames/adarkroom) | 畫面起初幾乎為空，只在狀態成立時揭露少量行動 | 玩家永遠只需理解眼前少數選擇，系統深度可以慢慢展開 | 它依靠作者安排的單人進程與謎團；不能直接證明持續世界中的居民與大量局部接觸也適用 |

### 這輪真正排除的誤解

1. **UI 研究不是替奇點挑皮膚。** 上述案例的價值在於拆出承載方法；沒有一套
   整體外殼能直接套用。
2. **「簡單」不等於只剩終端機。** Smudgy 的簡單來自克制，Farm RPG 的簡單
   來自穩定列表，A Dark Room 的簡單來自漸進揭露；它們犧牲的東西完全不同。
3. **GUI 化也不等於更接近世界。** MudForge、Nexus、GoMud 都證明命令可以
   變成按鈕；但按鈕越多、面板越完整，玩家越可能在操作客戶端或 RPG 系統。
4. **文字本身不是目前畫面出戲的根因。** 現行 v5 把地方描述、事件歷史、
   人物／物件連結與可做行動塞在同一條長卷軸裡，所以活世界被讀成一份持續
   增長的紀錄。這是資訊角色沒有分清，不是「回文字」必然如此。

### 可帶回奇點、但尚未升格為 UI 定案的原則

- 主表面首先要讓人辨認**我此刻身在什麼地方、身邊有誰／什麼、剛才因我或
  世界發生了什麼**；不是先展示系統總覽。
- `東、西、南、北、上、下、進、出` 是穩定的移動語彙，不必因此變成巨大
  方向鍵盤，也不必承擔接觸人物、物件與世界的全部操作。
- 值得保留的是 Smudgy 的克制、Written Realms 的情境接觸、Usurper 的當下
  行動壓縮，以及 Farm RPG 在次層功能使用的穩定列表；不保留任何一家的整套
  畫面結構。
- 背包、角色、設定、較長歷史等可以是需要時打開的次層；若它們長駐主畫面，
  就會與當下世界競爭注意力。
- 世界是否活著仍必須由人物、物件、時間與後果在玩家的接觸中自然露出，不能
  靠「世界正在變化」看板或狀態儀表宣告。

因此，這輪研究把下一個 UI 問題縮成一個可驗證命題：**同一個地方、同一批
人物與同一次玩家行動，能否在不靠長卷軸、不靠功能首頁、不靠大量常駐面板的
情況下，讓玩家看懂當下並自然接著行動。** 這才是後續原型要比較的對象。

## 後續若再研究

- 找實際可玩的完整匹配，而不是再堆同類論文。
- `Versu`、`Viv`、`Usurper Reborn` 的行動閉環與作者成本比較已完成，見
  [文字活世界的行動閉環：Versu、Viv、Usurper Reborn 對照](2026-07-16-text-world-action-loop-comparison.md)。
- 等文字玩家表面出現候選後，用同一個世界狀態驗證：玩家能否看懂現在、
  接觸人／物、採取行動、看到可靠結果，又不被 log 或散文淹沒。
