# 奇點世界設計考古索引（第一輪）

- 日期：2026-07-15
- 性質：歷史證據索引，不是正典，不是舊設定復活清單
- 現行第一權威：`docs/DESIGN_KEYWORDS.md`

## 一、先說結論

這次考古沒有發現「奇點世界一直沒有想法」。相反地，最早期已經有一條
相當穩定的遊戲骨架：

1. 玩家在手機上的 2D 大地圖中直接存在、移動、觀察與接觸世界。
2. 地圖負責空間、距離與方位，文字負責狀態、質感、結果與故事細節。
3. MUD 指的是自由感、世界規則與可讀的動態故事，不等於純文字房間 UI。
4. 世界不以玩家為中心；萬名以上 NPC 各自生活，事件在玩家缺席時也繼續。
5. 玩家與 NPC 服從同一套物理、物件、行為與因果規則。
6. 操作可以很輕，但世界模擬、後端狀態與因果不能因此變淺。

真正反覆發生的是：上述骨架因 AI 與實作能力不足，被依序壓縮、改譯成格子、
九宮格、房間節點、純文字 MUD；後來又嘗試 Hex 畫布，再次撤掉。這些版本能
證明當時做了什麼，不能反過來證明那就是使用者最想要的產品。

因此，2026-07 的「世界圖像化、細節文字化」以及 2D 平面大地圖，不是突然
換題，而是有證據支持的原始雙層構想回復。這仍不代表所有舊細節都要回來。

## 四、恢復出的產品骨架

### 4.1 玩家持續感受：整裝待發，出發探索

E2 回答不是把「探索」列為一種玩法分類，而是希望玩家一直保有
「整裝待發，出發探索」的感受。出生地也曾傾向一座足以探索很久的大城市，
或其衛星小鎮。

考古判讀：

- **探索感**是產品北極星候選，遠高於某一套戰鬥、經濟或技能公式。
- 「世界什麼都有」指世界不應先被題材標籤切窄；不等於第一版要同時塞進
  所有內容。
- 大地圖不是方便趕路的菜單，而是玩家感受世界尺度、密度與未知的場所。

狀態：探索北極星與大地圖已現行保留；出生地仍是恢復候選。

### 4.2 有限框架，無限延伸

E1 原話把 AI 的工作定為：把使用者的感性訴說轉成可執行規則，讓玩家能在
有限法則中作無限延伸。玩家不是被選單告知「只能做什麼」，而是世界規則
自然決定行動是否成立；血肉不能穿牆就是例子。

考古判讀：

- 這不是「系統真的容許任意輸入」；是可組合的世界規則讓許多合理行動成立。
- 「不可無中生有」「後端唯一數據真理」「全物件化」都是這個核心的護欄。
- AI 後來提出的原子行為、能量電路、標籤表等，只是 E3 實作延伸，不能冒充
  核心本身。

狀態：核心原則現行保留；具體原子系統未定。

### 4.3 地圖承載空間，文字承載細節

E1 原始說法不是要做一款圖像 RPG，也不是只想讀文字。選擇 Map 是因為純文字
很難讓人穩定感受方位、距離與世界尺度；同時，完全具象的畫面會限制人腦補完。
Map 提供抽象但可信的空間錨點，MUD 提供自由、狀態、質感與故事。

這與目前的「世界圖像化，細節文字化」高度一致：

- GUI 讓玩家**活在空間裡**：看見位置、人、物、路、障礙與變化。
- 文字讓玩家**理解接觸的內容**：觀察、狀態、對話、結果、傳聞與歷史。
- 文字不是拿來代替整個世界畫面，也不是每走一步讀一段場景散文。

狀態：現行保留。美術語言、地形生成與文字出現方式仍未定。

### 4.4 MUD 是感受，不是純文字外框

兩組 E1／E2 證據互相支持：使用者要的是「MUD 的感受」與「微視圖化的
MUD 遊戲」。其內容包括：

- 天大地大、原則上隨處可去；
- 不依傳統任務線維持世界；
- 玩家可旁觀、接觸、離開或改變事件；
- 每個 NPC 有自己的故事，世界不等玩家才開始演；
- 後端事實可轉成有可讀性的故事；
- 手機用點擊取代繁瑣文字指令。

後來的「純文字 MUD」「房間節點」「九宮格方向鍵」是對實作困難的表面解法，
不是 MUD 感受的完整定義。

狀態：MUD 自由感保留；純文字主表面已取代。

### 4.5 移動是世界本身，不是路線跳轉

E1 已明確說過：

- 角色不是點擊後瞬移，正常移動必須經過物理時間與空間；
- 縮小地圖時，點擊主要用於查看資訊，不能從遠方直接命令跨世界移動；
- 直接點遠處即使允許，角色也只會往目標前進，遇房、山、樹、石、河就停；
- 玩家靠持續觀察與點擊修正路徑，藉此感受旅途，不走傳統 MUD 的方向鍵串；
- 傳送可存在，但必須是世界內有來源、有規則的例外。

這與 2026-07 再次確認的「連續移動、單擊走、雙擊跑、直線、撞牆停、不自動
繞路」一致。早期關鍵字中的「自動尋路徑前進」已被更具體的原始對話與現行
決定覆蓋。

狀態：基本移動現行保留；遠近縮放的操作權限是恢復候選，尚未再拍板。

### 4.6 萬名以上 NPC 是世界內容，不是人數 KPI

E1 原話把「萬名以上」說得很清楚：每一名 NPC 都是一條可能被玩家跟蹤讀懂的
故事線；被發現前，發展有多種可能；所有人的生活每時每刻交織成故事網。玩家
下線洗個澡再回來，據點、人物、物品與市場都可能已經改變。

所以萬人 NPC 的用途不是：

- 在地圖上塞一萬個裝飾圓點；
- 生成一萬個聊天機器人；
- 讓玩家接一萬個任務；
- 宣稱規模很大。

它是為了回答一個產品問題：如何讓大世界不空，且玩家短暫缺席後仍能感覺
世界活著。更準確的現行定錨是：沒有玩家，世界還是世界；玩家不是世界的
主角，只是在世界中創造自己的故事，成為自己故事的主角。

狀態：萬人以上異步 NPC、玩家非唯一主角、世界持續運轉均現行保留；故事線
推演與觀測坍縮的確切模型仍需重審，不能直接採用舊 AI 公式。

### 4.7 全物件化不是「每個像素都要做一份素材」

早期原話與關鍵字反覆要求：畫面上有意義地存在的東西，應有後端身份、狀態、
來源與可成立的動作；不能靠文字臨時說一件不存在的物品突然出現。

考古判讀：

- 玩家看到物件會想「摸一下」，是接觸與探索承諾。
- 並非每個背景筆觸都要做成獨立資料列，也不是每棵樹都必須有獨有劇本。
- 正確邊界應由「玩家是否會把它理解成可接觸實體」決定，而非美術像素數量。

狀態：原則現行保留；物件粒度、群集物件與背景紋理的分界未定。

### 4.8 重體驗、輕操作

「輕」指手機上的輸入摩擦低：點擊、拖曳、接觸後出現符合情境的動作。它不
表示世界反應簡化、後端表格直接露出、NPC 停止生活，或玩家只讀預寫故事。

狀態：現行保留。

## 五、能力妥協清冊

| 被壓縮的原意 | 當時的替代物 | 為何判定是妥協 |
|---|---|---|
| 2D 大地圖直接生活 | 九宮格、方向按鈕 | 原始對話明說關閉視圖化來自 AI 技術壁障；格子方案也明列可大幅降低 Bug |
| 連續物理位移 | 一格一格跳、房間出口 | 舊對話把 Grid 形容為開發快但失去絲滑感；現行使用者再次否定頓格 |
| Map＋文字雙層呈現 | 純文字房間 MUD | `CURRENT_DESIGN.md` 明寫「放棄圖像表現設計，以控制 UI 成本」 |
| 圓＋字的人形角色 | 全名文字連結 | Q&A 的角色題直接被改寫為「純文字 MUD 模式一律全名」 |
| 世界距離由行走與障礙形成 | 方向指令／節點跳轉 | 與原始「手動引導、直線碰撞、感受旅途」相反 |
| 世界密度來自生活中的 NPC 與物件 | 每格塞寶、AI 生成敘事 | 後者多為 AI 對「每格值得停留」的快速機制化延伸 |
| 玩家下線後仍是完整居民 | 只做附近低風險簡易任務 | 使用者原本想不設限，但明說不知道系統能做到什麼程度，之後才收縮 |

這張表不是要求立即實現原始最寬版本；它只防止未來再把工程退路寫成產品本質。

## 六、舊設定的處置

### 6.1 已被現行決定取代

- 純文字 MUD 作為主要玩家畫面。
- 九宮格、房間節點、方向鍵串作為產品身份。
- Hex 作為預設世界拓撲或視覺風格。
- 自動尋路；現行是直線前進、碰撞停止、玩家自行修正。
- 所有人形生物以 sprite、紙娃娃或具身小人呈現；現行是圓＋中文字。
- 角色圖標以世界比例 `24px＝1m` 隨縮放；現行規則是人形標記維持固定螢幕大小。
- `重文字、輕畫面` 作為主畫面限制。

### 6.2 有使用者證據，但必須重新問過

- 遠距縮放時只查看、近距／目前載入區才可下移動命令。
- 大地圖與可進入的區域／建築容器如何銜接。
- 出生在一座足以長期探索的大城市或衛星小鎮。
- 角色離線後的自主程度、風險與回歸摘要。
- NPC 是否繼續採 OCEAN 五項人格，以及數值範圍。
- 點擊自己、點擊遠方物件、靠近物件後動作選項的具體界面。
- 死亡、掉裝與自動文字戰鬥的舊方向。
- 工具解鎖技能、熟練度產生進階／異變、技能組合。

### 6.3 已明確封存或不得自動復活

- Token／詞元／單詞／詞盤／敘事／陣列的語義造句系統。
- 舊 110V、念場、富態化、道化、天道審計等特殊術語與世界物理。
- 2026-06-23 前後那批未通過玩家驗收的世界大綱、地圖、材料、勢力、NPC、衝突與
  視覺稿。
- 2025-12 Gemini 白皮書中的九權、三劫、雲端費用、Firestore、Gemini API 對話、
  固定行為公式、指定世界觀與所有「終極企劃」式包裝。
- 把程序地圖的「未探索區才生成」直接等同於 NPC 故事線的「觀測坍縮」。兩者
  來源不同、處理的問題也不同。

### 6.4 AI 延伸，只能拆靈感

2025-12 舊文與後來問答結論中，以下內容大多是 AI 自行補齊：

- 精確經濟模型、社會階層表、權限矩陣與大批命名系統；
- 具體人格公式、NPC 行為樹、LOD 頻率與雲端架構；
- 水墨 SVG 濾鏡、Chunk JSON、程序噪聲與零美術成本論；
- 每格藏寶、費洛蒙熱區、宏觀／微觀雙層等機制包；
- 戰鬥數值、技能語法、裝備插槽與變異因子；
- 整套世界史、地名、組織、人名與能量物理。

它們可用於回答「以前試過哪些解法」，不能用於回答「使用者本來要什麼」。

## 七、目前仍值得挖的原始問題

第一輪已找回產品骨架。下一輪若繼續考古，最值得依序追的是：

1. **縮放與接觸權限**：遠看、近看、可走、可摸與「是否觸發」原本怎麼分層；
   第二輪考古見 [縮放、觀看、接觸與觸發](2026-07-16-zoom-contact-archaeology.md)。
2. **世界密度**：怎樣讓旅途有內容，而不是每格塞寶或每步跳散文；第三輪考古
   見 [世界為何大而不空](2026-07-16-world-density-archaeology.md)。
3. **NPC 故事網**：哪些是使用者真正想要的世界行為，哪些是「觀測坍縮」包裝。
4. **物件接觸語言**：圓＋字的人物與地圖物件，如何讓玩家自然地想摸一下。
5. **戰鬥／技能／裝備**：先取回體驗意圖，再隔離 Token 等已封存實作。
6. **大地圖與局部空間**：戶外、建築、樹林、樹海與其他容器是否需要同一種空間表現。

這些要先找原話，再討論現在還要不要；不應從舊結論表直接往下實作。
