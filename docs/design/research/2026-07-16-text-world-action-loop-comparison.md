# 2026-07-16 文字活世界的行動閉環：Versu、Viv、Usurper Reborn 對照

狀態：完成第二輪有界研究；研究推導，不是奇點正典、UI 定案或實作授權

承接：[文字作為活世界表面：外部先例與反證研究](2026-07-16-text-as-living-world-surface-prior-art.md)

第一權威：`docs/DESIGN_KEYWORDS.md`

## 這輪要回答的問題

第一輪已確認：沒有找到成熟案例把持續世界、自主人物、局部感知、文字主要
表面與 GUI 接觸完整接在一起。第二輪不再擴大案例清單，而是把三個最接近的
案例壓到同一條實際閉環上：

1. 誰產生人物此刻可能採取的行動？
2. 玩家與 NPC 是否真的使用同一份行動與世界規則？
3. 誰裁決行動結果，誰只負責把結果說出來？
4. 玩家看到的是當下局部世界，還是事件紀錄／作者安排的故事？
5. 要讓內容變豐富，作者必須手寫與調校多少東西？

## 核心發現：當下與歷史是兩條不同的閉環

要讓玩家「透過 GUI 活在故事裡」，奇點至少要分清兩件事：

### 當下閉環

`世界目前事實 → 玩家此刻可感知的局部 → 可接觸的人／物／現象 → 玩家嘗試行動 → 世界裁決 → 狀態真的改變 → 重新顯現局部世界`

它回答：**我現在在哪、察覺什麼、能碰什麼、做完後哪裡不同。**

### 歷史閉環

`行動痕跡 → 目擊／得知 → 人物記憶、傳聞、物件痕跡與公共紀錄 → 因果關聯與重要性篩選 → 在適當時機重新被人或玩家察覺`

它回答：**事情為什麼成為現在這樣、誰知道、哪些經過仍有後效。**

歷史閉環能讓世界有深度，卻不能取代當下閉環。若把歷史事件直接倒成主畫面，
玩家得到的是新聞、戰報或流水帳；若只做當下而不留歷史，世界每次重看都像
剛生成，人物也不可能真的記得彼此。

這個分法不等於主畫面、分頁或時間軸已定案；它只是確認兩種資料責任不能混成
一條文字流。

## Versu：真正可取的是「同一來源」，不是 `Act Now`

[Versu 架構論文](https://versu.com/wp-content/uploads/2014/05/versu.pdf)明確畫出：
NPC 的 action instances 送入 decision maker；玩家的 action instances 則繞過
decision maker，直接送到 GUI。兩者共用前面那段「世界狀態、成立中的 social
practices、前置條件、action 產生器」，也共用後面的 action executor。

這證明一個關鍵點：**玩家與 NPC 可以共用「世界認為現在能嘗試什麼」及「做了
會怎樣」；只有選擇來源不同。** NPC 用自己的欲望與判斷選，玩家用 GUI 選。
共用規則不等於共用輸入方式，也不等於玩家要看 NPC 腦內評分。

但不能照搬它的表面與內容方法：

- 玩家仍以 `More` 繼續閱讀、用 `Act Now` 打開分級行動清單；這仍帶有「故事
  正在往下讀」的節奏（[官方 FAQ](https://versu.com/support/faq/)）。
- episode 需手寫 social-practice、人物與初始世界腳本，另有 drama manager
  控制關鍵戲劇時機。
- 論文自己列出 300 多項欲望難以調校；多個 concurrent practices 會讓每個
  action 與其他所有 action 競爭，使除錯與調校更難。

因此奇點可以保留「同一行動來源、同一裁決」，不能把它翻成固定動作清單、
篇章式戲劇或另一套龐大 Praxis 類語言。

## Viv：很適合世界記得，不適合讓玩家看見現在

[Viv 官方介紹](https://viv.sifty.studio/introduction/)把責任說得非常清楚：

- Viv 產生並記錄離散 actions，action 沒有持續時間。
- 宿主遊戲負責世界資料與持久化；Viv 本身無狀態。
- reaction、人物得知事件、物件刻錄資訊時，系統保存因果關係。
- story sifting 是在 chronicle 或人物記憶中找出符合作者模式的因果事件串；
  白話就是從大量已發生事情中辨認「這一串其實是同一段恩怨／後果」。
- 官方明說 Viv 擅長 `What happens next?` 與 `What has happened so far?`，
  不是逐格回答 `What is happening right now?`。

這正好說明它對奇點的合理位置：因果記帳、人物記憶、傳聞與回看歷史可參考；
玩家此刻的空間、遮蔽、在場人、接觸物與連續行動仍要由奇點自己的世界與
感知層回答。

也不能把 story sifting 誤解成「AI 幫玩家寫一段故事」。它是在既有事件和
因果關係中找線，不得新增世界事實。這可當歷史閉環的工具思路，不該成為
主畫面或世界裁決者，也不構成採用 Viv、其授權或其專用語言的決定。

## Usurper Reborn：證明世界能活，沒有解掉玩家表面

本輪在 2026-07-16 讀取其 `main` 分支提交
[`4da8751`](https://github.com/binary-knight/usurper-reborn/tree/4da87512837ec2bb5f6ec68acae2cc6e4f9f0515)：

- [`NPCBrain.DecideNextAction`](https://github.com/binary-knight/usurper-reborn/blob/4da87512837ec2bb5f6ec68acae2cc6e4f9f0515/Scripts/AI/NPCBrain.cs#L145-L190)
  會更新情緒、衰減記憶、重估目標、產生 possible actions，再選最好者。
- [`WorldSimulator`](https://github.com/binary-knight/usurper-reborn/blob/4da87512837ec2bb5f6ec68acae2cc6e4f9f0515/Scripts/Systems/WorldSimulator.cs#L9-L42)
  以固定 tick 推進 NPC 與世界生活。
- 但玩家仍走 [`BaseLocation.LocationLoop`](https://github.com/binary-knight/usurper-reborn/blob/4da87512837ec2bb5f6ec68acae2cc6e4f9f0515/Scripts/Locations/BaseLocation.cs#L637-L928)：
  顯示 location、取得輸入、交給 `ProcessChoice`，並在各地點維護選單邏輯。
- [`NewsSystem`](https://github.com/binary-knight/usurper-reborn/blob/4da87512837ec2bb5f6ec68acae2cc6e4f9f0515/Scripts/Systems/NewsSystem.cs#L11-L107)
  明確把戰鬥、婚姻等世界事件合併成一條 unified news feed，另由
  [`NewsLocation`](https://github.com/binary-knight/usurper-reborn/blob/4da87512837ec2bb5f6ec68acae2cc6e4f9f0515/Scripts/Locations/NewsLocation.cs#L7-L105)
  倒序分頁顯示。

所以它有兩個成熟但分離的東西：**背景世界會自己運轉；玩家則透過傳統地點與
選單接觸內容。** 新聞流證明世界事件可以被保存與告知，卻也直接示範了為何
事件流不能當奇點的主要世界表面：它告訴玩家「世界發生過很多事」，沒有直接
回答「我眼前的世界現在是什麼、我能摸什麼」。

## 三個候選方向的審辯

### 候選一：以當下局部世界作主要循環

世界先切出玩家此刻可感知的人、物、位置、局勢與痕跡；GUI 讓玩家從這些
對象發起接觸；後端裁決後重新投影新的局部世界。

**目前證據最支持。** 它能吸收 Versu 的共用 action 來源、Usurper 的持續世界
與 Viv 的因果歷史，又不必繼承三者的產品外殼。

這裡所謂「可做行動」只是後端知道現在可嘗試什麼，不表示 UI 必須把它攤成
一列按鈕。玩家可能先接觸一個人、物、聲音或痕跡，GUI 再以尚未定案的方式
讓意圖成立；這仍服從奇點的關鍵詞「接觸」，不是預設動作選單。

### 候選二：以事件流或自動摘要作主要循環

世界持續產生事件，系統挑選或摘要後餵給玩家，再讓玩家選擇要追哪一則。

**不適合作主要表面。** 它容易把玩家變成世界新聞的讀者或管理者；離自己很遠
的重大事件會壓過眼前細小但可接觸的事。摘要只能處理資訊量，沒有自動建立
「我在這裡」的具身感。

事件、新聞、傳聞仍可在世界裡以合理途徑存在，但它們應是玩家可能接觸到的
人、物或資訊，不是上帝視角的固定主畫面。

### 候選三：以故事篩選／戲劇管理作主要循環

系統從因果歷史中找出最有戲的線，或主動安排事件靠近玩家。

**只適合作次要能力。** 它能避免歷史垃圾並幫 NPC 理解恩怨，但若主導當下，
世界又會開始為玩家編戲，違反「玩家不是世界的主角」。Versu 的調校負擔也
證明，讓所有行動為戲劇重要性互相競爭，作者成本會迅速失控。

## 舊奇點／Usurper 案例研究的考古結果

本機舊案例研究其實已做過一條後端骨架：

`收集候選行動 → 檢查前置條件 → 玩家或 NPC 選擇 → 執行 → 狀態差異／失敗 → 事件痕跡 → 玩家投影`

並曾用 `world_action`、`action_offer`、`action_execution`、
`action_state_delta`、`action_event_trace` 等名稱拆分責任。

這證明目前不是從零想一套資料流。但舊設計綁著 M4 場景、runtime slice、
玩家 log、可點 action_offer 等當時外框，也混有已退役世界素材。現在只能
保留以下**結構性證據**：

- 玩家與 NPC 不該各有一套可繞過世界規則的行動。
- 玩家送出的是嘗試，結果由後端狀態與條件裁決。
- 結果要改狀態並留下可追查痕跡，不能只產生文案。
- 玩家表面是後端真理的局部投影，不是自己解析散文猜人、物與出口。

舊名稱、M4、場景切片、事件流版面、固定 action 清單及內容樣本都不因此復活。

## 目前最強的研究推論

奇點不是要讓一個故事系統控制活世界，而是要讓**同一個活世界同時供 NPC
自己判斷、供玩家親手接觸，並在事後留下可追查的因果。**

可暫時拿來檢查後續設計的閉環是：

`世界唯一真理 → 玩家此刻可感知的局部 → 對局部人／物發起接觸 → 同一套世界規則裁決 → 真實狀態差異 → 新的局部呈現`

旁邊另有一條歷史鏈：

`行動痕跡 → 誰目擊／得知 → 記憶、傳聞、物件與公共紀錄 → 往後改變人物判斷與玩家所見`

這是研究結論，不是已由使用者拍板的架構。它仍未決定文字版面、空間表示、
移動操作、自由輸入、第一個場景或是否使用任何特定引擎。

## 反證條件

下列任一結果都足以推翻或改寫目前推論：

- 找到一個事件流為主、卻仍能讓玩家清楚感到「我在此地、我正接觸此物」的
  成熟案例。
- 實際玩家表面測試顯示，局部世界投影必須靠大量固定動作清單才能理解，且
  接觸式 GUI 反而造成更大負擔。
- 玩家與 NPC 共用行動定義導致玩家需要的細緻操作被 NPC 模擬成本拖垮，無法
  以同規則、不同決策解析度維持。
- 因果歷史無法實際改變人物判斷、傳聞、物件痕跡或玩家後續所見，只剩昂貴
  的資料保存。

在這些問題通過具體玩家體驗驗證前，不能把本報告升格為引擎選型或製作定案。

## 人物接觸紙上原型：從「揭露」改成「嘗試」

狀態：**待驗證研究方案，不是奇點定案。** 本節只處理玩家表面如何避免把
人物降格成聊天端點；不採用 Usurper Reborn 的人物欄位、生活模擬範圍或架構。

把「玩家接觸人物後，GUI 揭露其當前處境」當成答案仍然有錯。即使揭露的
資料完全來自後端，只要碰一下人物就得到整理好的工作、關係、義務與可用線索，
人物仍是可查詢的世界狀態 API。正確的因果順序應改為：

`玩家作出普通世界嘗試 → 時間、位置、人物活動與共同物件照規則推進 →
人物可能注意、忽略、拒絕、離開或被打斷 → 玩家只從實際後果感知資訊`

### 五個聊天端點回歸警報

- 一碰人物就出現正確但不該直接可知的人物摘要。
- 每次接觸都保證對方回一句話並等待玩家下一步。
- 反覆點擊可以把更多台詞、背景與線索「挖完」。
- 人物與附近物件、關係、義務被排成偽裝過的主題／行動清單。
- 接觸後人物進入保護泡泡，不再離開、不再趕事，世界等玩家結束互動。

另外，人物沒有義務在拒絕、離開或無視玩家後，自動留下有用線索或替代路徑。
遊戲要讓局部現實可讀，但不能讓每個人的一舉一動都暗中服務玩家進度。

### 方案 A：直接接觸是一個可失敗的招呼／靠近嘗試

- 接觸前：只呈現可見的動作、距離、手上正處理的東西、注意方向與是否正在離開；
  不解釋目的、關係或可用性。
- 一次接觸：玩家嘗試靠近或讓對方注意到自己，不開人物頁，也不保證說話。
- 真實變化：時間和相對位置推進；人物可能注意、繼續忙、放慢、改道或離開；
  這次嘗試本身成為現場事實。
- 可失敗：沒有被注意、對方無法回應、拒絕、趕不上、被另一件本地事件打斷。
- 玩家離開：已耗時間、位置、短暫中斷、是否認出玩家及錯過接觸等結果不重置。

主要風險：若每次點擊最終仍必定換來個人化回應，它只是沒有聊天框的聊天機器。

### 方案 B：透過共同局勢與人物相遇

- 接觸前：人物正以看得見的行動連著本地人物、物件、路線或正在發生的事；
  GUI 不替它貼上「關係」或「任務」標籤。
- 一次接觸：玩家碰的是同一個本地承載物或局勢，不是向人物查詢資訊；因為雙方
  同時影響同一件世界事實，人物才可能注意、阻止、配合、忽略或繼續。
- 真實變化：承載物、位置、通行、活動進度或占用狀態改變，人物依自己的條件反應。
- 可失敗：意圖無法由畫面預測、系統猜錯意圖、局勢已變、人物阻止或無視；若必須
  長期依靠固定選單消除歧義，這個方案失敗。
- 玩家離開：共同物件與活動保留改變；阻礙、協助、中斷、被認出或其他痕跡繼續存在。

主要風險：若玩家無法從接觸前的可見事實合理預測會嘗試什麼，輕操作會變成黑箱
自動代打。

### 可證偽假設與目前 verdict

假設：若人物先以正在進行的世界行動出現，而一次接觸是有時間、位置、不確定性與
失敗可能的普通嘗試，玩家應能在沒有角色卡、對話樹或關係數值的情況下，理解對方
不為自己待命，並從接觸後仍保留的局部變化修正下一步。

反證：人物是否「活著」仍只能靠介面摘要或作者台詞說明；每次接觸必得回應；反覆
點擊能挖完內容；人物在互動期間停止生活；或玩家在對話前離開後，世界沒有任何
權威狀態剩餘。

**Verdict：PIVOT。** 保留「當前感知型文字表面」，但把人物接觸從
「點擊後揭露人物狀態」改成「先發生一次可失敗的世界嘗試」。A、B 都只進入下一輪
同資料紙上體驗比較，不授權 UI 或人物模擬實作。

反方檢查由本機 WebGPT 單線窄題審查完成；其新增的決定性反證是：人物不是玩家的
狀態查詢端點，也沒有義務為每次拒絕或離開提供可利用的下一步。最終判斷仍以奇點
既有邊界、後端真理與玩家體感為準。

## 發話不是對話：三成員辦公室交叉審查

狀態：**待驗證研究方案，不是奇點定案。**

本輪補做完整辦公室程序：WebGPT、WebGemini、WebClaude 先獨立作答，再把三方的
具體分歧送回三條線交叉審查；中斷或帶入舊設定的回答不列入結論，也不以多數票
取代主設計判斷。這同時修正上一節把 WebGPT 單線審查寫成「辦公室」的錯誤。

證據邊界：WebGPT 第二輪在控制器時限結束時被標記為 interrupted；事後以精確
對話頁面檢視確認 `busy=false` 且完整結論區塊可讀。因此其內容只作退化但可讀的
交叉審查證據，不把控制器狀態冒充為乾淨完成。

### 交叉審查後仍成立的規則

- 後端可以建立一次次「發話事件」，不能建立有開頭、輪次、等待回覆與結束狀態的
  對話 session。
- 發話不預約對方的下一個動作。人物可以沒聽見、聽錯、繼續工作、邊走邊答、拒絕、
  被別事打斷或離開；回話本身也是另一個普通世界事件。
- 玩家組句時不選定或保留任何人；真正開口的一刻才依當下位置、距離、遮蔽、聲音、
  注意力、在場者與共同指涉物裁決。不能拿開始打字時的舊狀態回溯結算。
- 發話有短暫持續時間，不是瞬間把完整訊息塞進對方腦中。人物在話說到一半轉身、
  離開或被打斷，只可能聽到片段。
- 字句只在實際說話期間暫時占用說話者的「現在」呈現，之後回到其正在做的事；
  不累積成聊天紀錄。真正留下的是誰聽到什麼、活動是否改變、承諾、許可、物件、
  記憶與後續行為。

### 淘汰與降級

- 把眼前物件拖給人物只算指、展示或共同注意，可輔助一句話中的「這個」，不能冒充
  能表達疑問、否定、時態與不在場事物的語言。
- 固定的全域「Speak」廣播、房間歷史紀錄與對話泡泡都會重新建立受保護的發話通道
  或事件流，不採。
- 把句子做成可收藏、投擲的「思緒牌」只是把聊天輸入改造成道具與庫存，增加一層
  尷尬的介面隱喻，不採。
- 為照顧手機輸入而把結果鎖回開始打字的世界快照，會讓已離開的人在過去狀態中
  聽見現在才說出的話，破壞世界唯一真理，不採。

### 工作決定：先組句，開口時才定向

這是由奇點既有原則可以直接推出的**待驗證工作決定**，不再等待使用者裁決；它仍不是
玩家表面定案。保留的重點是「準備」與「真正發話」分開；長按、拖曳、常駐入口或
其他叫出方式仍可由原型比較，不必先把其中一項升格成設計主權問題。

1. 玩家以尚未決定的輕操作叫出一條暫時的「尚未說出口」文字，可輸入或語音轉字；
   它沒有收件人、頭像、歷史、建議回覆或等待狀態，且同時只能有一句。
2. 組句期間世界照常推進，沒有任何人物知道玩家正在輸入，也沒有人被要求等候。
3. 玩家完成後，點當下仍可感知的人物，才嘗試對其發話；點當下所在的局部環境，
   才是刻意向周遭開口。兩者不互相自動轉換。
4. 若人物在最後一刻已不是有效對象，句子維持「尚未說出口」，不自動轉成對周遭
   的話。玩家選的是「對此人開口」；系統不能因目標失效，暗中把它改寫成另一個
   行動。玩家若要向周遭開口，仍須明確點當地。真正開口後，沒聽見、只聽到片段、
   被打斷或對方離開，才是世界可以裁決的結果。
5. 玩家也可以先做既有的「接觸」嘗試，從對方是否轉頭、放慢或繼續走判斷現在是否
   適合開口；這只是另一個可失敗的世界事件，不是注意力燈號或隱形對話鎖。

人物實際開口時，其當下文字可從：

> 正在把彎掉的扣件分堆

短暫變成：

> 「別在我數到一半時問。」

說完後立刻回到人物此刻真正進行的活動。若玩家轉身、離開可聽範圍，或同時有別的
聲音蓋過去，錯過就是錯過；介面不替玩家保存逐字稿，但世界仍保存已發生的因果。

「世界照常推進」也不等於把人物活動先做成每秒搶按的節拍器。人物動作持續多久、
手機組句需要多久、玩家是否感到被迫競速，必須由同資料原型比較；不能先用極端
即時制把問題製造出來，再用回溯世界狀態補救。

### 紙上對照實驗與反證

這個實驗用來反證上述工作決定，不需先要求使用者在長按、拖曳或常駐入口之間替
原型裁決。同一組三張持續移動、忙碌或離場的人物卡，加一張代表當地的卡；玩家在可重複使用的
「尚未說出口」紙條寫一句話，再於送出時放到仍在場的人物或當地。主持者只依預先
列出的世界結果裁決：沒聽見、片段、繼續、拒絕、被打斷、離開；字句只覆蓋人物當前
行動兩個節拍，然後移除。比較玩家是否：

- 因尚未預選收件人而不再把打字速度當成溝通能力；
- 能區分尚未開口、定向發話與向周遭開口；
- 不靠歷史紀錄仍能從人物活動和後果理解誰可能聽見；
- 不會把每個人物當成必須輪流問完的內容容器。

若玩家普遍需要對話歷史才能理解剛才發生什麼、持續等待「輪到自己」、或覺得暫時
文字根本來不及讀，這個方案即告失敗，不能靠補一個聊天紀錄救回來。

## 世界如何在文字表面上繼續運作，而不變成事件流

狀態：**助手工作假設，待同資料原型反證，不是使用者定案。**

發話問題暴露出更大的表面矛盾：若畫面只顯示「目前成立的狀態」，人物從整理物件
變成轉身離開時，玩家可能只看見新狀態，不知道哪裡變了；若把每次變化依時間一路
往下追加，主畫面又會成為事件紀錄或自動敘事。解法不是二選一，而是讓同一個局部
世界表面承載三種不同壽命的文字：

| 文字所代表的東西 | 在畫面上的行為 | 玩家如何對待它 |
| --- | --- | --- |
| 現在仍成立的事實 | 穩定留在原本的人／物／位置上；事實改變時原位更新 | 可對仍存在的人、物與局部環境發起接觸 |
| 剛剛可感知的變化 | 只在發生變化的位置短暫出現，幫玩家看見前後差；不往下累積 | 它不是過去事件按鈕；玩家只能對變化後仍存在的世界事物行動 |
| 變化留下的痕跡 | 重新成為現在成立的事實；只要仍可感知就繼續存在 | 可被查看、接觸、使用、帶走、避開或成為人物往後判斷的依據 |

抽象流程可以只有三步：

1. 原本顯示：`人物｜正在處理物件`。
2. 世界狀態改變時，在同一人物位置短暫顯示：`人物停下手，轉向聲音來源。`
3. 隨即留下新的現在：`人物｜正看向聲音來源`。若一件物品因此留在地上，它不進
   歷史紀錄，而是成為 `地面｜有一件物品`，繼續存在並可被接觸。

「剛剛的變化」唯一職責是讓玩家察覺世界從 A 變成 B；它不是聊天泡泡、通知中心、
時間軸或可永久回看的逐字稿。玩家點的是現在仍存在的人與物，不是點過去式句子讓
系統重播或補發行動。

這也要求後端不要把每個數值 tick 都翻成文字。只有玩家在當下位置與感知條件下能
分辨、而且足以改變其理解或可行動對象的變化，才投影到表面。人物持續做同一件事、
連續移動中的每一步、微小數值浮動，都不應造成文字閃爍。

### 反證條件

- 玩家必須靠永久事件紀錄才能理解眼前狀態從何而來；
- 短暫變化迫使玩家搶讀、搶按，手機使用者只因閱讀速度較慢而錯失合理行動；
- 畫面持續更新到每一行都像重要通知，反而看不出真正改變；
- 變化文字消失後，世界沒有留下任何狀態差、人物記憶或可感知痕跡。

只要其中一項普遍成立，就表示「現在、剛變化、留下的痕跡」沒有真正分開；不能用
更長的事件列表補救，必須回頭調整投影門檻、閱讀時間或世界痕跡。

## 連續空間不必畫成地圖，也不能壓成房間

狀態：**助手工作假設，待原型反證，不是使用者定案。**

回文字已覆蓋舊 2D 地圖的單擊走、雙擊跑與直線碰撞操作；不能把那些操作直接搬回來。
仍然成立的是另一層事實：白塔半島有位置、距離、路線、地形與旅行時間；人物和物件
真的占有世界位置，玩家與 NPC 也不能靠換一段文字就瞬間跨過空間。

若文字 GUI 只列出幾個地名讓玩家選，連續座標即使仍藏在後端，玩家感受到的仍會是
房間圖。反過來，若要求玩家用東南西北反覆走一步，也只是把連續空間切成更碎的房間。
目前較能保留開放世界的工作解法，是讓三種移動意圖共用同一份位置、速度、碰撞與
地形規則：

| 玩家此刻想做的事 | 玩家指定什麼 | 世界實際推進什麼 | 文字表面持續顯示什麼 |
| --- | --- | --- | --- |
| 靠近 | 當下仍可感知的人、物或地形位置 | 向目標目前或最後可感知的位置連續移動；目標可移動、消失或變得不可達 | 相對距離、遮蔽、途中出現的人物與物件，以及是否已進入可接觸範圍 |
| 探索 | 一個連續方向，不要求先有命名目的地 | 沿該方向移動，直到玩家停止、遇到阻礙或被新的局部事實改變判斷 | 原本看不見的世界逐步進入感知，身後事物逐步離開，不跳到下一個「房間」 |
| 旅行 | 已知地點以及人物確實知道或能採用的路線 | 沿世界中的路線前進；時間、地形、阻斷與其他行動照常成立，玩家可中途改變或停止 | 目前所在的路段與局部世界，而不是一篇自動生成的旅途紀錄或瞬間抵達畫面 |

三者不是三張地圖或三個模式。它們只是同一個移動系統收到的不同意圖；玩家可以在
旅行途中停下接觸一件物品，也可以因人物改道而把「靠近」改成自由探索。NPC 同樣能
靠近某物、朝一個方向搜索，或沿自己知道的路線旅行，不能另外使用跳格或穿牆規則。

### 文字如何保留空間感

主畫面不顯示 `x=412, y=87`，也不需要把世界分成 `房間 12`。它顯示的是從玩家當下
感知推導出的相對空間事實，例如「伸手可及」、「在近處」、「隔著某個實體」、「正
在靠近」、「正在遠離」與「沿某條可見路線更遠處」。這些不是固定區域；人物移動時
會連續跨過它們，文字在原位置更新。

- 點仍可感知但碰不到的人或物，表達的是**嘗試靠近**，不是遠距接觸，也不是瞬移。
- 進入接觸範圍後，同一個人或物才取得接觸可能；不必切換到另一個房間頁。
- 想往沒有命名目標的未知處走，必須另有能指定連續方向的輕操作。確切是拖曳、按住
  或其他手勢仍未定，但這個能力不能省掉；否則「開放世界」會退化成可選地名清單。
- 遠方已知地點不應占據當下局部世界表面；它屬於人物記得的地方與可採用的路線。
  選定它只建立旅行意圖，不能把角色直接換到目的地。

### 阻礙不是錯誤訊息

第一個原型可先採最容易反證的局部規則：靠近或自由探索若被實體阻擋，移動停在真實
接觸邊界，阻擋物與可感知的開口重新成為現在的世界事實；系統不暗中替玩家穿越未知
區域或完成全域繞路。這只是一條原型測試規則，不是把已被覆蓋的 2D 點擊操作重新宣告
為使用者決定。

沿已知路線旅行則不同：人物可以依自己確實知道的路線持續前進，因為路線本身就是
世界物件與人物知識，不是介面憑空提供的全知尋路。路線中斷、封閉、失去辨識條件或
人物被別事吸引時，旅行意圖也必須改變或失敗。

### 反證條件

- 玩家只能在已命名地點間選擇，無法朝未知方向探索；
- 人與物只是從一個文字區塊突然消失、在另一個區塊突然出現，連續位置不影響體驗；
- 靠近、探索與旅行最後都變成同一個「選目的地後等待」按鈕；
- 長途移動不是反覆輸入無意義方向，就是不受時間、地形與阻斷影響的偽裝瞬移；
- 玩家到達接觸距離前就能遠距取得完整動作，或已經貼近仍無法理解自己為何碰不到。

若上述問題成立，後端即使保存再精密的座標也沒有用；玩家表面仍不是一個可生活的
連續世界。

## 空間不是附近清單，也不必靠二維排字

狀態：**已否決（2026-07-16）。**

否決原因：為了避開房間清單、事件流與敘事段落，把文字表面矯枉過正成難讀的
「關係式現況片段」。使用者指出方案本身難懂且不應矯枉過正。本節以下只保留作負面
證據，不再作候選方向。現行「回文字」決定仍有效；被否決的是把空間強制編碼成關係
資料表，不是文字作為正式玩家表面。

2026-07-16 以 390 × 844 手機視窗實際打開現行前端：登入卡覆在主畫面上；暫時只在
瀏覽器內隱藏登入卡後，露出的舊表面是上方時刻、中間持續追加的重連事件、下方四條
人物數值。這份實物證據說明現行三區外框的中心其實是事件紀錄，不是局部空間；不能
只把格子、方向鍵或舊描述換成新詞，就當作回到文字後的主畫面。

手機上的文字若照 `人物／物件／出口` 分類往下列，玩家得到的是附近資料庫；若把字詞
依座標散放在二維平面，又只是把圖示換成字的地圖。兩者都漏掉真正有用的空間資訊：
**什麼在玩家與目標之間、什麼能直接碰到、什麼從哪裡延伸出去，以及移動後這些關係
怎麼改變。**

目前較值得反證的方向，是把當下局部世界投影成一組**有前後關係的現況片段**。這裡的
「投影」白話就是：後端仍保存真實座標、距離、遮蔽與移動，畫面只把玩家此刻確實能
感知、而且足以影響行動的那部分翻成文字。主表面保持單欄閱讀，但不用分類標題取代
空間；每段世界事實本身說出物件彼此的關係。

同一份抽象局部狀態可以呈現為：

> 【路段】｜前行中  
> 【物件甲】｜手邊  
> 　　其後：【人物乙】｜遠離中  
> 　　　　乙身旁：【通道丙】｜延伸至視線外

括號內只是可被接觸的世界實體佔位符，不是故事內容。這四句比「附近物件：甲、乙、
丙」多保留了三件事：物件甲位於玩家與人物乙之間；人物乙正在改變相對位置；通道丙
延續到目前感知之外。它也沒有聲稱玩家是世界中心；這只是從玩家當下感官得到的局部
視角，畫面外的人與事仍依自己的規則繼續存在。

### 同一實體只出現一次，關係在原處改變

人物乙不能同時被複製到「人物」、「遠處」、「正在移動」三個區塊。它只在目前最能
說明其位置的關係句中出現一次；距離、遮蔽與活動都是附著在同一實體上的現在事實。
玩家或人物移動時，這一行盡量留在原處，由剛剛可感知的變化銜接成新的現在：

`隔著物件甲看見人物乙`  
→ `人物乙走到物件甲旁`  
→ `人物乙已在伸手可及處`  
→ `人物乙從身側經過，正在落到身後`

後端位置仍然連續，不因這四種文字而切成四格。文字只在跨過玩家能實際分辨、而且會
改變可行動性的關係時更新；不能把每一小步都翻成閃爍句子。這是文字表面對「順暢
移動」的最低要求：玩家看見關係連續改變，而不是一個名字從遠處清單消失、突然跳進
近處清單。

### 排列規則不是固定樓層

第一版原型不應預先固定「伸手可及／近處／遠處」三個永遠存在的面板。固定面板會
重新變成分類清單，而且沒有內容時留下大量空殼。只在真實空間關係成立時，才生成
必要的關係句：

- 實體直接可達時，句子說明它與玩家或當前動作的直接關係；
- 中間有別的實體時，先寫阻隔或承接物，再寫其後的目標；
- 道路、門口、林緣、岸線等會把空間向外延伸的實體，負責承接更遠處，而不是另列
  一排「出口」；
- 只被記得、目前看不見也聽不見的地點，不混入當下局部表面。

因此它在資料上接近一張關係網，但玩家不該看到節點線、座標或除錯樹。畫面仍是短的
世界事實與少量縮排；縮排只在「隔著某物看見另一物」這類從屬關係真的存在時使用。確切
字級、留白、線條、觸控回饋與視覺質感仍屬後續同資料原型，不在這一節偷渡定案。

這些片段也不是自動敘事。介面不補氣氛、不替人物下心理結論、不把連續狀態潤成一段
可閱讀的小說；每一行只回答「哪個世界實體，現在和什麼有何關係或正在做什麼」，並
保留那個實體作為可指向對象。若拿掉實體與關係後只剩好看的文句，便已偏回讀故事。

### 接觸與移動不能被排版取代

句中的人物、物件與地形實體必須保留成同一個可指向的世界對象，但「可指向」不等於
遠距萬能按鈕。玩家指向一個尚不可及的實體，只能形成靠近、注視、呼喊或其他受當下
條件限制的嘗試；進入接觸範圍後，才可能真正「摸」到。確切由單擊直接接觸、先聚焦
再選動作，或用其他輕操作表達，仍需原型比較，不能由這份文字排列擅自決定。

朝未知方向探索也不能被關係短句吃掉。短句負責呈現目前感知到的空間，另有一個尚未
定形的連續方向操作負責讓玩家走向沒有命名目標的地方；否則不論文字排得多漂亮，世界
最後仍只是可點選的已知名詞集合。

### 反證條件

- 玩家第一眼仍把畫面讀成物件選單、任務文字或系統產生的敘事段落；
- 玩家無法從句子判斷哪個實體擋在中間、哪個可接觸、哪條空間關係會在移動後改變；
- 實體一移動，整段文字大幅重排，玩家必須重新搜尋名字，反而比清單更失去方向；
- 實體稍多就產生多層縮排與長句，畫面退化成資料樹或讀不完的小說；
- 玩家只能點已出現的名詞，仍無法朝未知處探索；
- 為了讓玩家看懂局部位置，最後仍必須常駐一張小地圖或房間出口表。

若上述任一問題普遍成立，就表示「關係式現況片段」沒有真正承載空間。下一輪應拿同一份
局部世界資料，直接比較關係式現況片段、純附近清單與文字二維散佈，量玩家能否回答「誰在
誰後面、先碰到什麼、往前走會如何改變」，而不是用不同文案或美術品質掩蓋結構差異。
