# 06 NPC 生活模擬

## 2026-07-24 人物已進入同一上游供應與有限市場

人物生活不只在活動欄顯示「工作／交易」。54 個市場已有共 3,780 筆不會因重啟補滿
的有限庫存；居民會依 Azgaar 來源留下的供給、需求及 478 條市場流向，實際改變同一份
商品與鎂：

- 4,976 筆允許的 Azgaar `Burg → Market` 來源交易已落在 277 個正式場所，每處都有
  一個 operational 供應站及真實受派的「地方供應人員」；目的市場金庫支付工資。
- 人物必須抵達來源地才能供應；同地商品直接入庫，異地商品成為
  `origin_kind=producer` 的貨運，由這名居民沿正式路線承運。市場工作不再直接產貨。
- 居民使用自己的鎂購買有需求的消耗品；成交先改變庫存與金庫，再把商品寫入明確的
  consumption sink。玩家與居民使用同一市場結算。
- 起點過剩、終點短缺時，受派居民先從起點扣貨，沿正式路線搬到終點；承運人是正在
  世界裡移動的同一名居民，不是背景計數器。
- 市場經手者必須存活、在場、正式受派且沒有正在承運；GUI 會保留可交易者，不會把
  他折入「其餘人影」。玩家實際抵達後可點選、出價、扣款並在背包看到商品。
- 人身商品與舊 `mat_*`／柴枝束／粗礦不進 active 經濟；currency 仍保留來源與市場
  證據，但不進個人報價，避免「買一份錢幣」。

決策 015 的閉環驗收窗已有 557 筆歷史供應、618 筆消耗及 31 筆完成貨運；決策 016
保留這些帳本，並以新的上游供應帳接續，逐商品守恆差額仍為 0。
無玩家連線時這些行動仍推進，冷重啟沿用當下庫存。手機 390px 與桌面 1440px 已實際
完成市場接觸與背包驗收。登入後同場相遇紀錄改在背景寫入，不再讓密集市場出現畫面
已就緒、點擊卻排隊的假可用狀態。這證明居民已能在來源工作、消耗、供應和搬運同一
有限世界；不
代表完整奇幻現代產業、服務、家庭、生死、政治或半島人口已完成。

## 2026-07-21 活世界連續性校正

重新讀取 PostgreSQL 後，先前「1,553 名 NPC 已自主生活」的說法只能證明迴圈在跑，
不能證明人物是活人：1,553 人全部顯示「正在採集」，全部鎂為 0；決策程式把
`鎂 < 50` 寫成採集硬優先，因而截斷工作、社交、休息、性格與既有持物。另有
55,234 筆相遇記錄，但正式指派只有 2 筆，排程、dyad、thread 與 summary 均為 0。

本輪不以隨機活動修飾這個問題。現行垂直切片改為：

- 所有已建立的 player／npc 都有 `resident_continuity`；只有 npc 是 autonomous，
  玩家仍由本人輸入控制。
- 自主人物保存當前意圖、原因、目的地、阻塞、開始時間與 `next_wake_at`；服務重啟
  讀回同一狀態，未到期不重抽決策。
- 低鎂人物若已有可交換持物，交易是候選而不是繼續無條件採集；真實排程與指派仍
  有較高權重，休息、社交與走動保留競爭。
- 玩家與居民的 `move`、`trade`、`work` 走相同世界規則；世界變化與對應收據在
  同一交易完成。先前用於驗證守衡的 `gather` 介面仍保留，但白塔舊 P0 來源已停用。
- 指派只從現有 2 筆資料形成 obligation；關係只從實際 meet_count／同場相遇形成；
  家庭、職業與承諾沒有證據就保持空白。

完整邊界、反證與來源映射見 wiki「活世界與玩家接縫 v1」及
`data/world/white_tower_living_world_v1.json`。

部署後的 2026-07-21 13:12:38 READ ONLY 快照已驗證：1,574 名人物全部有 continuity，
1,553 名 NPC 全部由 autonomous 到期事件接續；活動分成走動、交易、社交、觀察、
休息、採集與公共場所停留，不再是 1,553 人同時採集。另以 5 名尚未到喚醒時間的
居民做冷重啟比對，其意圖、目的地、喚醒時刻、版次與最後行動逐欄不變。玩家 GUI
亦已在 1280×720 真實登入目視，能同場看到不同活動並點入人物讀到當下狀態。這只
驗收本輪生活連續性與玩家接縫。其後同日已關閉柴枝束等舊 P0 的玩家顯示與新產生
路徑；粗布、草鞋等既有背包污染仍是待清理資料債，不是奇幻現代物資定案。

## 2026-07-19 方向收斂與第一個 runtime 閉環

> 所以我要的是活的世界，把資源堆在如何讓每個人物都是活人

使用者當時隨後補正：

> 紀錄，但，生活的世界都還沒定案

這句在 2026-07-16 阻止了助手把探索材料偷升成定案；但它不是永久否決。使用者
其後明確要求：

> 世界架構起來
>
> 人物自主動起來
>
> 整個世界活的

後來的明確要求取代早期候選狀態。活世界現在的最低要求是：人物有真實位置與
狀態，能在沒有玩家連線時依世界條件自主選擇並執行行動，行動改變同一份世界資料，
關係與記憶會累積，服務重啟後從持久狀態接續。解析度、LLM、家庭與生死範圍仍可
逐步驗證，但不能以它們未定為理由讓世界停著等玩家。

### Usurper Reborn 採用邊界

[Usurper Reborn](https://github.com/binary-knight/usurper-reborn) 提供了一個可研究
案例；其承重鏈不是「會聊天的 NPC」，而是：

1. 人物先成為有位置、持有物與生命狀態的世界實體；
2. 個性、需求、目標、記憶與關係共同影響選擇；
3. 選擇轉成工作、移動、交易、結盟、成家、衝突等世界行動；
4. 行動改變資源、關係、家庭、社會與其他人的下一步；
5. 老化、出生、死亡、新聞與持久化讓改變跨越玩家當下視野。

2026-07-19 直接檢查原始碼後，奇點採用的是這條完整因果鏈與 24/7 運轉口徑，
不是直接搬碼。Usurper 的世界位置仍是硬編碼 C# 表，NPC 行動另走大型專用
dispatcher，且原始碼採 GPL-2.0；這些都不適合成為奇點的世界骨架。奇點保留
Rust／PostgreSQL 現有架構，讓居民使用實際可達的世界連結，把位置、活動、行動
結果與關係寫回同一個資料真相。

### 正式白塔 runtime 閉環

2026-07-19 先把既有方格 NPC 模組接成可持久運轉的居民迴圈：多人可以同處一個
場所，居民依固定批次公平輪轉，只沿實際出口移動，會依排程、工作、休息、採集、
社交與可達地點選擇下一步；位置與活動寫回 PostgreSQL，社交抵達會累積雙向相遇
記憶。無 WebSocket 玩家連線時，1,553 名 NPC 的位置、活動、事件與人物記憶仍
持續改變；重啟服務後從資料庫現況接著推進。

這個過渡缺口已於 2026-07-20 由決策 013 關閉：完整 Azgaar 作者資料被分類後編譯成
305 個正式可通行區域與 1,644 條路線，1,574 名實體與 1,555 筆旅程一次遷入；119
個舊格與 304 條舊出口全部退出 active 世界。遷移依原相對位置確定性映射，逐人保存
舊場所、座標、room 與旅程，可回復而不是任意安置。

1,553 名 NPC 現在於同一份白塔 PlaceGraph 上自主移動、找工作、工作、交易、休息與社交；
活動、原因、目的地、剩餘路徑與後果全部持久化，人物已產生的思考也會持久保存。
無玩家連線時仍持續推進；冷重啟後保留既有旅程與思考，再從同一世界接續。這證明正式底盤與居民生活已接通，
但不宣稱 1,553 人等於白塔半島全部人口，或家庭、生死、政治與完整經濟都已完成。

### 後續審辯紀錄（助手提案，未獲採納）

助手曾把可比較的路線整理為三個候選：

1. 每個人物都具備高頻、完整的 AI 推理；
2. 以家庭、機構或人口群體作批次生活推演；
3. 讓人物保有可持續、可追查的因果狀態，再依距離與事件重要性改變推演精度。

助手暫時偏向第三項，並把它稱為「人物因果主幹」。這個名稱、偏好與三分法都
是助手的分析工具，不是使用者的定名、決定或架構需求。

當時也提出兩個候選反證測試：讓一名人物在無玩家觀測下經過 24 小時，檢查其
變化能否由既有世界事實解釋；或移除一名人物，檢查世界是否留下可追查缺口。
這兩項只是幫助往後比較方案的提問，不是已通過的驗收規格。

## NPC 定位

NPC 是世界居民，不是功能按鈕。先設計「人正在過日子」，再從其中產生交易、問答、衝突與合作。

## 外部研究校準

`Generative Agents` 的可取部分不是讓 NPC 亂生成文字，而是把可信行為拆成觀察、記憶、規劃與反思。奇點的文件層只採用玩家可見版本：NPC 要有目的、去處、持物、事件記憶或行動痕跡；若玩家完全看不出這些差異，後端再複雜也不能算 NPC 生活模擬。

## NPC 最低狀態

| 狀態 | 玩家可見方式 |
|---|---|
| 位置 | 在場、缺席、剛走、正在路上 |
| 持物 | 手上、身旁、背著、放下 |
| 鎂/資產 | 交易時可見，不必常駐顯示 |
| 目的 | 行為、動作、詢問後透露 |
| 去處 | 路線、等待、跟隨、缺席痕跡 |
| 關係 | 稱呼、報價、拒絕、幫忙、記得 |
| 事件記憶 | 之後對玩家行動有反應 |

## NPC 行為來源

NPC 行為應來自：

- 工作。
- 等待。
- 搬運。
- 交易。
- 休息。
- 避險。
- 守物。
- 找人。
- 找物。
- 回家或赴約。
- 對玩家過去行動的反應。

## 同規則要求

玩家能做的核心世界動作，NPC 應有同構版本：

| 動作 | NPC 表現 |
|---|---|
| 走 | 自己改變位置並留下缺席/抵達痕跡 |
| 拿/放 | 改變物件與持物狀態 |
| 買/賣 | 改變鎂、物品、需求、價格感 |
| 用/修 | 改變物件狀態 |
| 等 | 在某地佔用時間或隊列位置 |
| 問/說 | 由狀態與關係驅動，不輪播 |
| 避/戰 | 對風險與衝突作反應 |
| 處理元素局勢 | 點燈、收棚、改路、封路、搬貨、清障、拒收或搶先使用工具 |

## NPC 與玩家的競合

NPC 必須能讓玩家感覺世界不是等玩家啟動。

競合例：

- NPC 先買走需要的物品。
- NPC 先完成某個需求。
- NPC 阻擋路線。
- NPC 因玩家讓位而記住玩家。
- NPC 因玩家插手而不信任。
- NPC 對同一物件有使用權或歸屬。
- NPC 因玩家處理或誤用元素局勢而請託、阻止、求償或承認玩家。

## NPC 與元素

NPC 的元素反應必須是行動，不是台詞。

合格表現：

- 雨後有人把貨移到棚下。
- 霧重時引路人提高報價或拒絕帶路。
- 雷暴前渡工停船、守路人封路、搬運者收工具。
- 玩家點亮燈架後，某 NPC 改從暗處經過或允許玩家查看物件。
- 玩家錯用火源後，守倉人要求賠償或不再讓玩家靠近。

不合格表現：

- NPC 隨機說「今天霧很大」但位置、持物、交易、路線與記憶都不變。

## 對話規則

NPC 對話有價值的條件：

- 回應當前狀態。
- 回應玩家關係。
- 提供線索。
- 表達目的。
- 改變後續選項。
- 留下事件記憶。

禁止把 NPC 做成隨機台詞播放器。

## NPC 顯示規則

玩家未知道姓名前，不直接顯示真名。顯示應依觀察層級：

- 陌生人。
- 可觀察身份。
- 已知姓名。
- 與玩家有關係的稱呼。

人群可折疊，但不得顯示精確人數。
