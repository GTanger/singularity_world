# 02 UI 與輸入設計

> **狀態補正（2026-07-13）**：本檔原本以手機文字 MUD 為主要畫面，
> 此前提已被 [21-2d-open-world-primary-surface.md](21-2d-open-world-primary-surface.md)
> 取代。本檔只保留零指令映射、資訊分工、動作面板與事件回饋等支援層；
> 下列版面不能再作新主畫面規格。

## UI 目標

奇點 UI 目前以 2D 平面大地圖為主要操作面。它仍要讓玩家用手指完成看、
走、拿、用、問、買、賣、戰、等、委託，而不要求輸入命令；本檔後續
條目只定這些意圖如何低摩擦映射，不定大地圖外觀。

## 外部研究校準

Will Wright 的模擬遊戲 UI 觀點提醒：模擬模型、玩法、UI、玩家心智模型要一起設計。奇點的 UI 因此不能只是把後端欄位排出來，而要讓玩家立刻建立「我在哪、我有什麼、我能碰什麼、為何現在要做」的心智模型。

Emily Short 對文字互動輸出的要求也適用於奇點：畫面輸出要把玩家互動所需的世界模型資訊凸顯出來。時間、天氣這類全局上下文應獨立置頂，因為它們重要、會變、會影響許多動作，但不應和場景正文混成同一段。

## 第一屏資訊分工

| 區域 | 內容 | 禁止 |
|---|---|---|
| 全局上下文 | 時間、天氣、必要節奏 | 不混成場景正文，不與地點描述黏在一起 |
| 自身入口 | 姓名、角色面板、錢、背包、工具、近期事件、當下會影響選擇的元素關係 | 不把玩家本人放成場景人物卡；不把背包、錢、工具拆成姓名旁邊一排雜訊；不顯示抽象元素條 |
| 場景狀態 | 當前格局勢、人物、物件、出口、痕跡 | 不寫無狀態散文，不露後端語言 |
| 動作層 | 點人/物/出口後出現的可用動作 | 前端不得猜動作；依後端狀態給出 |
| 事件流 | 玩家行動與自然察覺的結果 | 不推系統 debug，不刷 NPC 雜訊 |

## 零指令映射

| 傳統 MUD 意圖 | 奇點操作 | 設計要求 |
|---|---|---|
| look/examine | 點場景、人、物 | 顯示狀態、風險、可用動作 |
| move/go | 點 L4 出口或路徑 | 顯示目的地名與路況，不恢復方向欄 |
| inventory/status | 點玩家姓名/自身入口 | 顯示錢、物、工具、狀態、近期事件 |
| get/drop/use | 點物件後選動作 | 依條件成功或失敗 |
| talk/ask | 點人物後選問/說 | 對話必須依人物狀態與關係，不輪播 |
| trade | 點人物/物件後交易 | 顯示供需、報價、持物與成交結果 |
| fight/flee | 點危險人物/事件 | 事前給風險與避開選項 |
| wait/follow | 點人物/路況/隊列 | 推進時間或建立跟隨狀態 |

## 第一屏入口數

第一屏核心入口最多 6 個。超過 6 個時，要用以下順序取捨：

1. 出口/路況，因為移動是 MUD 基礎。
2. NPC 同規則行動者。
3. 可改變狀態的物件。
4. 工具/熟練入口。
5. 經濟入口。
6. 風險或可維護物件。

純背景物、純氛圍物、不能改變狀態的物件不進核心入口。

## 自身面板

姓名是玩家自身入口，不只是顯示文字。玩家不應在場景人物列表裡看見自己；也不應把背包、錢、工具拆成姓名旁邊一堆小物件。點姓名/自身入口後，才展開自身面板。

自身面板最低顯示：

- 姓名。
- 所在地。
- 鎂。
- 背包摘要。
- 手持/工具。
- 傷勢或明顯狀態。
- 當下會改變可用動作的元素關係，例如手持火源、可包覆工具、可固定工具、已知路況。
- 近期事件 3 條以內。
- 離線安排狀態。

自身面板不是資料庫頁。它要回答玩家「我現在能靠什麼活」。

自身面板也必須提供至少一個簡單自身動作，例如查看近期事件、整理手持、握持/收起工具、休息、等待或設定離線安排。若點自己只能看到欄位，不能讓玩家改變任何狀態，它還不是第一個可玩核心。

元素相關資訊只在會改變玩家選擇時顯示。UI 不顯示火/水/風/土數值，也不顯示後端環境欄位；它只顯示玩家能理解並操作的工具、持物、風險提示與可用動詞。

## 動作面板

點人物或物件後，動作面板應包含：

- 觀察結果。
- 可用動作。
- 不可用但可理解的原因。
- 可能風險提示。

不可用動作不一定要顯示；若顯示，必須是玩家可理解的世界原因，例如工具不足、對方不信任、時間不對、物件被佔用。

## 事件流

事件流只記錄：

- 玩家動作結果。
- 玩家在場自然察覺的局部事件。
- 重要狀態變化。

事件流不記錄：

- 後端 tick。
- NPC 資料表狀態。
- 精確人群數。
- 「世界尚未接入」之類後設語。
