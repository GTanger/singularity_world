# 03 場景卡與文字設計

## 場景卡定位

場景卡不是房間介紹。場景卡是玩家進入一個局部世界時看到的「可判讀狀態」。

## 外部研究校準

Emily Short 的 world model 原則可轉成一條硬規則：如果某個狀態不能在文字中被玩家看懂，或看懂後不能改變玩家選擇，就不該被當成核心設計成果。場景卡的文字不是裝飾，它是世界模型的渲染結果。

一張合格場景卡要讓玩家能判斷：

- 這裡目前發生什麼。
- 這個目前狀態由什麼沿革推到此刻。
- 上一秒、上一 tick 或上一動作造成了什麼差異。
- 誰在做事。
- 哪些物件可利用。
- 哪些路安全或不安全。
- 玩家自身、持物或工具如何改變此地可用動作。
- 有什麼正在變化或可能錯過。
- 我現在做哪件事比較有利。

## 場景卡結構

| 層 | 功能 | 設計要求 |
|---|---|---|
| 時間 | 世界節奏 | 獨立呈現，不混成場景句 |
| 氣候/環境 | 區域條件 | 影響物件、路況、NPC 行為 |
| 場景狀態 | 當前局勢 | 以狀態為主，不寫純散文；必須能追溯歷史/沿革 |
| 即時歷史 | 上一秒、上一 tick 或上一動作留下的事實 | 改變人物、物件、路況、價格、規矩、風險或可用動詞 |
| 玩家接點 | 自身、持物、工具、熟練、關係如何接上此地 | 只呈現會改變選擇的資訊，不顯示後端欄位 |
| 入口列表 | 人物、物件、出口 | 入口必須可點或可判斷 |
| 事件流 | 行動與痕跡 | 追加結果，不取代狀態 |

場景卡上的歷史不是一段附錄，也不是只用「痕跡」兩字帶過。昨天與前一秒都要能落到現在狀態：誰站到哪裡、哪個物件被用過、哪條路被改變、哪個價格被壓、哪條規矩剛生效、哪個動詞現在可用或不可用。

## 動態現象

動態現象是狀態投影，不是隨機修辭。

來源：

- 時辰。
- 天氣。
- 地形。
- 水域/道路/建物。
- 人流。
- 近期事件。
- 玩家曾做過的事。

例：

- 河霧：水域、濕度、時辰造成。
- 泥濘：雨、路況、車馬或人流造成。
- 擁擠：時間、隊列、交易、事件造成。
- 安靜：人群離開、危險前兆、店鋪收起造成。

## 文字可寫什麼

文字應呈現：

- 狀態。
- 風險。
- 可行動作。
- 後果。
- 關係。
- 痕跡。
- 缺席。
- 時間壓力。

## 文字不可寫什麼

文字不可用來：

- 創造不存在的物件。
- 創造未落地 NPC。
- 補救沒有機制的場景。
- 讓 NPC 發無意義輪播台詞。
- 把材料用途寫成百科。
- 把歷史寫成背景、遺跡或殘留物，卻不改變當前狀態。
- 把 debug 或資料庫摘要寫給玩家。

## 場景卡模板

```text
場景名：
尺度：
時間/氣候如何影響此地：
穩定骨架：
當下局勢：
造成當下局勢的沿革（不是殘留物，而是現在狀態成因）：
已成為歷史的上一秒/上一 tick/上一動作事實：
在場人物：
缺席/痕跡：
可互動物件：
出口與路況：
玩家自身/持物/工具如何改變選項：
玩家可立即做的事：
NPC 會自行做的事：
下一秒若玩家不介入會怎樣：
可錯過：
回訪差異：
```

## 合格與不合格

合格：

- 「雨後路口泥深，貨車停在石邊；搬運者把木箱改走棚下，守路人不讓空手者靠近。」
- 玩家可判斷：路難走、貨流改變、有人守、可能需要工具或關係。

不合格：

- 「雨後的路口帶著潮濕氣息，人聲在遠處起伏。」
- 玩家無法判斷可做什麼。
