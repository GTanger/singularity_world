相鄰文件：[05-character-tools-growth.md](05-character-tools-growth.md)、[10-combat-conflict-risk.md](10-combat-conflict-risk.md)、[15-elements-fantasy-gameview.md](15-elements-fantasy-gameview.md)、[16-player-fantasy-affordances.md](16-player-fantasy-affordances.md)

## 定位

本章回答一個問題：

```text
元素如何成為角色扮演，而不是自然現象、傷害顏色或場景氛圍？
```

奇點的答案是：

```text
元素 = 玩家角色與奇幻世界規則接上的介面。
```

它必須落到玩家自身、持物、工具、熟練、已知規則、位置、關係、NPC 同律與世界後果。

玩家不是讀到「這裡有雷」。玩家應該能判斷：我這個人此刻拿著什麼、知道什麼、能不能靠工具處理、會不會被阻止、是否值得冒險、做了之後誰會記得、下次回來什麼會變。

## 禁止先回答的方向

- 不先回答自然成因。
- 不把元素寫成身體感覺。
- 不把元素寫成玩家面板上的四條需求條。
- 不把元素只寫成戰鬥傷害類型。
- 不把元素當作場景文學修辭。
- 不把元素角色寫成一開始選職業或天生屬性。

自然成因可以在世界支撐層存在，但玩家層第一順位永遠是：看見、選擇、操作、後果、承認。

## 角色扮演層級

元素與玩家角色的關係分成五層。

| 層 | 問題 | 玩家可見表現 |
|---|---|---|
| 自身 | 我現在是誰、帶著什麼、知道什麼 | 自身面板顯示手持/工具、明顯狀態、近期元素相關事件 |
| 判讀 | 我能不能看懂局勢 | 文字揭露路況、貨況、工具適不適合、NPC 正在怎麼反應 |
| 動詞 | 我因此能做什麼 | 點火、熄火、包覆、排水、避雷、築、堵、示警、救援、利用 |
| 承認 | 世界如何記住我 | NPC 報價、稱呼、信任、拒絕、委託、路線經驗、工具熟練 |
| 痕跡 | 我做完後留下什麼 | 物件狀態、封路/通路、焦痕、貨況、告示、關係、下次回訪差異 |

若一個元素內容只落在「判讀」而沒有「動詞」與「後果」，它只能當場景狀態，不是角色扮演玩法。

## 元素不綁職業

奇點不需要玩家創角時選 `火系 / 水系 / 雷系`。

元素關係應從世界行動長出來：

| 來源 | 如何形成角色差異 |
|---|---|
| 持物 | 玩家手上有火種、油布、繩、木盾、排水工具、標記物，能做的事不同 |
| 工具 | 工具打開或封鎖元素動詞，例如照明、遮蔽、排水、固定、導引、修補 |
| 熟練 | 玩家能看出更細狀態、失敗原因更清楚、可做第二層動作 |
| 已知規則 | 玩家知道某地何時停船、哪種貨不能久放、哪些路遇風會改向 |
| 關係 | NPC 因玩家曾處理某類風險而信任、請託、阻止或求償 |
| 位置 | 玩家站在高處、水邊、棚下、路口、倉旁，能做與承擔的事不同 |
| 歷史 | 玩家曾點燈、救人、修路、弄壞貨、趁亂交易，世界留下記錄 |

這樣玩家可以逐漸形成「會處理火源的人」「熟水路的人」「懂避雷和封路的人」「常修土石邊界的人」等社會認知，但這是行動與世界承認的結果，不是職業選單。

## 元素關係卡

任何要進核心玩法的元素內容，都必須填完這張卡。

```text
名稱：
元素/狀態：
玩家當下身份關係：
玩家怎麼看見它：
自身/持物/工具如何改變可用動作：
可用動詞：
被封鎖或變貴的動詞：
NPC 同規則行動：
成功後世界差異：
失敗或不處理的世界差異：
誰會記得或承認：
下次回訪可見痕跡：
第二次再遇時有何不同：
```

這張卡是 [15-elements-fantasy-gameview.md](15-elements-fantasy-gameview.md) 的角色扮演版本。15 回答元素如何改世界狀態；本章回答玩家如何以一個角色接上那些狀態。

## 第一屏最小核心

第一屏若要接元素，不應直接丟出大天候或元素表。它只需要一個可玩單位：

```text
玩家看見自身入口。
玩家點自己。
玩家看到手持/工具和一個可理解的元素局勢。
玩家做一個自身或工具動作。
世界改變一個事實。
畫面回饋結果。
```

合格例：

```text
自身：codex，手上有火折與半卷油布。
場景狀態：雨後，臨時燈架未點，棚邊兩袋乾草被搬到暗處。
可做：點自身 -> 握持火折；點燈架 -> 點燈。
結果：燈架亮起，棚邊出口變得可辨，守棚人願意讓玩家先看一眼暗處的貨。
後果：火折耗一次，事件流記錄「你點亮了棚邊燈架」；下次回訪若燈未滅，該處仍較容易辨路。
```

這個例子裡，「火」不是火焰物理，也不是火傷害；它是角色手上工具、場景黑暗、NPC 反應、出口辨識、工具消耗與回訪痕跡的連接規則。

不合格例：

```text
夜雨微涼，火光在霧中搖曳。
```

這可以當輔助文字，但沒有入口、動詞、代價、NPC 同律或世界差異。

## 元素動詞庫

元素動詞不是技能名，而是玩家/NPC 能對世界做的基礎動作。

| 元素/狀態 | 起手動詞 | 角色扮演用途 |
|---|---|---|
| 火 | 點、滅、照、烘、熏、燒、驅、示警 | 照路、處理貨物、製造信號、逼退、毀壞或修補 |
| 水 | 接、排、洗、泡、渡、遮、等退、封存 | 通行、保存、清理、交易品質、延誤或利用水路 |
| 風 | 遮、順、避、放、聽、追、等、引 | 追聲、散煙、遮蔽、暴露、遠行、射擊/投擲判斷 |
| 土 | 挖、墊、堵、築、埋、採、固定、修路 | 通行、建造、守勢、藏物、採集、邊界維護 |
| 霧 | 等、靠近、跟隨、問路、點燈、標記、避開 | 探索、迷路、跟人、遮蔽、錯過、伏擊或救援 |
| 泥 | 清、墊、繞、追痕、藏痕、拖、固定 | 路況、追蹤、物流、逃避、車馬/貨物風險 |
| 雷 | 收、退、躲、封、提醒、拉走、等待、趁亂 | 風險控制、救援、封路、停渡、混亂交易、戰前判斷 |
| 毒/酸 | 辨、隔、洗、封、丟、治、利用、拒收 | 醫治、污染、交易拒收、陷阱、加工與社會責任 |

動詞庫不得直接變成 UI 全部按鈕。前端只能顯示當下後端判定可用、且玩家能理解的動詞。

## 元素與自身面板

自身面板不要顯示抽象元素條。它只顯示會影響玩家當下選擇的角色資訊。

可顯示：

- 手持工具：火折、繩、油布、木盾、標記牌。
- 背包摘要：可包貨、可照明、可固定、可修補的物件。
- 近期事件：點亮過、修過、誤燒、救過、被拒收、被請託。
- 明顯狀態：受傷、被拒入、被要求賠償、被允許進入、被某人記住。
- 離線安排：看守火源、等雨停、委託搬貨、留在棚下、跟隨某隊。

不可顯示：

- 火/水/風/土需求條。
- 沒有玩家決策價值的元素數值。
- 只有後端計算用的環境欄位。
- 以身體感覺取代可操作資訊。

## 元素與 NPC 同律

元素若只讓玩家可用，就會破壞 `玩家 = NPC`。

NPC 在元素局勢下至少要能做四種事：

| 行為 | 玩家看到 |
|---|---|
| 利用 | 有人先點燈、搬貨、封路、搶棚、趁亂成交 |
| 避開 | 有人停船、退到棚下、收工具、改路、不接某批貨 |
| 阻止 | 有人不讓玩家靠近、不讓玩家點火、不讓玩家帶貨入內 |
| 承認 | 玩家處理得好或壞後，被請託、被稱呼、被求償、被防備 |

NPC 的元素反應不是台詞輪播，而是位置、持物、行動、報價、委託、拒絕與記憶改變。

## 元素與戰鬥

戰鬥中的元素不能只做傷害顏色。它要先改變戰前判斷。

| 層 | 設計要求 |
|---|---|
| 前兆 | 玩家看得出局勢，能選擇靠近、撤退、準備、求援或等 |
| 裝備/工具 | 持物與工具影響能不能進場、能不能避開、能不能保護或利用 |
| 地形/物件 | 火源、水邊、霧、泥、障礙、棚、牆、路口都能改變自動結算前條件 |
| NPC 同律 | NPC 也能利用或避開同一局勢 |
| 戰後痕跡 | 不是只扣血；還要留下物件損壞、路況、關係、目擊與風險後果 |

自動戰鬥 log 應呈現玩家事前選擇的差異。例如玩家先點燈、先避開泥地、先收起某工具、先求援，戰報就應有不同原因，而不是同一段戰鬥文字換傷害數字。

## 元素與經濟/經營

元素讓物資、場所、工具與信用不再是靜態表格。

| 經濟層 | 元素接法 |
|---|---|
| 物資品質 | 貨物是否可收、可存、可加工、可轉賣 |
| 保存方式 | 包覆、烘乾、封存、隔離、降溫、通風等成為工具和場所需求 |
| 場所維護 | 棚、燈、渠、路、牌、箱、倉位要被維持 |
| 報價 | 風險、時間、關係與貨況改變報價 |
| 信用 | 玩家處理元素局勢的歷史會影響是否被委託或賒欠 |

經營不是把元素變成煩人日課。元素只在會創造選擇、代價、收益或痕跡時進核心。

## 元素與探索

探索不是開圖，而是學會局部世界規則。

元素探索成果包括：

- 哪種時段某路能走。
- 哪種天候某人會停工或改路。
- 哪類工具能打開某條捷徑。
- 哪種物件狀態代表危險快來。
- 哪個 NPC 知道處理方法。
- 哪個場所能讓玩家等待、避開或利用元素局勢。

探索成果應進入已知路線、已知人物、近期事件或地方信用，而不是只追加一條百科筆記。

## 內容驗收

任何角色扮演元素內容進入第一屏、場景卡、物件、NPC、戰鬥或經濟前，必須通過以下檢查：

1. 玩家能否從畫面讀到元素局勢，而不是看後端欄位。
2. 玩家自身、持物、工具、熟練、關係或位置是否改變可用動作。
3. 玩家至少能做一個有代價的選擇。
4. 成功是否改變錢、物、路、人、場所、關係、風險或痕跡。
5. 失敗或不處理是否也有世界差異。
6. NPC 是否能依同規則利用、避開、阻止或承認。
7. 第二次再遇到時，玩家是否可能因準備、資訊、工具、關係或時間不同而做不同決策。
8. 刪掉元素內容後，玩家決策是否真的變少；若沒有變少，該內容只算氛圍。

## 最小實作切片建議

第一個 runtime 切片若要驗證本章，不要做完整元素系統。只做一個閉環：

```text
自身入口 -> 手持/工具 -> 一個元素局勢 -> 一個可用動詞 -> 一個世界差異 -> 一條回訪痕跡
```

候選切片：

| 切片 | 玩家做什麼 | 世界差異 |
|---|---|---|
| 點燈 | 角色握持火折，點亮某處燈架 | 出口/物件變可辨，NPC 反應，火折消耗 |
| 包貨 | 角色使用油布包覆怕壞貨 | 貨物可被收，報價/信用改變 |
| 清泥 | 角色用工具清出踏板或路口 | 通行改善，NPC 先後順序改變 |
| 收工具避雷 | 角色收起不宜外露的工具並退到低處 | 某 NPC 放行或跟隨，路線暫停但風險降低 |

這些切片都不是完整地圖，也不是完整戰鬥。它們只用來證明：元素可以從玩家自身與工具開始，變成角色扮演行動。
