# 08 世界時間與觀測

本檔負責把 `../world/world-foundation-v0.md` 的「歷史即現在態」落到 GDD 層。時間不是背景氣氛，歷史不是年表，沿革不是玩家必讀 lore，變遷也不是隨機換句話；它們共同決定當前畫面上哪些人、物、路、價格、規矩、動詞與痕跡成立。

第一權威仍是 `../../DESIGN_KEYWORDS.md`：世界永遠在線、觀測坍縮不等於時間停止、後端唯一數據真理、NPC 與玩家同規則、不可無中生有。

## 世界永遠在線

世界時間不因玩家下線或離場停止。玩家下線只是玩家停止操作角色；角色與世界仍可依簡化規則推進。

永遠在線的玩家層結果不是全世界動態報表，而是玩家重新站入一地時，看到局部事實已經前進：某人離開、某物被搬走、某條路被封、某批貨錯過保存時機、某個承諾變成欠帳或信用。

## 時間層級

| 層級 | 用途 | 玩家可見方式 |
|---|---|---|
| 即時/短 tick | 同場人物、隊列、事件流、上一秒/上一動作結果 | 卡片變化、事件結果、可用動詞改變 |
| 日內時段 | 天氣、路況、工作、危險 | 時間文字、NPC 去處 |
| 日/季節 | 供需、採集、長期事件 | 價格、缺貨、活動變化 |
| 事件時間軸 | 可追溯歷史 | 近期事件、NPC 記憶、痕跡 |

元素局勢也走時間層級：霧、泥、火源、風向、雷暴、貨況、路況會隨時間推進，但玩家看到的不是後端天氣欄位，而是可追溯事實：誰改路、誰停工、什麼物件被處理、哪條路暫時不適合走、哪個工具或熟練能改變選擇。

## 歷史、沿革、變遷

本作採用狀態鏈定義：

```text
歷史：已經發生並改變世界狀態的事。
沿革：某個地點、人物、物件、制度或價格如何一路變成現在這樣。
變遷：狀態正在往下一步改變的方向。
故事：玩家/NPC/世界規則共同產生的可追溯狀態鏈。
```

昨天是歷史，前一秒也是歷史。上一 tick、上一個玩家動作、上一個 NPC 動作、上一個天候事件、上一個交易或失敗，都可成為現在狀態的成因。

判準不是離現在多遠，而是是否已經越過當下邊界，成為下一個狀態的因。十年前、昨天、前一秒、剛點擊之後，同屬不同尺度的歷史；差別只在影響層級、可追溯程度，以及玩家下一次觀測能讀到什麼。

歷史不是殘留物。不是只有地上有遺跡、舊物、焦痕、留言才叫歷史；隊列往前挪了一人、剛有人把貨拿走、上一秒風把霧推回河面、NPC 才把門牌翻成暫停、玩家剛點亮一盞燈，這些都已經是下一個畫面的歷史成因。玩家讀到的「現在」，必須是這些已發生事實共同構成的狀態，而不是另附一段過去說明。

場景、NPC、物件、路線、經濟與事件不能只寫「曾經如何」。它們必須能回答：

```text
目前狀態：
造成目前狀態的沿革：
上一秒/上一 tick/上一動作已成為歷史的事實：
若玩家不介入，下一步會怎樣：
若玩家介入，哪個世界事實被改變：
下一次觀測會看到什麼差異：
```

例：

| 內容 | 不合格歷史 | 合格現在態 |
|---|---|---|
| 路 | 這條路由古代商隊開出 | 昨夜雨後車轍陷深，巡路人先封了重車通行；玩家可等、繞、幫鋪板或冒險通過 |
| 人 | 他年輕時是渡工 | 他剛把第二條繩繞上樁，正在改船序；玩家若插話會影響下一班船與他的信用判斷 |
| 物 | 這盞燈是老物件 | 玩家上一動作點亮後，霧裡可見距離增加，旁人可能靠過來，也可能責怪浪費燈油 |
| 價格 | 這裡以前魚貨興盛 | 今晨第一批魚受潮慢賣，午後價格被壓；玩家可趁低買、幫保存或錯過時效 |

## 外部研究校準

外部 game-design 參照只用來校準奇點規格，不取代 `../../DESIGN_KEYWORDS.md`。

- Narrative design 應把 story 接到 mechanics 與 systems；奇點採用為：故事必須能改變可用動詞、NPC 行為、物件狀態、價格、關係或回訪痕跡。
- Worldbuilding 可包含歷史與設定，但過早、過量且不服務關卡/互動的 worldbuilding 會浪費；奇點採用為：只寫足以生成當前狀態與下一步變遷的歷史。
- Story generator / simulation 類遊戲的吸引力來自玩家行動與系統產生非預寫故事；奇點採用為：玩家不是讀歷史，而是用行動把下一秒寫進歷史。
- Persistent world-state 研究強調玩家決策與互動需要持續影響世界；奇點採用為：玩家/NPC/時間造成的狀態差異必須能在下一次觀測被讀到。
- RPG game-state 觀點指出，故事可作為遊戲開始時的狀態，玩家行動後由規則產生答案；奇點採用為：歷史是 game state 的成因，描述只是回報狀態，不是作者硬講故事。

參照來源：

- GameDesignSkills, *What Is Narrative Design?*：https://gamedesignskills.com/game-design/narrative-design/
- The Level Design Book, *Worldbuilding*：https://book.leveldesignbook.com/process/preproduction/worldbuilding
- Game Developer, *Rimworld, Dwarf Fortress, and procedurally generated story telling*：https://www.gamedeveloper.com/design/rimworld-dwarf-fortress-and-procedurally-generated-story-telling
- MDPI, *Persistence and Evolution Within Interactive Design*：https://www.mdpi.com/2227-7080/13/5/179
- Grumpy Wizard, *Game State, Story, and The Truth*：https://grumpywizard.home.blog/2023/09/21/game-state-and-story/

## 觀測坍縮

觀測坍縮處理的是「玩家看到時，哪一條局部事實被承認」，不是讓未觀測世界停止。

觀測層級：

| 層級 | 例子 | 結果 |
|---|---|---|
| 未觀測 | 玩家不在場 | 以背景規則推進 |
| 到場 | 玩家進入場景 | 承認當前人物/物件/路況 |
| 觀察 | 玩家點人物或物件 | 揭露更多狀態 |
| 接觸 | 玩家交易、幫忙、阻擋、戰鬥 | 事件進入關係/記憶/物件歷史 |

元素相關觀測不得把未觀測世界凍結。玩家到場時看到的是局部結果：NPC 已收棚、某物被搬走、路被封、燈被點或熄、貨被拒收。玩家接觸後，才把自己的角色行動寫進物件歷史、NPC 記憶、關係或回訪痕跡。

觀測坍縮的驗收不是「生成一段合理敘述」，而是承認一條可追溯狀態鏈：

```text
未觀測期間的背景推進
-> 玩家到場時承認一組當前事實
-> 玩家觀察時揭露更多狀態與成因
-> 玩家接觸時寫入新的事件
-> 下一次觀測以新事件作為歷史成因之一
```

如果某個坍縮結果無法說明它造成哪個人物、物件、路況、價格、記憶、關係或可用動詞不同，該結果不合格。

## 離線安排

離線安排是玩家與永遠在線世界的接口。

可用安排：

- 原地等待。
- 休息。
- 看守某物。
- 跟隨某人。
- 委託某人。
- 嘗試交易。
- 搬運到某處。
- 回到某個已知地點。

離線結果：

- 成功。
- 部分成功。
- 被他人搶先。
- 因風險中止。
- 因關係/工具/時間不足失敗。
- 留下新的問題。
- 因元素局勢成功或失敗，例如等霧散、守火源、看貨、等雨停、封路或清障。

離線安排的結果也屬於歷史。玩家再次登入時，不顯示「離線報表」作為主要玩法，而是在當前場景中呈現結果：手上少了燈油、貨被看住或被拒收、某人已經先走、玩家被記得守約或失約。

## 重訪差異

重訪差異必須來自狀態：

- NPC 不在原地。
- 物件被使用。
- 需求被完成。
- 路況變差或改善。
- 天氣造成新風險。
- 玩家上次修補留下效果。
- 離線安排產生結果。
- 元素局勢被玩家、NPC 或時間處理後留下的具體差異。

禁止只換一句氛圍句當成世界在動。

## 禁止寫法

- 把歷史寫成年表、古戰爭、王朝、神話或名詞表，卻不能改變目前狀態。
- 把歷史當成殘留物、遺跡或舊痕跡，而不是此刻人、物、路、價、規矩與可用動詞的成因。
- 把沿革寫成玩家必讀設定，沒有接到人物、物件、路、價格、規矩、關係或動詞。
- 把變遷寫成隨機場景句輪播，沒有世界事實差異。
- 把未觀測世界視為凍結，玩家一回來所有事都停在離開時。
- 把觀測坍縮當成無中生有的補文案機制。
- 把後端 tick、狀態機、資料庫欄位直接暴露給玩家。

## 驗收

任一時間/歷史/沿革/變遷設計，至少要通過：

1. 能追溯 `../../DESIGN_KEYWORDS.md`：永遠在線、觀測不凍結、後端真理、NPC 同規則、不可無中生有。
2. 能說出上一秒、上一 tick 或上一動作留下什麼世界事實。
3. 能說出玩家不介入時，下一步哪個人、物、路、價格、規矩、風險或關係會改變。
4. 能說出玩家介入後，哪個世界事實被改寫。
5. 能說出下一次觀測或重訪時，玩家能看到什麼差異。
6. 玩家不需要讀年表，也能從當前狀態判斷一個可做決策。
7. 若移除「上一秒/上一 tick/上一動作」欄，場景仍完全不變，代表即時歷史沒有落地。
