# 09 探索、冒險與地圖

上位地圖規格：`../world/world-scale-and-systems-v0.md`。

## 地圖從世界觀生成

地圖不是先有地名再補玩法，也不是先有北岸、城鎮、商店、路口再往外擴。地圖生成順序必須是：

```text
DESIGN_KEYWORDS.md
-> world-foundation-v0.md
-> M1 大尺度地帶
-> M2 局部秩序區
-> M3 人類活動帶
-> M4 玩家站入場景
```

任何地點若不能回答它屬於哪個地帶、維持什麼邊界、哪種物候/地貌/人群/物資風險正在改變此地、誰為何在場、什麼物資或消息流過、玩家能改變哪個事實，就不得進入可玩地圖。既有場景清冊先視為素材與工程進度，需重審後才算合格地圖。

## 地圖服務玩法

地圖不是進度本身。每個地點必須支撐玩法：行動、風險、資訊、NPC、物件、經濟或回訪差異。

地點驗收：

1. 這裡能做什麼。
2. 做了改變什麼。
3. 哪些 NPC 也會來。
4. 有什麼可利用、可失去、可爭奪或可錯過。
5. 玩家為什麼再來。

答不出就降為背景或連接路。

## 探索

探索是取得資訊優勢。

元素是探索規則的一部分。玩家探索到的不是百科條目，而是可行動的局部知識：什麼時段某路可走、哪種天候某人會停工、哪個工具能打開捷徑、哪個 NPC 懂得處理某種元素局勢。

探索獎勵：

- 路線揭露。
- 安全時機。
- 危險前兆。
- 人物行蹤。
- 供需資訊。
- 可維護物件。
- 可佔用場所。
- 可避開的風險。
- 可利用或需避開的元素局勢。

## 冒險

冒險是帶著不完整資訊進入風險。

冒險需要：

- 前兆。
- 準備。
- 選擇。
- 代價。
- 收益。
- 痕跡。

不確定路設計模板：

```text
路線名：
玩家第一眼看到：
可取得線索：
準備方式：
可能收益：
可能損失：
NPC 是否也會走：
回訪後可能變化：
```

## 地圖尺度與命名

命名要跟當前尺度一致。玩家看到的是自己能理解的地點，不是資料節點。

命名原則：

- 通俗。
- 可定位。
- 符合玩家視角。
- 不用功能壓縮詞。
- 不用半文半白怪詞。
- 名稱會引導後續設計，因此不得草率。

## 揭露規則

| 資訊 | 揭露方式 |
|---|---|
| 當前場景 | 進入即見 |
| 出口 | 當前可感知或已知才見 |
| 危險 | 前兆、人物提醒、物件痕跡 |
| 遠方地名 | 傳聞、地圖物件、NPC、告示 |
| 資源 | 探索、工具、熟練、天氣 |
