# 04 物件、動作與狀態

## 物件是遊戲機制

奇點的物件不是場景裝飾。只要它出現在核心入口，它就必須有狀態、動作、條件、結果與回訪差異。

## 外部研究校準

The Sims 的 smart terrain 方向可借一半：把可做的事放到環境物件裡，而不是把所有智慧塞進角色。奇點不採用家居模擬或需求條，但採用「物件是動詞來源」這個原則：核心物件必須向玩家與 NPC 提供可理解的動作、條件與後果。

## 物件資料設計

| 欄位 | 說明 | 玩家是否直接看見 |
|---|---|---|
| 名稱 | 玩家可理解名稱 | 是 |
| 類型 | 工具、容器、路障、告示、來源、場所物 | 否，可由文字呈現 |
| 狀態 | 空/滿/壞/濕/堵/被佔/缺料 | 是，用文字 |
| 元素/狀態關係 | 火、水、風、土、霧、泥、雷等是否會改變可用動作 | 是，只在影響玩家選擇時呈現 |
| 歸屬 | 無主、公共、某人、某組織 | 視情況 |
| 可用動作 | 看、拿、用、修、買、賣、搬、掛牌 | 是 |
| 條件 | 工具、錢、關係、時間、天氣 | 失敗時呈現 |
| 結果 | 物品、錢、位置、路況、關係、事件 | 是 |
| 回訪差異 | 下次看到的狀態 | 是 |

## 動作模型

每個動作都要有：

```text
動作名：
目標物件：
前置條件：
元素/狀態條件：
玩家可見提示：
成功結果：
失敗結果：
NPC 是否也能做：
會留下的痕跡：
```

## 失敗設計

失敗不能只寫「不能這樣做」。失敗要揭露世界規則。

失敗類型：

- 工具不足。
- 錢不足。
- 物件已被佔用。
- 時間不對。
- 天氣不適合。
- 元素局勢不適合，或需要先處理火源、積水、霧、泥、風向、雷暴等狀態。
- 對方不信任。
- 有人阻止。
- 風險太高。
- 物件已被他人先改變。

好失敗會讓玩家知道下一步可以準備什麼。

## 物件等級

| 等級 | 作用 | 範例設計方向 |
|---|---|---|
| 背景物 | 辨識地點 | 不進核心入口 |
| 狀態物 | 顯示局勢 | 可看，不一定可操作 |
| 行動物 | 產生狀態變化 | 核心入口 |
| 競合物 | NPC 也會使用 | 優先設計 |
| 長期物 | 可維護、佔用、投資 | 支撐經營/建造 |

## 物件與 NPC 交會

物件要能被 NPC 讀取或改變。否則「玩家 = NPC」無法成立。

要求：

- NPC 可先玩家一步取走、使用、修補、堵住、買走或留下痕跡。
- 玩家可看到 NPC 對物件的改變。
- 玩家可利用物件影響 NPC，例如清路、放物、掛牌、修補、阻擋。
