# 00 遊戲設計層：骨筋肉皮

狀態：細節設計總結構草案，未經使用者拍板前不得視為定案
第一權威：`../../DESIGN_KEYWORDS.md`
用途：把 GDD 從概念章節推進成可檢查的設計層。任何新設計若只落在理念，不算完成；必須能落到骨、筋、肉、皮四層。

審查口徑：四層不是給文件自我滿足用。使用者會直接以玩家角度看設計是否想玩；Codex 必須同時讓四層內容能追溯 `../../DESIGN_KEYWORDS.md`。四層完整但玩家無感，仍然不合格。

## 四層定義

```text
骨：世界與玩法不能少的硬結構。
筋：系統之間如何牽動，行動如何傳成後果。
肉：玩家實際可玩的內容、局勢、取捨、成功、失敗、重訪。
皮：玩家畫面、文字、按鈕、事件流如何把狀態呈現出來。
```

四層缺一不可：

- 只有骨：像資料表或框架，玩家玩不到。
- 只有筋：像流程圖，沒有內容。
- 只有肉：像散裝點子，容易互相矛盾。
- 只有皮：像漂亮畫面或文案，沒有世界事實。

四層之上還要通過玩家可感檢查：

```text
玩家看到什麼
-> 玩家想點什麼
-> 玩家做了改變什麼
-> NPC/世界是否同規則回應
-> 下次回來有什麼痕跡
-> 玩家為什麼願意再玩
```

這不是第五層文件，而是四層的共同驗收方式。

## 骨：硬結構

骨是奇點世界每個可玩內容共同使用的設計結構。

| 骨件 | 必須回答 | 對應 GDD |
|---|---|---|
| 玩家自身 | 我是誰、在哪、有多少錢、手上拿什麼、我能做什麼 | 01, 02, 05, 16, 17 |
| NPC | 這個人在哪、要做什麼、持有什麼、是否認得玩家 | 06, 12 |
| 物件 | 名稱、狀態、歸屬、可用動作、條件、結果、回訪差異 | 04 |
| 場景 | 穩定骨架、當下局勢、人物、物件、出口、痕跡 | 03 |
| 路線/地圖 | 從哪到哪、路況、風險、時間、誰也會走 | 09 |
| 行動 | 誰對什麼做什麼、條件、成功、失敗、痕跡 | 04, 13 |
| 時間 | 當下、上一秒/上一 tick/上一動作、日內、日/季、事件時間軸、歷史/沿革/變遷如何改變內容 | 08 |
| 經濟 | 鎂、物資、需求、供給、報價、物流、信用 | 07 |
| 衝突 | 前兆、接近、衝突、戰鬥、後果 | 10 |
| 維護/建造 | 玩家投入後，世界物如何跨時間維持或磨損 | 11 |
| 社會承認 | 人如何記住玩家，關係如何改變可做事 | 12 |
| 元素規則 | 火、水、風、土、霧、泥、雷等如何改變角色選擇與世界狀態 | 15, 17 |

骨的驗收：

```text
這個內容若要進核心畫面，它至少能被歸入一個骨件，並填出必要欄位。
同時要能說清玩家第一眼看到哪個骨件，以及它為什麼值得點。
```

如果一個設計只能寫成一句氣氛、地名、材料名或概念名，它還沒有骨。

## 筋：牽動規則

筋是系統之間的連接。奇點的每個核心行動都必須走完下列鏈條。

```text
玩家/NPC 意圖
-> 目標人/物/路/場所
-> 條件檢查：工具、錢、關係、時間、位置、元素局勢、歸屬
-> 成功/失敗/部分成功/被搶先
-> 世界狀態變化
-> 事件記錄
-> 玩家畫面回饋
-> NPC 記憶/關係/經濟/路況/物件歷史之一被更新
-> 下次登入或重訪可見差異
```

筋的設計表：

| 牽動點 | 必須有的結果 |
|---|---|
| 工具 -> 動作 | 手上拿什麼會改變可用動詞 |
| 動作 -> 狀態 | 點擊後至少一個世界事實改變 |
| 狀態 -> 文字 | 畫面描述從狀態渲染，不臨時創造事實 |
| 狀態 -> NPC | NPC 能讀取、利用、避開、阻止或搶先 |
| 狀態 -> 經濟 | 價格、需求、缺貨、報酬或信用至少可能被改變 |
| 狀態 -> 時間 | 等待、離線或重訪後狀態可能持續、衰退、被處理或造成新問題 |
| 狀態 -> 社會 | 某人記得、拒絕、信任、求償、請託或改稱呼 |
| 狀態 -> 戰鬥/風險 | 戰前判斷、避開、準備、求援或自動結算條件改變 |

筋的驗收：

```text
刪掉某個牽動點後，玩家決策是否變少？
若沒有變少，該牽動點只是裝飾。
若牽動點存在但玩家看不到、感受不到、下次回來讀不到，也只是後端自嗨。
```

## 肉：可玩內容

肉不是世界觀散文，而是玩家能進入的局勢。

肉的最低單位是「玩法模組」：

```text
模組名：
玩家第一眼看到：
自身/持物/工具接點：
可點入口：
可用動作：
NPC 自走行為：
成功結果：
失敗/不處理/被搶先：
回訪差異：
支撐哪個長期位置：
```

可玩內容至少要覆蓋五類：

| 類型 | 玩家在玩什麼 |
|---|---|
| 自身 | 握持、收起、整理、休息、等待、離線安排 |
| 物件 | 拿、放、修、用、搬、堵、掛牌、佔用 |
| 人 | 問、幫、拒、讓、跟、阻、交易、記住/被記住 |
| 路 | 走、等、繞、探、標記、求援、避險 |
| 場所 | 維護、補料、修補、委託、守護、改變可用性 |

肉的驗收：

```text
玩家做一次後，第二次是否因人、物、錢、路、時間、關係、工具、元素局勢之一不同而有不同選擇？
玩家是否有理由想做第二次？
```

第二次仍完全一樣，就是薄肉。
第二次雖然不同，但玩家不在乎，也仍是薄肉。

## 皮：玩家呈現

皮不是裝飾。皮是讓玩家讀懂世界模型的界面。

第一屏皮層分工：

| 區域 | 玩家要讀到 |
|---|---|
| 全局上下文 | 時間、天氣/局勢、必要節奏，不混入場景正文 |
| 自身入口 | 姓名、鎂、手持/工具、明顯狀態、近期事件，點開能做自身動作 |
| 場景狀態 | 此地當下局勢、人物、物件、出口、痕跡 |
| 入口列表 | 可點人物、物件、出口，不列純背景 |
| 動作面板 | 觀察結果、可用動作、不可用原因、可能風險 |
| 事件流 | 玩家行動結果、自然察覺到的局部變化、重要狀態變化 |

皮的文字要求：

- 先寫狀態，再寫氣氛。
- 先寫玩家能判斷的事，再寫風味。
- 成功要說哪個世界事實變了。
- 失敗要說玩家能準備什麼。
- 不用 debug、資料庫、精確人群數、後設語。
- 不用抽象口號替代具體入口。

皮的驗收：

```text
玩家不看文件，只看畫面，是否知道自己在哪、有什麼、能點什麼、做了會失去/得到什麼？
玩家是否看得出這次點擊會被世界承認，而不是只換一行文案？
```

## 設計層完成標準

一個設計題目要宣稱「完成設計層」，必須有：

1. 骨：實體與狀態欄位清楚。
2. 筋：行動到後果的牽動鏈清楚。
3. 肉：至少一個具體玩法模組，不只是原則。
4. 皮：玩家畫面與文字回饋模板清楚。
5. 禁止方向：明確排除錯誤做法。
6. 驗收：能用 13 的內容檢查表與 14 的切片檢查表驗。
7. 玩家可感：能說服玩家角度的使用者「這裡有事可做，而且做了有世界後果」。

2026-06-20 起，完整遊戲設計層還必須能回到上層總檔的九大塊自審表：[../奇點世界遊戲設計檔.md](../奇點世界遊戲設計檔.md) `0.2 完整設計層落地狀態`。本檔只定骨筋肉皮的完成語法；總檔 0.2 定哪些設計已可交給實作、哪些仍不可。

九大塊的骨筋肉皮對照：

| 設計塊 | 骨 | 筋 | 肉 | 皮 |
|---|---|---|---|---|
| 世界背景正典 | 世界根命題、元素、歷史現在態、M0-M4 | 背景到地圖推導式 | 七大地帶、秩序區、物資流、NPC 在場理由 | 玩家看到土地、路、人、物與當前局勢 |
| 玩家身份與起點 | 姓名、位置、鎂、持物、明顯狀態 | 自身動作改變手持、時間、安排或關係 | 自身入口、握持/收起、離線安排 | 玩家能點自己並知道下一步靠什麼行動 |
| 核心玩法與動詞 | 動作、條件、狀態、失敗成本 | 動作到錢、物、路、人、時間、關係的變化 | 12 個可玩內容模組 | 少量入口、清楚回饋、下一目標 |
| 物件/材料/經濟 | 來源、歸屬、品質、保存、價格承認 | 取得、處理、搬運、交易、損耗、信用 | 物件卡、材料族群、小額經濟流 | 玩家看到可碰物、可用動詞、報價理由與回訪痕跡 |
| NPC/社會/勢力 | 位置、持物、目的、時間義務、記憶 | 未介入行為、競合、關係與名聲變化 | NPC 卡、關係層級、組織玩家可見面 | NPC 以觀察態呈現，不是服務端點 |
| 地圖/地貌/命名 | M1/M2/M3/M4、地貌、邊界 | 地貌、歷史、物資流與玩家動詞推導命名 | 地圖節點驗收、路線與探索/冒險模板 | 地名通俗可定位，出口帶路況與風險 |
| 元素/奇幻規則 | 基礎元素、派生狀態、材料族群 | 元素改變路、貨、工具、NPC 行程與戰鬥前判斷 | 元素局勢、元素動詞庫、角色元素關係卡 | 玩家能看見、利用、避開、修補或承受奇幻規則 |
| 戰鬥/衝突/風險 | 前兆、接近、衝突、結算、後果 | 準備、避開、交涉、求援、制止、承擔 | 戰鬥前置、非戰鬥風險、簡單自動結算 | 戰前選擇可讀，戰後留下物件/路/關係/目擊差異 |
| 玩家表層/UI 文字/驗收 | 第一屏、自身入口、場景狀態、事件流 | 成功、失敗、錯過、重訪如何改變下一步 | 場景卡模板、表層回饋模板、內容驗收表 | 玩家不用讀文件就知道自己在哪、能點什麼、做了差在哪 |

缺任一層，不得宣稱完整；缺總檔 0.2 的交付邊界，不得轉成 runtime 工單。

## 已否決方向

下列方向即使能填完表，也不得算完成設計：

- 北岸局部慣性：從單一地方、單一樣本或單一地名往外硬長世界。
- 散文場景：只寫氣氛、景物、人物站著，沒有動作與後果。
- NPC 服務點：商人、任務人、問答端點、台詞輪播。
- 材料名堆砌：材料有名字但沒有來源、狀態、動詞、NPC 同規則與玩家取捨。
- 小額跑腿交易：只有採集、交料、收錢，沒有更大的世界、關係、風險或再目標。
- 生活條：把遊戲退化成通用照顧表，而不是由世界事件、工具、關係與後果驅動。
- 舊特殊設定：未被明確要求時，不接回舊世界特殊術語與管線。
- 抽象沉浸詞：用沉浸、活世界、有生命感等詞替代玩家實際看到、能點、會變的內容。
