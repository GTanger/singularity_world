# 07 經濟、物資與物流

## 2026-07-24 已落地的來源場所與有限市場閉環

現行經濟不另造玩家商店，而是把既有 Azgaar Full JSON 的完整來源接成會在無玩家時
自行消耗、供應與運送的有限世界：

| 層次 | 數量／狀態 | 權威含義 |
|---|---:|---|
| 來源商品／市場 | 71／54 | 全數保存；人身商品封鎖 |
| 來源報價／交易 | 3,834／25,808 | non-canon 作者證據，不冒充人物成交 |
| operational 庫存 | 3,780 | 54 × 70；首次由來源建立，重啟不回填數量 |
| 供給／需求輪廓 | 1,029／935 | 只由來源交易關係導出 |
| Burg → Market 上游輪廓 | 4,976 | 每筆保留來源聚落、商品、目的市場與運送成本 |
| 上游場所／供應站 | 277／277 | 使用既有正式場所；每地一個 operational 工作場所 |
| 市場間流向 | 478 | 每條有來源交易、起訖市場與正式可達路徑 |
| 個人可攜／可消耗列 | 2,268／594 | 決定人物報價及居民消耗候選 |
| 實際帳本 | PostgreSQL 持續累積 | 供應、消耗、貨運、成交與工作都改變同一世界 |

### 已成立的因果與守衡

- 市場庫存只在第一次採用時依 Azgaar 報價建立；服務重啟只更新輪廓與價格基準，
  不把 `quantity` 回填成 `initial_quantity`。
- 4,976 筆允許的 `Burg → Market` 來源交易落在 277 個正式來源場所；每個場所都有
  一個供應站及一名受派的「地方供應人員」。人物必須抵達來源地工作，目的市場金庫
  才支付工資。
- 來源與目的市場同地時，商品在工作交易內入庫；不同地時先建立
  `origin_kind=producer` 的實體貨運，由該名居民沿 PlaceGraph 承運。市場工人不再
  根據抽象來源證據直接生成商品。
- 居民以自己的鎂購買有需求且可消耗的商品，市場庫存減少、金庫增加，商品隨後進入
  consumption sink；沒有假買家或背景刪除。
- 起點過剩且終點短缺時，正式受派居民先從起點取出有限貨物，沿 PlaceGraph 移動後
  交付終點；在途數量單獨計入守恆，滯留可被重新指派。
- 玩家在同一市場點選真實受派居民，報價、出價與成交直接讀寫這份庫存；商品進背包，
  鎂進市場金庫。NPC 與玩家共用市場結算。
- 每種商品都必須滿足「初始＋有帳本供應＝市場＋在途＋人物持有＋消耗」。最終 live
  快照的總量為 110,193＋1,269＝110,844＋0＋0＋618，逐商品差額 0。

### 玩家內容邊界

- 人身商品只留來源證據，不建立 operational 庫存。
- `Coins` 保留作者、市場與物流證據，但 currency 不進個人報價；玩家不會買到「一份
  錢幣」。船、火砲、車、貨盤、貨堆等非個人攜帶單位同樣排除。
- 舊 `mat_*`、柴枝束與粗礦式 P0 不進現行庫存、報價、供應、消費或物流。原資料與
  舊帳本只供追查，不得再寫成奇幻現代玩法。

### 仍未完成的真正缺口

已完成的是來源地真人供應接上有限市場，不是完整奇幻現代經濟。來源交易沒有足夠證據
支撐工廠、農場、配方、設備或所有權，因此仍缺製造鏈、服務業、物件用途與耐久、
家庭／組織財務、契約與信用、帶風險的物流、完整職業人口、
政治及奇幻能力對生產生活的影響仍未成立；後續必須擴張同一有限世界，不能以來源數量、
採集換錢或儀表板冒充豐富。

## 真實經濟的玩家感

真實經濟不是把材料賣給固定板子。玩家要看見世界中有人需要、有人供給、有人搶先、有人壓價、有人缺貨、有人願意相信或不相信玩家。

## 外部研究校準

Raph Koster 對玩家經濟的核心提醒是：重點不是錢本身，而是讓不同玩法在同一個生態裡有用。奇點的經濟設計不能只做採集換錢；採集、搬運、修補、探索、交易、委託、經營都要能互相形成需求。

另一個限制是遊戲性：經濟可以有虧損、錯估與缺貨，但不能讓新玩家只看到會計懲罰。第一階段切片必須保留可理解的起手需求、報酬、失敗原因與下一步準備方向。

## 經濟構件

| 構件 | 設計作用 |
|---|---|
| 鎂 | 玩家可見貨幣錨點 |
| 物資 | 可持有、可消耗、可交易、可修補 |
| 需求 | 由 NPC、場所、組織、修補、建造、風險產生 |
| 供給 | 由採集、製作、交易、回收、NPC 持物產生 |
| 報價 | 由需求、關係、風險、時間、缺貨影響 |
| 物流 | 物資從 A 到 B 的移動與風險 |
| 信用 | 玩家是否被允許先拿、代送、賒欠、承接 |

## 物資進場規則

物資要進核心設計，至少接到一個玩法：

- 工具使用。
- 修補/建造。
- 交易需求。
- NPC 競合。
- 路線風險。
- 人際信用。
- 場所狀態。
- 戰鬥/避險。
- 元素局勢，例如保存、包覆、烘乾、隔離、封路、停渡、通風或清障。

不能只因現實用途多就加入。

## 玩家經濟身份

| 身份 | 玩家行為 | 回訪差異 |
|---|---|---|
| 短工 | 接臨時活、搬運、整理 | 被某些人認得，報價改變 |
| 採集者 | 找來源、看天氣、避風險 | 來源被採空或恢復 |
| 搬運者 | 跑路線、避路況、準時送 | 路線熟悉、信用增加 |
| 修補者 | 用工具和材料改善物件 | 物件狀態保留，NPC 使用 |
| 交易者 | 買低賣高、談價、壓貨 | 缺貨、過剩、關係變化 |
| 委託者 | 花錢讓 NPC 做事 | 離線後有成功/失敗結果 |
| 場所維護者 | 補料、掛牌、佔用、管理 | 場所形成玩家痕跡 |
| 元素處理者 | 用工具處理火、水、風、土、霧、泥、雷等局勢 | 貨況、路況、報價、信用與委託改變 |

## 元素造成的交易差異

元素只在創造取捨時進經濟核心。

| 層 | 玩家感 |
|---|---|
| 保存 | 同一批貨因包覆、通風、烘乾、隔離而有不同收價或拒收結果 |
| 物流 | 雨、霧、泥、風、雷暴會改變路線、時機、停渡、封路和搬運風險 |
| 工具需求 | 玩家需要火源、油布、繩、箱、棚、排水或標記工具才能接某些活 |
| 信用 | 玩家曾正確處理或弄壞元素局勢，會影響 NPC 是否願意交付貨物 |
| 回訪 | 貨被保存、壞掉、被他人先處理、被拒收或改價，回來要看得出 |

## 缺貨與過剩

缺貨要改變：

- 報價。
- NPC 行動。
- 玩家可接工作。
- 路線價值。
- 風險。

過剩要改變：

- 報價下降。
- 收購停止。
- 物件堆積。
- NPC 改做別的事。

## 交易介面設計

玩家交易時要看到：

- 對方是誰或什麼機構。
- 對方需要/出售什麼。
- 玩家持有什麼。
- 價格或交換條件。
- 關係或信用是否影響交易。
- 成交後錢與物怎麼變。

交易失敗也要有原因：錢不足、物不足、對方不信、收滿、時間不對、物件不在場。
