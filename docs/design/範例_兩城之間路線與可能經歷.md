# 範例：兩城之間旅行（非 MUD 實作稿）

> 目的：示範「文字主導、有空間感、低操作負擔」的城際旅行。  
> 範圍：`霧港城（City）` -> `赤石城（City）`。  
> 原則：玩家做「旅行決策」，不是「逐格操作」。

---

## 1) 一次旅行的互動骨架（固定三段）

每次城際移動都固定輸出三段，不再逐節點報站：

1. `出城抉擇`：決定路線性格  
2. `途中兩段`：兩個關鍵遭遇（世界回應玩家）  
3. `入城落點`：帶著結果進城，直接影響下一段城市體驗

> 內部仍可用 Node/Route 計算，但前台不暴露 hop 與數值刷表語言。

---

## 2) 兩城之間的路線設計（後台）

- 城際最短距離：`8 格`（符合 City↔City 8~14 建議）
- 路線只分 3 種語意，不寫成方向鍵流程：
  - `官道線`：穩定、消息多、變化小
  - `河灣線`：視野開闊、商旅多、突發中等
  - `舊礦線`：收穫高、秩序差、事件尖銳

---

## 3) 玩家看到的版本（前台）

### 3.1 出城抉擇（單次只選一條）

系統顯示：

- `官道線`：路況明朗，常碰到公務與商務消息
- `河灣線`：容易遇到流動人群與臨時交易
- `舊礦線`：容易碰到利益衝突與灰色場景

玩家只做一個選擇：`本次走哪條`

### 3.2 途中兩段（每段都必有可選反應）

每條路都固定觸發兩段「場景事件槽」：

- `事件槽 A：前半段遭遇`
- `事件槽 B：後半段遭遇`

每個事件槽都提供三類反應（語意一致）：

- `介入`：主動處理眼前事件
- `旁觀`：低介入觀察，取得有限資訊
- `迴避`：不捲入，保留行程穩定

### 3.3 入城落點（不是「抵達」而已）

進入赤石城時，系統必輸出三項：

- `你帶進城的狀態`（例如：被關注 / 帶著線索 / 沾上麻煩）
- `你解鎖的入口`（例如：工坊線、碼頭線、治安線）
- `你錯過的東西`（讓選擇有代價，不做完美路線）

---

## 4) 實際範例（霧港 -> 赤石）

## 路線選擇：`河灣線`

### 事件槽 A（前半段）

場景：河岸停泊點出現爭執，一方是渡運工，一方是臨時採買商隊。  
玩家可選：

- `介入`：替其中一方說話，快速拿到一條赤石內部消息
- `旁觀`：記下人名與口音，得到模糊傳聞
- `迴避`：直接離開，保持行程乾淨

### 事件槽 B（後半段）

場景：赤石外圍巡查加嚴，路上旅人被逐一盤問。  
玩家可選：

- `介入`：主動配合，建立正面印象
- `旁觀`：混在人群後方，觀察城門規矩
- `迴避`：改走側邊入城點，避開正門視線

### 入城落點（結果輸出）

- 帶入狀態：`守規旅人`（門哨態度中立偏正面）
- 解鎖入口：`赤石工坊區：舊帳簿傳聞`
- 代價：`錯過河灣夜市的短時機會`

---

## 5) 後台事件槽資料（可落地）

> 關鍵：不用「降遭遇、耗時+2」這類 MMO 詞彙。  
> 用「敘事標記 + 城市入口影響」驅動結果。

```json
{
  "route_id": "mistport_to_redstone",
  "route_styles": ["official_road", "river_bend", "old_mine"],
  "event_slots": [

      "slot_id": "A",
      "phase": "early",
      "pool": ["dock_dispute", "bridge_block", "rain_shelter_crowd"]
    },
    {
      "slot_id": "B",

    }
  ],
  "responses": ["intervene", "observe", "avoid"],

    "unlock_workshop_thread",

    "raise_gate_attention",
    "lower_gate_attention"
  ]

```

## 6) 驗收條件（是否真不是 MUD）

- [ ] 玩家全程不需要連續方向鍵操作
- [ ] 玩家只做 1 次路線選擇 + 2 次事件反應
- [ ] 入城結果必影響至少 1 條城內可互動線
- [ ] 同一條路線重跑時，事件文本與落點可變（非固定劇本）
- [ ] 前台文案不出現 MMO 參數語言（例如：降遭遇、耗時+2、buff/debuff）

若不符合，先改事件槽與輸出模板，不改美術。
