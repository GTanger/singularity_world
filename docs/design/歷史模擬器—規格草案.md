# 歷史模擬器—規格草案 v0

> 2026-04-16 起稿 · 設計者審局中 · 尚未交碼農

## 核心洞察

**地圖不是輸入，是輸出。** 歷史模擬器吐出的「當下世界狀態」就是遊戲起始地圖。節點、連線、聚落、遺跡、詞元分布——全部是幾百年歷史跑出來的副產物。

## 目標 / 非目標

### 目標
- 從解放日（USD 世紀末）模擬混沌紀 N 年，凍結成世界初始快照
- 快照灌回主遊戲 PostgreSQL，作為遊戲端方格世界的起點
- 設計者觀察湧現結果（不預寫骨幹事件），不滿意就重跑
- 快照不是靜態文件，是**活世界的某一瞬切片**

### 非目標
- 不是遊戲 runtime（那是主遊戲責任）
- 不是玩家介面（離線工具）
- 不碰 hex 觀景窗（觀景窗繼續吃自己的 91 格）
- 不自動處理 Azgaar 匯入（未來另案）

## 架構決策

| 項目 | 決策 | 理由 |
|------|------|------|
| 部署形態 | 獨立 Rust binary | 避免污染主遊戲 build、省重啟代價 |
| 專案位置 | `/home/tanger/Projects/singularity_simulator/`（新 repo）| 獨立生命週期，不跟遊戲版本綁 |
| 狀態儲存 | SQLite（WAL 模式）| 跑完可搬動、可重放、不動主 PG |
| 時間壓縮 | 三段（0-50 逐年 / 50-200 逐十年 / 200+ 逐年）| 動盪期密、穩定期疏、接近現代再密 |
| LLM 整合 | Ollama HTTP API | 本地算力、無 API 費用 |
| 重跑成本目標 | **過夜可收工**（4-8 小時）| 設計迭代需要 |

## 三層並行引擎

每 tick（= 壓縮後的一個時間單位）依序跑三層。

### L1 地理層（純公式，無 LLM）

不需要 LLM，純數學。

輸入：當前念場密度網格
輸出：下一 tick 的網格狀態

公式：
- 富態化擴張：Token 密度 > 閾值 → 格子變「富態化區」（植被瘋長、野獸異變）
- 聚念場收縮：有念生物聚集 → 局部念場密度降低 → 抑制富態化
- 地形 drift：百年級地形變化（河改道、森林退化、沙漠擴張）

110V 原則嚴格遵守：
- 密度公式純連續函數，不做狀態機
- 沒有冷卻、沒有計時器
- 有人就壓、沒人就漲

### L2 人口流體層（統計模擬，無 LLM）

三族群（依原文五話設定）：

| 族群 | 本質 | 人口占比 | 行為特徵 |
|------|------|---------|---------|
| **普通人** | 未被 Token 改寫的人類 | 絕大多數 | 聚居抑制富態化、政府癱瘓後自組殘餘體制 |
| **異化人** | 不完全改寫（念場破碎） | 少數但增長 | 念場撕裂慢性痛、殘存意識、可自爆成 T 彈、神使組織來源 |
| **神化人** | 無念物質（腦死者等）被 Token 完整烙印 | 極稀 | 本能不干預、壽命長、散居、極罕主動出手 |

每 tick：
- 出生／死亡（普通人 × 聚落衛生度 + 異化人 × 人體實驗失敗率 + 神化人極緩不繁殖）
- 遷徙（普通人向聚念場區聚集、異化人向富態化邊界游移）
- 族群互動（普通人 vs 異化人武裝衝突、神化人匿名警告／稀有干預）
- 聚落形成／解散（普通人 population-fluid 湧現、異化人藏匿點浮動）

記憶：奇點記憶早已設計過，參考 `群體流體模擬` 抽象。

### L3 敘事層（LLM Agent，核心湧現層）

Agent 粒度分三級：

| 級別 | 數量 | 職責 | LLM 模型 |
|------|------|------|----------|
| 陣營級 | 2（人類殘餘政府 / 神使組織）| 大戰略、文化走向 | qwen3.5:35b-a3b-nvfp4 主敘事 |
| 聚落級 | 30-100（視人口流體長出多少）| 年度決策（擴張、撤退、結盟、戰爭）| qwen3.5:9b 快決 |
| 個人級 | 神化人（極稀，個位數）+ 後期角色 | 稀有干預、傳記 | qwen3.5:9b 按需 |

**神化人 Agent 特例**：不屬於任何陣營。本能是不干預（繼承創造者禮讓）。99% tick 不活動。觸發條件（原文校準）：
- 匿名警告事件（類五話末匿名信，全球元首同時收到，內容極簡無論證）
- 極端狀況下的單次干預（類五話警衛擋 T 彈——該次因與 T 彈共處念場籠罩範圍而消失，非「出手必死」）

Agent 有：
- 記憶（本聚落的過去事件、受教育的歷史敘事）
- 當前狀態（人口、資源、周邊威脅）
- 決策介面（LLM prompt 吐出 JSON action）

Agent 互動產生事件，事件影響 L1/L2。

## 輸入

### 靜態公理（專案常駐檔）
- `axioms/token_physics.toml`——Token 物理參數
- `axioms/tribes.toml`——三族群屬性
- `axioms/epoch_seed.toml`——解放日當下世界狀態（五集敘事提煉）

### 動態參數（CLI 入參）
- `--seed`（確定性）
- `--years`（模擬年數）
- `--density-level`（骨幹 + 輔助總量）

## 輸出

### 快照 SQL（灌回主遊戲 PG）
- `grid_cells`——節點地圖（聚落、遺跡、Token 熱點）
- 連線表（新建，連節點）
- `entities`——活到當下的 NPC
- `lore_events`（新表）——歷史年表
- `artifacts`（新表）——流傳至今的傳說物
- `factions`（新表）——當下派系

### 年表與事件條目（純結構化，不靠本地 LLM 潤飾）
- `chronicle.md`——結構化年表（混沌紀 1 年 → N 年），每條 = 年/地/主角/事件種類/一句話 summary
- `events.jsonl`——所有事件的結構化條目（供離線篩選與手工潤飾）
- **骨幹事件潤飾＝離線手工流程**：設計者從 events.jsonl 挑 30-100 個關鍵事件，沿「用戶給骨架 + Opus 潤」的五話產出模式寫成 `legends/<id>.md`。**模擬器不生產敘事文本**

### 設計者檢視工具
- Web UI 時間軸（tick 向前倒放，看哪一年發生什麼）
- 地圖 heat map（Token 密度、人口分布隨時間變化）

## CLI 介面

```bash
simulator init --epoch liberation_day --seed 20260414
simulator run --years 300 --out snapshot.db
simulator inspect --year 150 --layer geography
simulator snapshot --from snapshot.db --to seed.sql
simulator replay --event-id <uuid>
```

## LLM 分層使用（決策／敘事分離原則）

**本地 LLM 只做結構化決策輸出（吐 JSON action）**，不負責寫敘事。實測本地 27B 以下（Qwen3.5-27B-UD-IQ3、Gemma 4 26B、Qwen3.5-9B）寫奇點世界敘事全軍覆沒——讀不懂原文、硬套訓練資料套路、產出順語空話。敘事層完全外放給「用戶給骨架 + Opus 潤飾」的離線手工流程。

| 用途 | 模型 | 輸出形式 | 單次呼叫 | 累計次數（300 年）|
|------|------|---------|---------|------------------|
| 陣營決策 | qwen3.5:27b-ud-iq3 | JSON action | ~300 tok | 2 × 150 = 300 |
| 聚落決策 | qwen3.5:9b | JSON action | ~200 tok | 50 × 300 = 15000 |
| **敘事潤飾** | **不走本地 LLM** | 離線手工 + Opus | — | 骨幹 30-100 個 |

估算總時長（決策 LLM）：**RX 9060 XT 16GB，約 2-3 小時一輪**（跑過夜綽綽有餘）

## 資料模型（SQLite）

```sql
-- 時間軸
CREATE TABLE ticks (
  tick INTEGER PRIMARY KEY,
  year INTEGER,  -- 混沌紀年
  real_timestamp TEXT  -- 跑這 tick 的現實時間
);

-- 地理狀態（每 tick 快照太重，存 delta）
CREATE TABLE geo_snapshots (
  tick INTEGER,
  cell_id TEXT,  -- 節點 id
  token_density REAL,
  terrain_type TEXT,
  PRIMARY KEY (tick, cell_id)
);

-- 人口
CREATE TABLE populations (
  tick INTEGER,
  cell_id TEXT,
  tribe TEXT,  -- ordinary / yihua_ren / shenhua_ren
  count INTEGER,
  PRIMARY KEY (tick, cell_id, tribe)
);

-- Agent 記憶
CREATE TABLE agents (
  id TEXT PRIMARY KEY,
  level TEXT,  -- civilization / settlement / individual
  created_tick INTEGER,
  dissolved_tick INTEGER,  -- NULL if still active
  cell_id TEXT,
  memory JSON  -- accumulated narrative context
);

-- 事件（Agent 決策 + L1/L2 湧現事件）
CREATE TABLE events (
  id TEXT PRIMARY KEY,
  tick INTEGER,
  kind TEXT,  -- war / migration / founding / disaster / discovery
  actors JSON,  -- agent ids
  cell_ids JSON,
  summary TEXT,  -- 一句話（模擬器產生）
  structured_detail JSON,  -- 結構化細節（誰對誰做了什麼、數字、前後狀態）
  is_legend_candidate BOOLEAN  -- 標記值得離線手工潤飾的骨幹事件
  -- 注意：不存 narrative。傳說文本由設計者離線用 Opus 潤飾，成品在 legends/<id>.md
);

-- 派系（文明內次文化分裂）
CREATE TABLE factions (
  id TEXT PRIMARY KEY,
  tribe TEXT,
  name TEXT,
  founded_tick INTEGER,
  dissolved_tick INTEGER,
  ideology TEXT
);

-- 傳說物（事件遺留的物件）
CREATE TABLE artifacts (
  id TEXT PRIMARY KEY,
  origin_event_id TEXT,
  kind TEXT,  -- weapon / tome / relic / ruin
  current_cell_id TEXT,  -- NULL if lost
  decay_level INTEGER
);

-- 節點連線（地圖拓撲）
CREATE TABLE edges (
  from_cell TEXT,
  to_cell TEXT,
  kind TEXT,  -- road / river / pilgrimage / nian_field
  established_tick INTEGER,
  broken_tick INTEGER,
  PRIMARY KEY (from_cell, to_cell)
);
```

## 關鍵設計抉擇（待你審）

### Q1：模擬到混沌紀幾年？
- 用戶態度：「看結果再說」
- 預設：**先跑到混沌紀 300 年**，不滿意再調

### Q2：Agent 決策真讓 LLM 自主，還是規則預選選項後 LLM 挑？
- 純自主：LLM 吐任何 action → 系統照做（風險：亂）
- 選項制：系統列合法 action → LLM 挑 → 執行（風險：同質化）
- 混合：LLM 先提 3 個候選 → 系統驗證可行性 → LLM 選 → 執行
- **建議：混合**（湧現 + 可控）

### Q3：初始地圖從哪裡來？（已坍縮 2026-04-16）

**就是現在的地球。** 奇點宇宙 2026 Token 降維事件發生在真實地球，不用虛構大陸。

資料源：
- **Natural Earth**（ne_50m_admin_0_countries、ne_50m_coastline）海岸、國界
- **GeoNames cities1000** 篩 >50 萬人口 ≈ 1000 城市
- **SRTM / ETOPO** 高程地形（可選，M2 之後）
- **H3 hexagonal index**（Uber）作為格點拓撲

H3 解析度：
- **res 5**（1 hex ≈ 253 km²，全球 ~2000 格）→ 主模擬骨架
- res 7（~5 km²，10 萬格）→ 有人聚落局部細切

初始狀態 = 解放日當下的地球主要城市分布，模擬器從此開跑。

**與舊記憶的連結**：shodh-memory 存過「planetary expansion, expansion_factor scaling area-per-cell linearly」——H3 + 行星尺度是凍結的舊計畫，此規格將其啟動。

### Q4：要看哪個尺度的湧現（前問未答）
- 文明尺度 / 聚落尺度 / 人物尺度
- **建議：M0-M3 先文明+聚落兩尺度，人物尺度 M4 後視興趣加**

## 風險 / 已知坑

1. **LLM Agent 記憶漂移**——300 年累積記憶會爆 context。緩解：定期 summary 壓縮
2. **模擬器結果不可重現**——LLM temperature 有隨機。緩解：記錄每次 LLM 呼叫的 seed 與 output
3. **重跑代價**——若公理調整需全跑。緩解：checkpoint 每 50 年，從中間恢復
4. **AMD ROCm 與 Ollama MoE 相容性**——RX 9060 XT (gfx1200) 較新，需實測
