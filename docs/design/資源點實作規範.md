# 資源點與採集：框架連續與富態收穫規範 v1.5

> **定位**：定義基於環境框架與物質富態化（Luxuriance）的採集物理。
> **具名修訂**：Gemini (2026-04-08 世界觀用語校正版)。
> **核心準則**：PostgreSQL 為唯一真理。遵循「原本怎麼長，仍舊怎麼長」。嚴禁使用任何與世界觀無關的外部物理術語（如電荷）。

---

## 一、 世界觀物理：富態積累與念場排斥

### 1.1 富態積累 (Luxuriance Accumulation)
*   **無念豐盈**：地格無人（Token 密度 1.0）時，環境物資持續吸收輻射，呈現 **「富態化 (Hyper-growth)」**。
*   **性狀質變**：富態化伴隨質變（肉質、玉質、高能流體滲出），不僅是體型放大，更是物質張力的膨脹。
*   **原本怎麼長，仍舊怎麼長**：物質基礎（如水稻需水、礦脈居山）保持連續性。

### 1.2 採集機制：念場抑制與資源冷卻
*   **抑制效應**：採集者的念場會物理性排開 Token 輻射，導致局部密度下降。
*   **養分中斷**：一旦密度下降，富態化生長立即停止。
*   **採集體驗**：採集者是在「剝取」環境已積累的富態位能。當積累物被耗盡且因為念場抑制導致新的生長無法發生，產量自然歸零。
*   **冷卻與回溫**：人必須撤離，讓地格回歸無人狀態（密度回復 1.0），環境才能重新開始脈動、積蓄富態豐盈。

## 二、 PostgreSQL 資料架構 (Authority)

### 2.1 `resource_pools` (性狀分流與環境檢查)
```sql
CREATE TABLE resource_pools (
    id SERIAL PRIMARY KEY,
    key VARCHAR(50) UNIQUE NOT NULL,
    kind VARCHAR(20) NOT NULL,            -- crop, ore, herb
    required_terrain VARCHAR(20),         -- 地形掛鉤
    phenotype_path VARCHAR(20),           -- 演化路徑: giant, jade, fleshy, liquid
    entries JSONB NOT NULL                -- [{"id": "spirit_paddy_rice", "weight": 100}]
);
```

### 2.2 `resource_nodes` (地圖資源節點)
```sql
CREATE TABLE resource_nodes (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    hex_q INTEGER NOT NULL,
    hex_r INTEGER NOT NULL,
    pool_id INTEGER REFERENCES resource_pools(id),
    luxuriance_level REAL DEFAULT 1.0,    -- 富態豐盈程度 (0.0~1.0)
    danger_level REAL DEFAULT 0.0,        -- 環境原生危險度
    active BOOLEAN DEFAULT TRUE,
    UNIQUE(hex_q, hex_r)
);
```

## 三、 採集動作：被動狀態與產出

1.  **被動放置 (Gathering State)**：
    *   人物與地格咬合，進行 Token 坍縮與物資提取。
    *   日誌敘事：體現環境的「張力」、「豐盈」與「念場衝擊」。
2.  **產出結算**：
    *   `Yield = luxuriance_level * current_density`。
    *   隨提取次數，`luxuriance_level` 降低。
3.  **剝名的定位**：
    *   獲取具體的「富態物種實體」。
    *   屬性在「剝名」完成前不存在，保持 Token 烙印的混沌法則。
