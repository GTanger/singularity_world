# 資源點與採集：框架連續性實作規範 v1.3

> **定位**：定義基於環境框架的資源產出與採集物理。
> **具名修訂**：Gemini (2026-04-08 框架連續性對齊版)。
> **核心準則**：PostgreSQL 為唯一真理。遵循「原本怎麼長，仍舊怎麼長」的物質限制。

---

## 一、 世界觀物理：限制框架的連續性

### 1.1 物質基礎與環境約束
*   **原本怎麼長，仍舊怎麼長**：Token 輻射不改變物質的既有生長邏輯與環境要求。水稻不會長在沙漠，鐵礦不會長在雲端。
*   **富態化 (Hyper-growth)**：Token 僅負責推高生長的天花板（尺度、張力、營養純度）。資源點是環境原生種在沃土風下的「頂配表現」。

### 1.2 脈衝收割 (Pulse Harvest)
*   **電荷累積**：地格無人（密度 1.0）時，環境物種依照其原生框架積累「富態位能」。
*   **坍縮採集**：採集者抵達，將高能位能坍縮為實體物資。念場會逐漸排開 Token 輻射，產能隨之衰減。

## 二、 PostgreSQL 資料架構 (Single Source of Truth)

### 2.1 `resource_pools` (產出池與環境檢查)
```sql
CREATE TABLE resource_pools (
    id SERIAL PRIMARY KEY,
    key VARCHAR(50) UNIQUE NOT NULL,      -- 如 'wetland_spirit_rice'
    kind VARCHAR(20) NOT NULL,            -- crop, ore, herb
    required_terrain VARCHAR(20),         -- 必須匹配的地形（如 Wetland, Mountain）
    entries JSONB NOT NULL                -- [{"item_id": "spirit_paddy_rice", "weight": 100}]
);
```

### 2.2 `resource_nodes` (地圖資源節點)
```sql
CREATE TABLE resource_nodes (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    hex_q INTEGER NOT NULL,
    hex_r INTEGER NOT NULL,
    pool_id INTEGER REFERENCES resource_pools(id),
    charge_level REAL DEFAULT 1.0, 
    danger_level REAL DEFAULT 0.0,
    active BOOLEAN DEFAULT TRUE,
    UNIQUE(hex_q, hex_r)
);
```

## 三、 採集與產出邏輯

1.  **產物具象化**：
    *   採集獲得的是受 Token 滋養的 **具體物種實體 (Luxuriant Items)**。
    *   水稻與旱稻、生鐵與精金，其物理特徵與環境需求在採集前即已確定。
2.  **被動放置 (Gathering State)**：
    *   實體進入地格後掛載狀態，由後端 Tick 根據 `charge_level` 與 `Density` 結算產量。
3.  **剝名的定位**：
    *   採集物是帶有高濃度 Token 烙印的「富態實體」。
    *   **剝名 (Naming)** 負責將這些混沌烙印提煉為有序詞元，決定其品質位階。

---

## 四、 開發約束

*   **禁止無中生有**：資源點配置必須檢核地圖 API 的地格屬性。
*   **禁止過度抽象**：禁止將所有產物統一為「Token 元件」。必須保留「原本長什麼，採集後就是什麼」的視覺與語意標籤。
