# 資源點實作規範 (Resource Point Implementation Spec)

> **定位**：本文件定義了《奇點世界》資源採集系統的底層邏輯與資料格式。
> **權威來源**：**PostgreSQL (postgres-singularity)**。嚴禁依賴 `data/config/*.json` 作為執行期資料來源。

---

## 一、產出定義 (What)

### 1.1 產出內容：材料與可剥名之物
*   **非成品制**：資源點產出白板材料或無名之物。
*   **品質判定**：品階（丙/乙/甲）在後續的**「剝名 (Naming)」**流程中判定。採集階段僅負責項目抽取與數量結算。

### 1.2 PostgreSQL 架構 (Authority)

#### 表 1: `resource_pools`
存儲各類資源的掉落熱度表。
```sql
CREATE TABLE resource_pools (
    id SERIAL PRIMARY KEY,
    key VARCHAR(50) UNIQUE NOT NULL, -- 如 'mine_low_iron'
    kind VARCHAR(20) NOT NULL,       -- mine, wild_gather, water, farm
    entries JSONB NOT NULL           -- 格式: [{"item_id": "iron_ore", "weight": 70}, ...]
);
```

#### 表 2: `resource_nodes`
實體資源點在 Hex 地圖上的配置。
```sql
CREATE TABLE resource_nodes (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    hex_q INTEGER NOT NULL,
    hex_r INTEGER NOT NULL,
    pool_id INTEGER REFERENCES resource_pools(id),
    danger_level REAL DEFAULT 0.0,   -- 危險度 0.0 ~ 1.0
    renew_base REAL DEFAULT 1.0,    -- 基礎再生係數
    active BOOLEAN DEFAULT TRUE,
    UNIQUE(hex_q, hex_r)             -- 一格一節點
);
```

## 二、資源生長與 能量密度 (How)

### 2.1 聚念場悖論 (The Paradox)
*   **計算基準**：`Density = 1.0 - (在場有念生物數量 * 0.1)` (下限 0.1)。
*   **物理效果**：人多 -> 密度低 -> 重長慢 -> 單次採集產能低（但總敲擊數與協作由後端邏輯補償）。

### 2.2 再生機制
*   **全域 Tick 結算**：伺服器依據 `resource_nodes.renew_base` 與當前地格密度，定期更新資源點的可採集量（Stored Amount）。

---

## 三、採集行為（被動放置/狀態制） (Process)

### 3.1 狀態採集 (Passive Gathering)
*   **狀態切換**：`POST /api/action/gather/start` 使實體進入 `Gathering` 狀態。
*   **結算機制**：後端 `GatheringTimer` 定期檢索 `Setting_Gathering` 的實體，計算 `Yield = BaseYield * Density` 並寫入 `inventory`。
*   **中斷條件**：移動、背包滿、受傷或主動停止。

---

## 四、開發流水線 (Pipeline)

1.  **DB Migration**：在 `postgres-singularity` 執行 DDL。
2.  **Seed Data**：注入首批 `resource_pools` 資料。
3.  **Entity State**：在 `store::Entity` 增加 `is_gathering` 標記與關聯節點 ID。
4.  **Loop Logic**：實作每分鐘/每小時的資源產出滾動結算。
