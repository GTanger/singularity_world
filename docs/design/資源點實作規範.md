# 資源點實作規範 (Resource Point Implementation Spec)

> **定位**：本文件定義了《奇點世界》資源採集系統的底層邏輯與資料格式。
> **核心哲學**：對齊「聚念場悖論 (Paradox of Collective Mind)」，資源產出受「Token 密度」動態影響。

---

## 一、產出定義 (What)

### 1.1 產出內容：材料與可剥名之物
*   **非成品制**：資源點不產出帶有品質（丙/乙/甲）的最終詞元或裝備。
*   **產出物**：掉落物為「白板材料（如：生鐵礦、寒鴉草）」或「無名之物」。
*   **品質判定**：資源的品質階級是在後續的**「剝名 (Naming)」**流程中，根據詞元規則與機率決定的。採集這一步只決定**產量 (Quantity)** 與 **種類 (Kind)**。

### 1.2 產出池 (Yield Pool) 格式
產出池定義在 `data/config/resource_pools.json`。

| 欄位 | 說明 |
| :--- | :--- |
| `id` | 池唯一 ID (例: `mine_iron_t1`) |
| `kind` | `mine` | `wild_gather` | `water` | `farm` |
| `entries` | `{ item_id: string, weight: number }` 的陣列 |

## 二、資源生長與 Token 密度 (How)

### 2.1 聚念場悖論 (The Paradox)
*   **Token 密度 (Density)**：環境能量狀態，無人時恆為 **1.0**。
*   **在場抑制**：有念生物（玩家/NPC）的存在會產出磁場排開 Token 輻射，導致 Density 下降。
*   **動態公式**：`CellDensity = 1.0 - (在場有念生物數量 * 0.1)` (下限 0.1)。

### 2.2 再生機制
*   **生長速率**：`Growth = BaseRenew * CellDensity`。
*   **壟斷懲罰**：若有人長期駐守採集，Density 會處於低位，資源幾乎停止生長。**「撤離讓地格靜置」是唯一的冷卻方式。**

---

## 三、採集行為（被動放置/狀態制） (Process)

### 3.1 狀態採集 (Option 1)
目前階段僅實作**「有念生物被動採集」**。

*   **進入狀態**：實體（玩家/NPC）進入資源地格，使用 `Action: Gather` 或受 `Assignment` 驅動進入 `Gathering` 狀態。
*   **被動累積**：不需要連點，系統每個 Tick / 遊戲小時自動結算產出。
*   **產出公式**：`Yield = BaseYield * CellDensity * Efficiency`。
*   **停止條件**：
    1.  背包已滿。
    2.  移動至其他地格。
    3.  受到攻擊中斷。
    4.  密度過低，個體判斷產能不符成本（撤離）。

### 3.2 放置裝置 (Option 2 - 待開發)
*   **機械覺醒風險**：無念機械在 1.0 密度的環境下會「進化出自主意識」，目前暫不實作該技術路徑。

## 四、資料格式 (Schema)

### 4.1 資源點 Node
定義在 `data/config/resource_nodes.json` (或資料庫)。

| 欄位 | 說明 |
| :--- | :--- |
| `node_id` | UUID 或唯一字串 |
| `hex_q`, `hex_r` | 世界座標 |
| `pool_id` | 指向對應 ResourcePool |
| `danger_level` | 危險係數 0.0~1.0 |
| `active` | Boolean |

---

## 五、開發建議順序

1.  **資料層**：定義 `resource_pools.json` 首批範本。
2.  **邏輯層**：
    *   計算 `CellDensity` 的 Tick 定時器。
    *   實體 `Gathering` 狀態的 Tick 結算處理。
3.  **NPC 接入**：將 NPC `Gather` 意圖改為真實節點尋路。
