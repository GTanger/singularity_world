# 已知區域外部空間連接架構

狀態：舊架構參考，不作為現行設計依據
日期：2026-05-21
適用：方格 MUD、路口形狀 UI、第一個手工已知區域

> 2026-05-21 註記：此文件來自舊架構討論，只保留為歷史參考。後續設計不得引用此文件作為現行架構約束，除非明確要回看舊方案。

## 一句話

先造一個「後台已知、玩家局部知道」的手工區域；外部世界先不要展成大地圖，而是用幾種邊界連接契約掛在已知區域外圍。

這份文件只設計空間接法，不指定村名、事件名、舊模板或劇情題材。

## 問題

如果一開始直接做大世界，會回到上帝視角：

```text
區域 A
→ 區域 B
→ 城鎮 C
→ 山林 D
→ 外部路網
```

玩家會開始看地圖、算路線、理解世界拓撲，而不是站在一個地方，用身體感知周遭。

所以第一步應該是：

```text
已知區域內部：可以細做
已知區域外部：先做連接契約，不做全量展開
```

## 三層空間

### L0：當前可玩內核

玩家第一眼能活動的少量格子。

用途：

- 建立第一人稱感。
- 承載最早的 NPC、物件、日常、異常。
- 讓玩家不用地圖也能記住地方。

規模建議：5 到 9 格。

### L1：已知區域全體

後台已經存在、可持久化、可讓 NPC 日程運作的完整區域。

用途：

- 給 NPC 生活範圍。
- 給事件留下足夠空間。
- 給玩家逐步揭露。

規模建議：20 到 35 格。

玩家不需要一開始全知道。

### L2：外部連接層

不是完整地圖，而是掛在 L1 外圍的外部節點契約。

用途：

- 表示人、貨、消息、危險從哪裡來。
- 讓已知區域不是孤島。
- 給未來擴張留 hook。

規模建議：4 到 8 條連接契約。

## 核心名詞

### 已知區域 Known Region

後台已落地的區域。它不是玩家已全量知道的區域。

白話：世界已經知道這裡長什麼樣，但玩家只知道自己看過的部分。

### 邊界格 Boundary Cell

已知區域內負責接外部的格子。

邊界格不能只是「出口」。它本身也要有功能：

- 守望
- 傳聞
- 檢查
- 交易
- 風險預警
- 資源入口
- NPC 日程節點

### 外部節點 External Node

區域外部的佔位節點。它暫時不是可完整遊玩的格子，只是一份契約：

```text
這條路往外，大概通向某種空間與事件來源。
```

例如：

- 官方道路
- 生產腹地
- 危險邊界
- 本地捷徑
- 禁忌地
- 水路／渡口
- 荒地
- 下一個聚落方向

### 外部連接 External Connector

邊界格與外部節點之間的連線。

它決定：

- 玩家是否已感知這條路。
- NPC 是否能用它移動。
- 它是否算官方聯外道。
- 它是否有風險。
- 什麼事件可以從這裡進入已知區域。

## 連接類型

### `official`

官方聯外。

用途：

- 商旅
- 稅務
- 公文
- 治理
- 正規 NPC 往來
- 聚落等級門檻

第一個已知區域至少要有 1 條 `official`，否則它像孤島。

### `productive`

生產腹地。

用途：

- 農田
- 採集
- 牧場
- 水源
- 柴薪
- 礦點前置

這類連接讓區域能活，不只是住人。

### `social`

人流與消息路。

用途：

- 外來者
- 流言
- 客商
- 行腳者
- 求職者
- 離開與返鄉

這類連接是 NPC 對話、消息延遲、社會變化的入口。

### `risky`

能走，但風險明顯。

用途：

- 野獸
- 盜匪
- 迷路
- 天候
- 異常場
- 夜間危險

`risky` 可以給玩家探索壓力，但不該拿來算官方聯外。

### `hidden`

後台存在，但玩家一開始不知道。

用途：

- 捷徑
- 密道
- 禁忌地
- NPC 私用路
- 事件真相線

`hidden` 只能透過觀察、傳聞、NPC 帶路、物件線索或事件解鎖。

## 建議拓撲

第一個已知區域不要做棋盤，也不要做環形大路。用「核心 + 邊界器官」。

```text
                 [risky 外部節點]
                       │
      [productive] ─ 邊界格 ─ 生活內圈 ─ 邊界格 ─ [social]
                       │           │
                    公共核心 ─ 工作/民居
                       │
                    邊界格
                       │
                 [official 外部節點]
```

白話：

- 中央不是地圖中心，而是玩家最容易理解的生活核心。
- 邊界格不是路牌，是區域器官。
- 外部節點不是地圖格，是壓力、資源、人流、危險的來源。

## 第一版應該有哪些外部連接

不要先命名地點，先定功能。

| 連接 | 類型 | 作用 |
|---|---|---|
| 主聯外道 | `official` + `social` | 外人、商旅、消息、正式往來 |
| 生產腹地 | `productive` | 食物、材料、工作日程 |
| 危險邊界 | `risky` | 探索、戰鬥、自動遭遇、恐懼來源 |
| 本地捷徑 | `hidden` 或 `local` | NPC 私用、追蹤、事件反轉 |
| 禁忌方向 | `hidden` + `risky` | 傳聞、誤導、夜間事件 |

第一版不需要更多。

## 玩家感知規則

外部連接在玩家端不直接顯示成：

```text
official_road_node_01
productive_hinterland_02
risky_wildedge_03
```

而是變成感官線索：

```text
遠處有車轍。
有人從那條路帶來外地口音。
那邊風裡有草木腥氣。
本地人提到那條近路時會壓低聲音。
夜裡沒人願意往那邊走。
```

路口 UI 只承載「可往哪裡走」和「你目前如何理解那個方向」，不承載全世界地圖。

## 後台資料模型

```rust
struct KnownRegion {
    id: RegionId,
    cells: Vec<CellId>,
    core_cells: Vec<CellId>,
    boundary_cells: Vec<CellId>,
    connectors: Vec<ExternalConnectorId>,
}

struct ExternalConnector {
    id: ExternalConnectorId,
    from_cell: CellId,
    to_node: ExternalNodeId,
    classes: Vec<LinkClass>,
    player_reveal: RevealState,
    npc_access: AccessRule,
    travel_profile: TravelProfile,
    event_hooks: Vec<EventHook>,
}

struct ExternalNode {
    id: ExternalNodeId,
    role: ExternalNodeRole,
    display_hint: String,
    expansion_state: ExpansionState,
}

enum LinkClass {
    Official,
    Productive,
    Social,
    Risky,
    Hidden,
    Local,
}
```

白話：

- `KnownRegion` 是已知區域本體。
- `ExternalConnector` 是區域往外接的邊。
- `ExternalNode` 是外部世界的佔位契約。
- `player_reveal` 控制玩家知不知道。
- `npc_access` 控制 NPC 能不能走。
- `event_hooks` 控制事件能不能從這條路進來。

## 擴張規則

### 1. 先有壓力，再展開

外部節點不能因為「存在」就展開。必須有壓力：

- 玩家追蹤線索。
- NPC 日程需要。
- 商旅或難民進入。
- 危險逼近。
- 資源短缺。
- 傳聞累積到足以行動。

### 2. 每次只展一層

第一次展開外部節點時，只新增 1 到 3 格。

不要一次展開森林、整條官道或下一個聚落。

### 3. 新格必須有兩個以上用途

外部新格若只是路，就不要生成。

至少要命中兩項：

- 路徑決策
- 風險
- 資源
- NPC 日程
- 物件線索
- 傳聞
- 狀態變化
- 事件入口

### 4. 官方聯外與探索連通分開

`official` 只算正式聯外。

`hidden`、`risky`、`local` 可以讓世界更活，但不提升聚落等級。

這能避免一個區域因為祕密小路很多，就被錯算成高等聚落。

## 第一版不做

- 不做完整外部大地圖。
- 不做世界縮略圖。
- 不做所有外部節點坐標化。
- 不做玩家可見的全區連線圖。
- 不把已知區域一次全揭露。
- 不把所有邊界都變成可走遠路。
- 不預設任何特定村名或固定劇情。

## 第一版要做

1. 手工定一個已知區域的 L0 可玩內核。
2. 後台定 L1 全區域，但玩家逐步揭露。
3. 選 4 到 5 個邊界格。
4. 為每個邊界格指定外部連接類型。
5. 至少有一條 `official`，一條 `productive`，一條 `risky`，一條 `hidden/local`。
6. 外部節點先只作為事件、人流、資源、風險入口。
7. 等玩家行動或 NPC 日程需要時，再把某個外部節點展成 1 到 3 格。

## 結論

「已知區域」不是孤立場景，也不是大世界縮圖。

它應該是：

```text
內部足夠細
邊界有語意
外部先保留契約
玩家只透過線索理解外面
需要時再從邊界往外長
```

這樣可以先做出第一人稱可玩的區域，同時不把世界鎖死在小場景，也不讓上帝視角污染玩家體驗。
