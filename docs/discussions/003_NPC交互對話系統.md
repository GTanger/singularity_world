# 討論 003：NPC 交互對話系統

> **共識：NPC＝玩家 → 選 D（AI）**，已實作：同房兩 NPC 一來一往由 Ollama 生成，失敗 fallback 微互動。  
> **觸發選**：重＝閒置、中＝排班、輕＝隨機。**內容**：主題劇本 + AI。**記憶**：寫（長碰面的 NPC 不可能永遠重複對話）。  
> 對齊：[NPC 之間交互行為](../reference/NPC之間交互行為.md)、[NPC 活化系統](../NPC活化系統.md)、現有微互動（`db/npc_social.go`）、玩家↔NPC 對話（模板 + AI）。  
> **雙 LLM 調度** → [004 Web LLM 調度與複數玩家](004_Web_LLM_調度與複數玩家.md)。

## 一、現狀簡述

| 項目 | 現況 |
|------|------|
| **微互動** | 同房 ≥2 NPC 時，閒置 tick 15% 機率隨機兩人，產出一句**敘事**（如「【A】與【B】閒聊了幾句」），不帶具體台詞、不寫記憶。 |
| **玩家↔NPC 對話** | 玩家點 Talk → 可送 `player_input`；回覆來自 Ollama（背版+記憶）或模板（`PickFromDialogue` 的 talk/greet/idle）；會寫入該 NPC 的 archival + summary。 |
| **對話模板** | 依職業掛載，佔位符含 `{name}`（單一 NPC 名）、`{room}`、`{time}` 等；**沒有**「A 對 B 說」的雙人模板。 |

目標：在**不破壞現有體感**的前提下，討論「NPC 對 NPC 的對話」要做到什麼程度、怎麼觸發、內容從哪來。

## 二、範圍選項（要做多「重」）

### A. 只擴充微互動（輕）

- **行為**：維持「一句 ambient 敘事」，但把內容從**固定 8 句**擴成「可配置／可依職業抽」的**敘事 + 少量台詞**。
- **例**：「【經理】對【服務生】低聲道：「今日客人多，手腳利落點。」」
- **特點**：仍是「一句就結束」、不寫記憶、不跑 AI；只擴充 `microInteractions` 或改為從 JSON／模板抽一句。
- **實作量**：小（改 `npc_social.go` + 可選一份 npc_to_npc 敘事表）。

### B. 單輪「A 對 B 說一句」（中輕）

- **行為**：觸發時選定 A、B，A 說**一句**具體台詞（或敘事+台詞），B 可選「不回應」或「回一句」；玩家只看成一段 ambient。
- **例**：「【陳正明】對【林小雯】說：「櫃檯那邊你盯一下。」【林小雯】點了點頭。」  
- **內容**：可從**新模板槽**（如 `npc_to_npc`）抽，佔位符 `{speaker}`、`{listener}`、`{room}`、`{time}`；或沿用職業的 idle/greet 改為雙人版。
- **記憶**：可選不寫，或只寫「A 與 B 曾在某房有過簡短交談」到 A/B 的 archival（供日後玩家與 A/B 對話時提及）。

### C. 多輪 NPC 間對話（中重）

- **行為**：觸發後 A 說 → B 回 → 可再 1～2 輪，再結束；整段以 ambient 形式推給同房玩家。
- **例**：A：「聽說東街又出事了。」 B：「可不是，這兩天少往那兒跑。」 A：「嗯，謝了。」  
- **內容**：需**多句組合**（同一主題的 A 句、B 句、A 再回）；可劇本表（topic → 3～5 句輪替）或輕量腳本。
- **記憶**：若寫入 archival，需決定寫在 A、B 或兩者；以及是否影響該 NPC 對**玩家**的 summary（例如「剛和同事聊過東街」）。

### D. NPC 間對話接 AI（重）

- **行為**：A 對 B 的「第一句」或整段由 **Ollama** 生成，B 的回覆也由 AI 生成（context 帶 A/B 背版、所在房間、時段）。
- **特點**：彈性最大、最不重複，但延遲與成本高；且需定義「誰的背版／記憶」當輸入（A 的、B 的、還是兩人皆帶）。
- **記憶**：若寫入，需決定寫入誰的 archival、是否寫入「與另一 NPC 的對話摘要」。

## 三、觸發方式

| 方式 | 說明 | 優點 | 缺點 |
|------|------|------|------|
| **閒置 tick（現有）** | 與現有微互動同一計時；有玩家在的房、每輪一次、機率觸發。 | 與現有一致、不額外掃描。 | 僅「有玩家在」的房；頻率受 tick 上限。 |
| **擴充為「觀測圈」** | 有玩家的房 + 鄰房（與移動／腦驅動一致）都算；在這些房內觸發 NPC 對話。 | 玩家偶爾在鄰房也能「聽到」隔壁對話感。 | 需傳 roomIDs（已有 `buildActiveRoomIDs` 可沿用）。 |
| **排班／事件驅動** | 換班、交接、或特定事件時強制觸發一次 A–B 對話（如經理—服務生交班）。 | 情境明確、易做劇本。 | 需定義事件點、可能與「隨機」並存。 |
| **純隨機（無玩家條件）** | 每 tick 對全圖或活躍房隨機選一房、再選兩 NPC 觸發。 | 世界感更足。 | 無人觀測時也跑、耗資源；玩家可能從未看到。 |

**觸發選（分級共識）**：

| 權重 | 觸發方式 | 說明 |
|------|----------|------|
| **重** | **閒置** | 與現有微互動同一計時；有玩家在的房、閒置 tick 到期時機率觸發 NPC 間對話。主流量。 |
| **中** | **排班** | 換班、交接或排班事件時觸發一次 A–B 對話（如經理—服務生交班）；情境明確、可接主題劇本。 |
| **輕** | **隨機** | 無固定節奏，隨機時點／隨機房觸發，補足世界感；可與閒置、排班並存。 |

## 四、內容來源

| 來源 | 說明 | 適用範圍 |
|------|------|----------|
| **擴充微互動表** | 現有 8 句改為 JSON 或更多句，可帶簡單佔位符（A 名、B 名）。 | A（輕） |
| **新模板槽 `npc_to_npc`** | 在 `DialogueFile` 或獨立 JSON 新增槽位，如 `npc_to_npc: { lines: ["【{speaker}】對【{listener}】說：「…」"] }`；可依職業區分（經理對服務生、服務生對經理）。 | A、B |
| **主題劇本表** | 例如 `topic: "交班"` → 3～5 句依序或隨機輪替，組成一段 A–B 對話。 | B、C |
| **AI 生成** | 以 A/B 的背版、房間、時段為 context，讓 Ollama 產一句或一來一往。 | B、C、D |

**內容共識**：**主題劇本 + AI**。即：  
- 有**主題劇本**（topic → 多句輪替、情境如交班／閒聊／打聽）時，可依主題抽句或帶入劇本；  
- 同時可接 **AI**（Ollama）：以主題或劇本首句為 seed、背版＋房間＋時段為 context，生成一來一往或補足後續句。  
- 實作上可「主題劇本提供情境與候選句，AI 負責最終產出」或「劇本與 AI 二擇一／並存」依情境選。

## 五、記憶與背版

- **是否寫入 archival**  
  - **不寫**：實作最簡單，與現有微互動一致；但**長碰面的 NPC 會永遠重複同一套對話**，體感差。  
  - **寫**：**共識為寫**。可寫「A 與 B 在 X 房有過簡短交談」或一句摘要到 A、B 的 archival（或兩人皆寫）；或另存「A 與 B 的最近交談摘要」供下次觸發時帶入 context，讓再次對話可接續／不重複。  

- **summary**  
  - 目前 summary 是「該 NPC 與**玩家**的最近印象」。若 NPC 間對話寫 archival，可選擇**不**改動對玩家的 summary，或新增「最近與誰（NPC）說過話」供背版／檢索。

**共識**：**寫**。長碰面的 NPC 不可能永遠重複對話；需寫入記憶（archival 或專用 NPC–NPC 摘要），供下次觸發時檢索、帶入 AI context，避免重複或讓玩家問 A「剛才你和 B 聊什麼」時能答得上。

## 六、與現有系統的邊界

- **微互動**：若做 A 或 B，可**取代**現有 8 句微互動，或與其**並存**（例如 50% 舊句、50% 新「帶台詞」句）；需避免同一 tick 同房又微互動又 NPC 對話，可合併為「同房兩 NPC 一次只出一種」。
- **玩家↔NPC Talk**：不變；仍由玩家點擊、`player_input`、Ollama/模板、FlushConversationAndAppend 寫入該 NPC 的 archival/summary。
- **觸發頻率**：若 NPC 對話與微互動共用同一閒置 tick，建議**二擇一**：該房這輪要麼出一句微互動、要麼出一段 NPC 對話，避免刷頻。

### 6.1 若 NPC 對話中，玩家也想對話怎麼處理？

- **行為**：玩家**照常可對話**。Talk 由 WebSocket handler 處理，與閒置 tick 不同 goroutine，不會被 NPC-NPC 的 Ollama 卡住。
- **結果**：NPC-NPC 的 Ollama 回傳後，在**送出 narrate 前**再檢查：該房是否有玩家在**過去 15 秒內**做過 Talk。若有 → **不播**該段 NPC 間對話（丟棄），以玩家對話為準；若無 → 照常播送。
- **體感**：玩家在 NPC 間對話「生成中」時點對話，會立刻得到回覆，且不會再被一段遲到的 NPC 間對話洗掉。

## 八、實作位置（已全數上線）

- **AI 一來一往**：`ai/talk.go` — `CallAITalkNPCToNPC(..., roomName, timeLabel, npcNpcMemory, topicHint)`，回傳 lineA、lineB；npcNpcMemory 為兩人過往交談摘要，topicHint 為主題劇本 hint。
- **觸發－重（閒置）**：`main.go` 閒置 tick 內，遍歷有玩家的房，呼叫 `tryTriggerNpcNpcInRoom(roomID, topicHint)`，topicHint 由 `PickRandomNpcNpcTopic()` 抽；成功則寫記憶、廣播，失敗則 fallback `PickMicroInteraction`。
- **觸發－中（排班）**：`main.go` 每遊戲小時 `ApplySchedules` 後，對有排班動靜的房（OldRoom/NewRoom）試觸發一次，topicHint＝`GetNpcNpcTopicByID("交班")`。
- **觸發－輕（隨機）**：`main.go` 每 tick 遞減計數器，每 80～120 tick 在隨機一房呼叫 `tryTriggerNpcNpcInRoom`，topicHint 隨機。
- **主題劇本**：`data/npc_to_npc_topics.json`、`db/npc_topics.go`（LoadNpcNpcTopics、GetNpcNpcTopicByID、PickRandomNpcNpcTopic）；hint 帶入 AI system prompt。
- **記憶**：`store.NpcNpcSummaries`（key＝canonical idA|idB）、`data/runtime/npc_npc_summaries.json`；`db.GetNpcNpcConversationSummary` / `SetNpcNpcConversationSummary`；`tryTriggerNpcNpcInRoom` 觸發前讀、成功後寫一句摘要。
- **玩家優先**：`server/session.go` — `Session.LastTalkAt`、`UpdateLastTalkAt(playerID)`（handler 在 Talk 後呼叫）、`RoomHasPlayerWithRecentTalk(database, roomID, within)`；60 秒內有 Talk 的房不觸發 NPC 間 AI。
- **NPC 對話中、玩家也想對話**：觸發 NPC 間對話後會呼叫 Ollama（可能數秒～十幾秒）。若這段時間內同房玩家發起 Talk，handler 照常處理、玩家會立即得到回覆。NPC-NPC 的 Ollama 回傳後，**送出 narrate 前**再檢查一次：該房是否有玩家在**過去 15 秒內**做過 Talk；若有則**不播**該段 NPC 間對話（丟棄結果），以玩家對話為準。若無則照常播送。因此「NPC 對話中玩家也想對話」→ 玩家照常可對話，且不會再被一段「遲到的」NPC 間對話洗掉。
