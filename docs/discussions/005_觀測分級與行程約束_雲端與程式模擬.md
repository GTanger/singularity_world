# 討論 005：觀測分級、雲端對話與非玩家格程式模擬—行程約束

> **狀態**：**核心共識已升格為 ADR** → [**決策 009：觀測分級與行程約束**](../decisions/009_觀測分級與行程約束.md)（**以 009 為準**）。本文 §一至 §六保留推導與筆記；§五為實作待補。  
> 相關：[004 Web LLM 調度與複數玩家](004_Web_LLM_調度與複數玩家.md)（佇列與資源策略，與 009 並行）。

---

## 一、曾出現的方案直覺

- **玩家所在格（房）**：對話等互動使用**雲端 API**（高成本、高表現力）。  
- **非玩家所在格**：以**程式／規則**模擬變化（低成本），不為每一句對白呼叫 LLM。

---

## 二、「時間不可能靜止論」— 釐清對象

主管曾以此反駁的**不是**「遠處不能用程式算」，而是避免這種**錯誤理解**：

- 若解讀成「只有玩家那一格時間在走、其餘世界凍結」→ **不合理**；與**單一世界時鐘**牴觸。

**較合理的並存方式**：

- **全域時間同一條軸**，各處都在 tick。  
- 差異在**敘事／推理成本**：高顯著度（例如玩家當面）可用雲端 API 產出語言；其餘用**規則化、摘要化、機率化**推狀態，**不必**逐句 LLM。  
- 與專案既有方向同族：觀測圈內較細、無人觀測時仍有 `RunUnobservedWorldTick` 等—**時間仍推進**，只是**模擬粒度**不同。

---

## 三、主管補充反駁的核心—「上班與睡覺」

後續補充說明：當初要掐死的，更是**狀態與行程的真實性**，例如：

1. **NPC 要上班**  
   職場／排班／在崗是已成立的事實；後台不能讓「該在班上的人」因無人看就永遠卡在家，或在錯的時空亂跑。

2. **NPC 在睡覺**  
   休息／在家／不可當成外出閒晃；後台**不應**用便宜模擬去算出「半夜還在街上看起來很閒」—與**玩家若觀測時應看到的因果**矛盾，也破壞擬真。

**收斂成一句**：  
**觀測分級只影響「敘事／LLM 成本」，不豁免「排班、作息、職場」等行程與狀態約束。**  
非玩家格的程式模擬必須是**約束內**的狀態推進，不是無視班表與睡眠的亂數劇場。

---

## 四、後台擲骰 vs 玩家進「蕗易沙」：店員如何**必定**在場？

**問題**：若非玩家格大量依**擲骰／機率**推進，玩家走進蕗易沙（`life_cofe_1` 等店面房）時，怎麼保證**該顧櫃的店員**會出現在這裡，而不是骰到「今天剛好沒人」？

**原則：擲骰只決定「約束已滿足之後的枝節」，不決定「該不該在崗」。**

1. **權威來源：職場綁定與排班（硬約束）**  
   - 店員與「蕗易沙」所屬 **venue／店面** 的 **assignment**（或等價資料）決定：**在班時段內，其合法位置必須包含店面（或後場與店面連通規則內）**。  
   - 這一段是**規則解**，不是骰子。無人觀測時 tick 也應先把「該在班上的人」**推進到職場房間**（或維持在崗），與 §三「要上班」一致。

2. **擲骰用在哪裡**  
   - **在已滿足「人在店內、在班」之後**，才骰：微動作、閒置 emote、是否多一句模板對白、與同事的**摘要級**互動 log 等。  
   - **不可**用骰子決定「店裡有沒有店員」—除非世界設定上本來就允許**閉店／請假**等**明確狀態**，且該狀態也寫入權威資料（例如 `closed`、`on_leave`），讓玩家進房時敘事一致（「拉下鐵門」），而不是隨機空城。

3. **玩家進房＝觀測坍縮（呈現層）**  
   - **進房當下**的 `entity_room`（或等價）以**當前遊戲時間 + 排班 + 圖上合法位置**做一次**決定性解析**：  
     - 在班且指派為蕗易沙店員 → **必在**（除非資料明確標記不在崗）。  
   - 前端／敘事只**顯示**解析結果；若與 log 曾寫下的摘要衝突，以**權威狀態**為準並可選擇性修正 log（或接受「摘要為印象、實況以進房為準」的規則，但需事先約定）。

4. **與「全非玩家格雲端」的關係**  
   - 店員在不在：**後台規則**。  
   - 店員講話細不細：玩家對話可雲端；非玩家格只用模板／骰子決定**是否寫一條短 log**，不影響**在崗與否**。

**一句話**：蕗易沙有沒有人顧櫃，由 **assignment／排班／店舖狀態** 決定；骰子只動**氣氛與次要事件**，不動**該不該出現**。

## 六、認知收斂—視線外的人與「機器人」類比（主管筆記）

> 獨思易鑽牛角尖；與人對照後，有時會發現問題本來就不必那麼重。

**收斂**（主管自述，大意）：

- 現實裡的人也是依**固定節律**在生活（班表、作息、路徑）；自己**看不到**的時候，並沒有在腦裡為他們逐句生成對白與內心戲。  
- 換句話說：**視線外**的他人，對「我」而言，與依規則運轉的**機器人／黑箱**並無二致—直到再次進入觀測為止。  
- 據此，遊戲裡「**玩家格細膩、非玩家格規則模擬**」不再心裡過不去：**遠處本就不必是人類級內心戲**；進觀測後再把表現拉滿（雲端或精緻 prompt）即可。

**補記**（觸發於 §四「排班／職場優先於擲骰」的對談）：

- 人遠在其他城市時，浮生城裡蕗易沙的店員在設定上仍**日復一日**依班表上下班—像**機械式卻真實**的節律。  
- 對照自身：**公司—家**兩點一線，在**未曾觀測自己的人**眼裡，自己同樣是依規律移動的「**機器人**」—並非貶義，而是指**外在可預測、內在不可見**。  
- 由此帶出一點**《楚門的世界》式既視感**：鏡頭內外、被看與不被看之間，**誰在演、誰在黑箱裡過真實生活**，界線可玩味；與本作「觀測／坍縮」母題可並讀（敘事層，非劇透設定）。

此段**不取代**技術規格，僅標註**設計心理與世界觀敘事**為何能與工程方案同向；實作仍須滿足 §三、§四 的行程與在崗約束。

## 七、共識結語

以下為本討論串之**定調**，供後續規格與實作對齊；**不**取代 `004` 既有技術決策，與之並行時以「本節為世界觀／取捨原則、`004` 為佇列與資源策略」分工理解。

1. **單一世界時鐘**  
   時間全域推進；觀測分級改變的是**敘事與推理成本**，不是「遠處時間停住」。

2. **行程與狀態優先於擲骰**  
   上班、在崗、睡眠、職場綁定等為**硬約束**；後台模擬不可為了「便宜」而與班表／作息矛盾。擲骰僅用於約束已滿足後的**枝節與氣氛**。

3. **在崗與在場由權威資料決定**  
   例：蕗易沙店員是否出現在店內，由 **assignment／排班／店舖狀態** 等**決定性規則**解析，**不**由隨機決定「店裡有沒有人」；閉店、請假等須為**明示狀態**。

4. **雲端／LLM 的定位**  
   優先用於**玩家高顯著度互動**（如當面對話的語言表現）；**非玩家格**以規則、模板、摘要 log 為主，不必逐句雲端。權威狀態始終在後端，API 只產出**可被校驗的文字**。

5. **認知與敘事對齊（可選讀 §六）**  
   視線外的人事物，在現實與在遊戲中皆可合理視為**節律可見、內心不可見**；「非玩家格像機器人」與「進觀測後才拉滿擬人」並不違和，且與本作觀測／坍縮母題同向。

**一句收束**：**世界在暗處仍依規律活著；鏡頭照到時，才把話說得像人。**
